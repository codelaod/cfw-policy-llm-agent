## 3. 推荐的整体系统图

```text
浏览器（五个轻量视图）
  ├─ 普通 JSON API
  └─ fetch SSE（失败后 JSON 轮询补发）
          │ 同源、本地应用访问头、范围检查
          ▼
Go 单进程服务（Gin 只负责 HTTP 边界）
  ├─ 会话／消息／确认／审阅／报告应用服务
  ├─ ExecutionAdmission：范围、权限、预算、幂等、效果上限
  ├─ 持久任务队列＋单工作器＋阶段事件投影
  ├─ 审计服务
  │    ├─ 归一化与三值规则内核
  │    ├─ 受限单 Agent（Eino；只读本地工具）
  │    └─ 建议校验、证据与报告
  └─ Connector
       ├─ 离线快照
       ├─ 阿里云只读 CFW／ECS／安全组／必要网卡
       └─ 非流式 OpenAI 兼容模型适配器
          │
          ▼
纯 Go SQLite：业务历史、不可变输入、任务、事件、尝试账本、审阅、报告
```

前后端在代码和职责上分离；首版部署建议同源单机，由 Go 服务提供 API 并承载正式前端构建产物。这不等于把 Vue 写进 Go，也不引入 Nuxt 服务端或微服务。真实云和模型连接器只能由统一准入后显式执行，浏览器、模型和普通 Handler 都不能直接取得云写权限。

## 5. 真正阻塞 G2 的未决问题

以下问题需要用户给出“同意／修改／暂不通过”，否则不能把整体设计标记为 G2 通过：

1. **正式总体路线**：是否接受 Go／Gin／Eino、逻辑前后端分离但首版同源单进程、单工作器，而不是微服务或多 Agent。
2. **持久化与恢复路线**：是否接受纯 Go SQLite、业务 Store 与 Eino Checkpoint 分离、全部用户可见历史和执行证据持久化，以及 GORM 不合格即回退 direct modernc。
3. **计算与模型边界**：是否接受确定性规则为事实底座、受限单 Agent 为补查／解释层、非流式 Chat Completions 为首个候选适配器、失败保持 rules-only。
4. **云接入与授权边界**：是否接受当前最小只读采集、显式范围和 CredentialProvider，不允许机器 profile 回退、Agent 扩权或云写。
5. **执行、费用与事件恢复语义**：是否接受统一准入、逐物理尝试计数、显式刷新／取消、SSE 只恢复观察而不重放任务，以及文档中的首版默认预算。
6. **可测性能目标**：是否接受 03 §10.2 的本地环境、负载和阈值作为首版 NFR-06 验收档位。
7. **评价与研发门槛**：是否接受三组对照、全部运行分母、单资源串行真实复审和 E0→E5 分期，不以局部功能或离线结果越级宣布完成。

当前复核没有发现需要修改 B2 才能解决的架构矛盾。需要特别防止两种误读：

- “前后端分离”是代码／职责分离，和首版生产同源单进程部署不冲突。
- “20～30 个独立案例”是评价样本要求，不是创建 20～30 台 ECS；真实环境优先串行复用，但仍不能省略 NAT 边界和至少一次真实整改复审。

## 6. 不阻塞 G2、但 G2 后必须实测的事项

这些事项可以在设计上先规定“验证门槛＋失败回退”，不需要在 G2 前伪造实现证据；未通过对应门槛时，相关能力仍为未验收。

| 实测项 | 为什么不能现在写成通过 | 计划门槛／失败处理 |
| --- | --- | --- |
| 固定依赖与正式构建 | 尚无正式 Go／Vue 工程和锁文件 | E0 固定版本并离线复现构建；失败时调整适配，不进入 E1／E2 |
| GORM＋纯 Go SQLite | 未安装驱动，零值、外键、条件更新、回滚和重启未测 | `CGO_ENABLED=0` 构建与事务矩阵通过；否则退 direct modernc，不退回 CGO |
| SQLite 并发与恢复 | 目前只有事务／单工作器设计 | 验证短事务、独占启动锁、取消竞争、事件连续性和第二进程拒绝 |
| Nuxt UI v4／Tailwind 的 Vite 集成 | 原型是原生 HTML／CSS／JS，不是正式组件库 | 正式五路由构建、本地图标／字体、键盘／小屏／错误态通过；不引入 Nuxt 服务端 |
| 真实 SSE／轮询 | 当前只有人工契约和内存模拟 | 验 UTF-8 拆帧、重复／缺号、鉴权、401／403／404、代理缓冲、慢客户端、终态补发和重启 |
| CFW／ECS SDK transport | 公开源码有 WithContext 不等于实际请求可控 | 模拟 HTTP 证明取消、重试、凭据交换、响应上限和 attempt ledger；不合格返回设计调整 |
| 阿里云账号能力与字段 | 尚未调用目标账号，也未核对控制台 | E4 在明确账号／地域／资源／RAM／预算授权下逐接口验证；缺能力标未验收，不用离线替代 |
| 当前模型多轮能力 | 旧 MiniMax 小样例不含完整依赖式多轮证据 | 至少两种真实工具路径，其中一种依赖前次结果；结构、失败和用量分开取证；不合格保留 rules-only |
| 本地性能目标 | 当前没有正式服务或基准 | 按 G2-10 的固定环境和数据运行；不完整／截断不算性能通过 |
| 20～30 案例与正式评价 | 静态示例、文档负例和原型回归不是正式评价集 | 冻结案例、标签、协议后运行三组；全部终态数量可对账，失败不从分母删除 |
| 真实整改→重采集→复审 | 当前没有真实云闭环证据 | 至少一次有前后快照、人工修改说明、强制刷新、比较证据和还原／清理记录 |

如果上述某项失败，只能按表中回退、标记未验收或回到用户重新决策；不能静默换技术、放宽阈值或把模拟结果升级为真实结果。

## 7. G2 通过后的分阶段研发建议

**重要**：G2 通过只表示设计基线通过。鉴于当前请求是“审核通过后再决定下一步”，实际启动任何阶段仍需用户另行明确；真实模型、云接口、资源开通／采购、人工云修改、提交和推送还各自受已有授权边界约束。

| 阶段 | 入口条件 | 主要工作与交付物 | 退出条件 |
| --- | --- | --- | --- |
| E0 依赖与契约门槛 | G2 明确通过；用户另行授权开始研发；不需要云／模型外呼 | 固定 Go／Gin／Eino／SQLite 和前端版本；最小构建；存储事务矩阵；模拟 HTTP 的取消／重试／限额／请求账本；SSE 编解码与鉴权契约；形成 ADR／锁文件／门槛报告 | 无 CGO 构建、数据库关键语义、正式前端构建、模拟 transport 和协议负例通过；任何关键门槛失败先修订设计，不启动业务扩展 |
| E1 离线核心闭环 | E0 通过 | 归一化输入、分区身份、证据、三值首匹配／区间内核、规则目录、固定人工样例、不可变报告数据；先完成“输入→规则→保存→审阅→导出” | 离线固定案例、边界／未知／缺失／超限、参考穷举和版本追溯通过；无模型／无云仍可完整使用 |
| E2 持久服务与基础 Web | E1 通过 | 会话／消息／确认／审阅／任务／事件／报告仓储；Gin API；五路由基础界面；SSE＋轮询恢复；刷新／重启／取消／保存失败状态 | 连续会话、幂等、重启中断、事件补发、范围隔离、错误与空态、报告固定版本通过；不是只有聊天页 |
| E3 受限 Agent 与前端完善 | E2 通过 | Eino 当前轮循环、只读本地工具、依赖补查、结构化分类型建议、规则保留、字段投影、预算／失败；完善审计／证据／确认／报告交互 | 先用模拟模型端点覆盖调用 ID、依赖路径、未知工具、无效结构、取消和越界；正式模型能力仍保持未验收，UI 能清楚区分事实／推导／待确认／信息不足 |
| E4 受控真实接入 | E3 的本地契约通过；用户另行明确数据、账号、地域／资产、RAM、模型、请求数／费用和时段 | 逐项验证模型、CFW、ECS、安全组、NAT ACL；控制台对照；同一资源串行情境；至少一次人工云端整改、强制重采集和复审 | 每个接口／字段／权限／分页／模式有证据；模型依赖式多轮有证据；真实复审闭环完成。缺能力项明确未验收，不自动扩 API、权限或预算 |
| E5 正式评价与论文材料 | E1～E4 中对应能力稳定；案例、标签、模型条件和预算另行冻结 | 20～30 独立人工案例；三组运行；全部终态、误报漏报、建议评分、工具路径、耗时／用量／费用与局限；可复现实验材料 | 运行总数与终态可对账；比较条件公平；真实与人工数据来源清楚；论文只陈述实际证据，不预设 Agent 一定提升 |

可以在 E0／E1 先验证高风险契约并尽快形成离线闭环；不建议一开始同时接真实云、真实模型和完整 UI，因为失败时无法定位是规则、协议、权限还是界面问题。

## 8. 用户可直接回复的 G2 审核清单
