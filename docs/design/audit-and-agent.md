# 规则与受限Agent设计

基线：需求v0.6／B2、设计v0.6，G1／G2已通过。本文为该领域的现行详细设计；实际运行验收另行取证。

## 1. 三类输出分工

1. **输入事实**：配置、标签、关联、保护状态、已确认业务要求及其来源／时点。安全组只是画像线索，不等于发现监听服务。
2. **规则结果**：在明确支持子域内计算配置语义、范围差异和覆盖缺口；保留原始发现、证据与未检查范围。
3. **模型内容**：角色候选、补查选择、条件解释和推荐；无依据时待确认。模型疑点不写成规则事实，也不能删除或修改原始规则输出。

只读 SDK 适配、纯规则内核与 Eino 编排分离；规则单测不需要云账号或模型。真实云采集由受控任务先建立快照，Agent 默认只读快照和固定业务版本。

## 2. 归一化与可支持子域

规范化策略至少保留边界／方向、身份、来源／目标类型与集合、协议、端口、动作、顺序、启用、时间及应用／域名等条件、引用与原始位置。

B2 的精确计算涉及 internet/in、internet/out、nat/out 内明确的所审端点／查询，限 IPv4、TCP／UDP、字面 IP／CIDR 和完整展开的静态 IP／端口引用。网关策略集模式不建立全网络源×目标矩阵。作用于本查询的应用／域名、动态引用、复杂时间或未知生效条件均不能丢掉后当作普通策略。

- IPv4 与 CIDR 转为有界区间并合并，端口转有效闭区间；厂商 ANY／空值哨兵按已核实字段映射，不猜测请求与响应同名字段的含义。
- 协议 ANY 在 TCP／UDP 查询中可以匹配，但原策略其他协议含义不能被缩成 TCP；结论始终说明只覆盖所选子域。
- 明确关闭的条目不作为生效匹配；启用未知、重复／缺失顺序或相关高级条件无法判断时保留不确定性。稳定 ID 排序不能用来编造同优先级的实际顺序。
- 观察 log 动作不等于 drop；本设计不对相关观察／高级条件给出完整有效路径推导，只标该查询超出支持。其他明确不相关规则不必拖累全部检查。
- 默认行为绑定 provider-semantics 版本、资料依据与分区适用性；CFW 的未命中允许不能套成安全组默认拒绝，NAT StrictMode 也不能直接转为默认 drop。导入声称与该 profile 矛盾的默认值时报告语义冲突，不静默改写。
- 原文和未支持字段保留在私有数据；只有已知与匹配无关的描述性字段可以不参与计算。

请求先固定范围、资料基版和数据策略；准备完成后，规则输入只封存一次 `policy_scope / snapshot_sections / profile / intent / baseline / normalizer / kernel / provider_semantics` 版本及 `evaluation_at` 清单。例外按固定评估时点判定有效期；时点变化是新输入，不以未记录的当前时间产生不可复验结果。

## 3. 端点与三值首匹配

### 3.1 先确定比较对象

按账号／地域／资源身份和已知地址映射建立所审端点；同机多个地址／服务分开查询。未知代理／NAT 观察位置、无法归属的安全组或端点不能直接证明某项访问路径。

CFW 配置逻辑分析需要该对象的适用范围、保护状态及相关策略分区足够明确。关闭／切换／未知保护状态不能凭一份 ACL 列表说实际受保护；可保留静态配置观察与 CHK-05 的当前覆盖事实。

**配置逻辑允许／拒绝不是数据面实测**：API 中看到配置、开关开启或人工修改后重新采集，都不证明策略已下发、链路可达或业务恢复。结果使用快照时点和限制措辞，不将传播延迟当成自动修复成功。

### 3.2 三种边界的比较轴

| 查询 | 固定项 | 变化／比较维度 | 前置证据 |
| --- | --- | --- | --- |
| 互联网入向 | 所审目标地址／服务、分区、协议 | 来源 IPv4 范围与目标服务端口 | 目标归属、适用保护、完整规则／引用、业务允许来源（如该检查需要） |
| 互联网出向 | 发起资产在该边界的有证据地址、分区、协议 | 外部目标 IPv4 范围与目标端口 | 地址观察点／归属、外部依赖及完整性，不能直接沿用入向白名单 |
| NAT 资产级出向 | 所选网关分区、发起地址／观察点、协议 | 外部目标范围与目标端口 | 资产到网关的配置关联、观察位置和 scope-bound 业务要求；不推定转换关系 |
| NAT 网关策略集 | 一个明确网关及其配置版本 | 条件合法性、精确重复候选、当前层状态 | 不自动展开为网关背后的全部资产或全源×目标可达性 |

`required_access` 明确不属于所审互联网／NAT 出网边界的私网／VPC 访问应标不适用；归属不明时标信息不足，不凭一个 CIDR 证明实际路径。返回流量不作为另一条新发起连接倒置检查，不因反向没有 ACL 就宣称断连。

用 `Q` 表示当前明确查询的配置地址／端口子域，`A`、`D`、`U` 分别是计算所得允许、拒绝和未知部分。只在 Q 中输出事实；不把其范围之外的地址、协议或路径算作已覆盖。

### 3.3 匹配结果是 yes／no／unknown

对一个地址／端口单元，按已知策略顺序：

```text
若分区／端点归属不成立: 返回 unknown 与原因
若路径所需枚举不完整，或实时配置已观察到变化: 返回 unknown 与原因
for rule in 当前分区已知的相关顺序:
    若明确禁用: 跳过
    match = 比较所有已知匹配维度及可支持条件
    若可证明不匹配: 继续
    若可能匹配但条件／状态／顺序不明: 返回 unknown 与原因
    若可证明匹配且动作支持: 返回 accept 或 drop 与路径证据
若没有匹配: 返回已核实的默认行为；未知则 unknown
```

如果策略分区漏页或已观察到配置族变化，未知规则可能更早匹配，不能仅因为已读到一条 accept 就给确定允许。若未知高级条件只存在于可证明不相关的规则，可跳过那条，而不必一概放弃全部事实检查。

### 3.4 区间划分，而不是随机探测

对于每个固定端点／协议查询，按入向来源或出向目标这一明确的变化轴，收集相关策略、业务集合与查询子域的地址／端口边界，划分为匹配结论一致的单元，逐单元首匹配并合并相邻同类结果。跨端点逐一处理，避免构造全网络拓扑。

这是支持子域内的集合运算，不是向主机发连接，也不通过几个样本地址声称穷尽全部空间。单查询单元上限暂定 50,000 作为设计防护；先以溢出安全的整数运算预估边界积，再逐段／流式生成，不能先分配整个笛卡尔积后才检查上限：达到上限／超时则返回未穷尽范围与原因；没有发现不能算通过。已证明的一处违例可以保留，但必须注明未发现全部问题。

全任务规则阶段继续受 20 秒上限约束；每个有界批次及可能的大循环检查 context，保留已完成子域。内核不得因单查询未超过 50,000 就假定 50 个资产的总工作量必可完成。

复杂度取决于端点、策略及边界数；不承诺在任意输入下都完整计算。实现时应先过滤明确不相交规则并复用解析结果；不得为了通过性能指标在未知处直接假定允许／拒绝。

## 4. M0 检查器如何使用内核

| 检查 | 计算／证据 | 降级或特别约束 |
| --- | --- | --- |
| CHK-01 管理来源 | 对明确管理服务计算配置允许来源与已确认允许集合之差 | 白名单未知只给业务待确认，CHK-07 可独立运行 |
| CHK-02 协议／端口 | 配置允许集合减去完整的业务允许上界 | 不完整列表不能把其余全判违规；TCP／UDP 外不作整体通过 |
| CHK-03 服务来源 | 按服务比较来源差异，保留相关引用 | 不把未知引用当空集合；与同问题的其他检查关联 |
| CHK-04 重复候选 | 完整匹配／生效／动作条件的规范化比较 | 身份、描述、位置单列为上下文；未知语义不宣称完全等价，不自动删除 |
| CHK-05 覆盖 | 保护适用范围／已采用要求与可信当前状态比较 | 不知道不等于未保护；该层关闭不等于所有防护缺失 |
| CHK-06 必要访问 | 支持范围内的必要访问与配置拒绝集合求交 | 私有／VPC 等超出所审边界的访问标不适用，不能证明实际故障 |
| CHK-07 宽泛来源 | 高风险端口上，由全地址条目或默认允许形成的未被完全覆盖的配置允许范围 | 只报明确剩余范围，不要求证明全部 IPv4 可达；没有 wildcard 路径不代表任意 CIDR 都合理 |
| CHK-08 角色差异 | 已确认数据库服务＋明确不需公网／限定访问的声明，再比较对应配置 | 角色本身不推导私网要求；同机 Web／其他服务独立，不误封必要访问 |

CHK-07 的证明示例：全地址 accept 被更高优先级全地址 drop 完全遮蔽则不成立；只有部分来源被 drop 时，报告剩余配置允许区间；没有显式 accept 也可能由未命中默认允许形成该路径。全地址来源可以由完整 IP 引用等价表达；未知引用不强行认定。

每项分别输出适用范围、`pass / fail / needs_confirmation / insufficient_data / unsupported / not_applicable`、覆盖／限额与证据。多个检查可以指向一个业务问题族，原始记录全部保留，主实验指标不重复计分。

### 4.1 B2 的出向／NAT 检查映射

| 检查目标 | 核心计算／前提 | 不得推导 |
| --- | --- | --- |
| OUT-01 出向允许上界 | 当经确认的允许集合 W 完整且适用当前 scope，计算 `A ∖ W`；非空已证明部分可报 fail，未知 U 不能补成允许或拒绝 | W 未完整时是待确认，不把未填写当 deny_all，不编造依赖 IP／域名 |
| OUT-02 必要外联 | 对已确认必要集合 R，计算 `R ∩ D`；非空则报告本层拒绝；`R ∩ U` 不可判通过 | 只证明所审层的配置差异，不证明实际连接失败；已声明项通过不代表全部业务依赖齐全 |
| NAT-01 关联与证据 | 核对网关／防火墙／资产地址／观察位置／时间和 scope；不足时 insufficient_data，冲突保留来源 | 同 VPC、选择了网关、出现公网地址都不是路径证明；未采集不等于没有转换 |
| NAT-02 网关层检查编排 | 在 NAT 语义 profile 和前置证据合格后，复用 OUT-01／02、精确重复和当前层状态的受支持内核 | 不另造一份反向入向规则；不把包装层与被复用检查重复计为两个问题 |

NAT-02 的结果保留 `rule_id / subcheck / policy_scope_ref / subject_ref / query_scope`，同一业务问题族去重但不删原始结果。gateway_policy 模式可做精确重复／状态观察；没有资产关联时，资产级 OUT-01／02 标不适用或信息不足，而不是替用户把整个网关网段当已确认资产。

CHK-01／03／07／08 的入向业务来源／角色基线不自动应用到出向目标；比如“出向目标端口 22”不等于“本机管理端口暴露”。CHK-04／05 的可复用部分仍必须有本边界身份与状态依据。

输出判定分开：数据缺口为 insufficient_data；相关未知语义为 unsupported；缺业务授权为 needs_confirmation；明确不适用为 not_applicable。流程 completed 不代表所有项 pass。任何 pass 必须限定已完整且受支持的查询子域；没有找到问题但截断／超时不得当 pass。

### 4.2 手算示例（人工设定，不是运行结果）

- OUT-01：固定源 `192.0.2.10`、TCP 443，允许上界仅 `198.51.100.0/25` 且用户声明完整；策略在完整已知语义下允许 `198.51.100.0/24`。应报告剩余 `/25` 的配置差异；若上界未声明完整，则改为待确认。
- OUT-02：用户明确需要访问某个外部目标 TCP 443；完整本层规则先拒绝该查询，则报配置差异。若前面存在可能匹配但无法解释的应用条件，不能跳过它后给确定性拒绝／允许。
- NAT：只知道 asset 与 gateway 的 VPC ID 相同，而观察位置未知。可以陈述网关的 ACL 条目，不能宣称该资产已受该 NAT 层保护或建议基于猜测的转换地址。

这些文字是 G2 后预标注案例的设计依据；本方案没有执行区间算法或形成审计效果数据。

## 5. 画像引导与审计 Agent

### 5.1 两种任务，共用能力而非多 Agent 平台

- `assistant_turn` 的画像引导场景从固定实例上下文、会话历史与已确认基版本开始，必要时查询关联组／引用；产生候选与缺项问题。用户回答继续同一业务会话，已确认事实和公共历史由应用持久化；若需模型整理，创建关联本方案的有界执行，不从零拼一次性问题，也不无限维持旧执行。
- `audit` 在已保存规则结果之上补查业务要求、策略／引用证据和判据，形成条件解释。细节不足时提出待确认，不强制凑出具体变更。

业务会话、可见消息、公开摘要、确认与任务／报告关系必须持久；ContextBuilder 按当前分区／投影组装获准历史，不能只发最后一句。完整 wire assistant／reasoning 仅在当前执行内保留，不把裁剪后孤立旧 tool 消息当合法历史回放。Eino Session Store 由业务实现，Checkpoint 与产品历史分开，详见[会话与执行](session-and-execution.md)。一次确认需服务端预览与基版本条件；模型没有确认工具。

### 5.2 B2 受控工具目录

| 工具 | 输入及返回 | 权限／边界 |
| --- | --- | --- |
| `get_partition_context` | 当前 scope 引用 → 边界／方向／owner 别名、模式／默认依据、窗口与覆盖 | 只读已封存当前分区，不列举其他账号／网关的全量策略 |
| `get_nat_association` | 已返回的关联引用 → 资产／网关／观察点及证据／缺口 | 仅当前 NAT 分区；缺证据返回 unknown，不补调云或推演 SNAT／DNAT |
| `get_asset_context` | 任务内资产别名 → 元数据、关联引用和证据／完整性 | 只读所选快照及获准字段，不暴露所有账号资产 |
| `get_security_group_rules` | 已关联组引用 → 方向／协议／端口／动作／来源及歧义 | 关联验证；共享组不是主机实际服务，不调用实时云 API |
| `get_business_intent` | 任务内业务引用／服务／scope → 已固定的入向授权或出向依赖／未声明状态 | 不取“最新”偷偷改变输入，也不生成白名单 |
| `get_policy` | 策略引用 → 规范化条件／原始证据位置 | 同快照、同规范分区且关联所审端点／发现的范围；快照中无关对象不自动获准，未知条件不得隐藏 |
| `resolve_reference` | 任务中返回的引用标识 → 同分区已采集成员／完整性 | 不因模型请求扩大采集；不可展开时明确 unknown |
| `get_finding_evidence` | 原始发现编号 → 证据、相关策略／业务引用 | 不能覆盖发现或伪造新证据 |
| `get_rule_definition` | 已启用检查编号 → 当前基线版本的适用条件与禁止推断 | 只读，不能由模型修改判据或阈值 |

没有通用 shell、SQL、文件读取、任意 HTTP、云 RPC、写策略／标签／例外或确认授权工具。工具参数、对象存在性、归属关系和任务授权均由后端校验，不依赖提示词说“只能只读”。

### 5.3 真正的依赖补查案例

初始只给任务目标、有限资产／发现概况及资料是否可查，不一次性提供全部细节。代表案例让 `get_asset_context` 返回此前未知的关联组引用，再据该引用决定是否查规则；另一个案例因业务资料不存在停止具体建议。B2 的 NAT 案例可由 get_asset_context 返回关联引用，再决定调用 get_nat_association；若返回缺口，就停止资产级确定性建议。出向案例按 get_business_intent 的完整性决定是否继续查询策略，而不是固定凑齐工具次数。工具执行和结果回传必须记录真实 call ID，不用函数名代替同批多个调用 ID。

必须在所配真实服务上观察到“依据前次结果再发起后续工具查询”的路径后，才能声称该能力验收；不以脚本 fixture、提示强制顺序或批内执行先后冒充自主决策。现有 MiniMax 初测尚未覆盖，当前不追加真实请求。

### 5.4 推荐引导与专用认证

首次／续聊／失败的推荐短语由本地 GuidanceCatalog 提供，不额外调模型。模型可同轮返回受控追问，不能因此注册新动作或直接云写；Web／CLI／TUI 的同意图和确认契约见[用户引导](guidance-and-entrypoints.md)。Agent 工具仅获 QueryService，不持云／模型凭据；采集时 CloudCredentialProvider 对 CFW／ECS 复用明确身份，启动／环境／STS／MCP 边界见[凭据与权限](credentials-and-permissions.md)。

## 6. 协议与输出约束

首版仅接已配置的非流式 Chat Completions，复用固定 Eino 模型组件和应用 guard。OpenAI 官方工具调用指南（本方案复核 T-12）是协议概念依据，不代表所有第三方支持相同能力；Chat Completions 的工具结果关联与 Responses 字段不混用。

保留用户当前模型配置，不把文档推荐模型替换进来。MiniMax 所需的完整 assistant 消息连续性按已验证路径在内存处理；`reasoning_split` 不被误当关闭思考。JSON 依靠 schema／本地校验，不预设原生 strict JSON Schema。截断、未知工具、非法 ID、越界参数或不合法最终结构均失败／降级，不静默换协议或无限重试。

角色输出至少含候选服务／角色、支持与反对证据、未知项和待确认问题；不能直接写 confirmed。审计推荐引用 `policy_scope_ref / rule_version / evidence_ids / business_ref`；针对已有发现时携带 finding_id，条件化组件评估不伪造发现或策略 ID，用声明来源引用代替编造字面网段，并给条件／影响／人工复核动作。

校验顺序：严格结构与大小 → 对象／范围 → 版本／引用 → 业务约束 → 来源／建议目标。已确认来源、必要端口和明确禁止不能被输出扩大或抹掉。校验无法证明每句自然语言都正确，因此事实字段由服务端生成，模型正文作为独立解释／疑点，不改变规则结论。

### 6.1 B2 推荐的额外校验

policy_change 类型的 `target_policy_ref` 或 `target_policy_set_ref` 必须属于当前分区，目标字段与方向一致：入向可讨论来源约束，出向讨论目标依赖，NAT 还需观察点证据。用确认资料引用表达新允许集合，不能因为模型生成了一个看似合理的字面 IP 就允许进入修改建议。

建议使用 `confirm_intent / collect_missing_evidence / review_rule / conditional_restrict / conditional_allow_required` 等本地意图；不输出可由工具直接执行的 SDK method、shell 或任意 URL。条件、影响和未核实项单列；缺证据时只给待办，不填充“默认安全来源”。

同会话不代表所有历史都可外发：ContextBuilder 与摘要按当前 scope／disclosure 过滤，跨方向／网关的工具衍生事实不得通过历史回放绕过查询授权；见[数据与API](data-and-api.md)／[会话与执行](session-and-execution.md)。

工具事件保存 call ID、工具名、范围摘要、输入／输出证据引用、成功／拒绝／截断与耗时；可见决策摘要说明依据什么资料选择了什么下一步，不保存或要求完整内部推理。两个同名工具调用必须按各自 call ID 回传。

## 7. 工程预算与限额（不是当前付费授权）

以下是已随整体G2采用、尚未实测的工程默认上限，用于阻止无限执行；**不是模型服务费金额保证，也不授权现在按这些值发请求**。实际采用值取用户私有配置与项目上限中更严格者，不自动提高现有实验的次数／输出配置。

| 项目 | 设计默认 | 说明 |
| --- | --- | --- |
| 并行长任务／排队 | 1／10 | 前台优先、后台定时默认关；不代表业务只有一次性任务 |
| 助手轮次模型 HTTP／工具／执行时限 | 4／8／90 秒 | 连续会话内有界轮次，排队和总时限见[会话与执行](session-and-execution.md) |
| 审计模型阶段 HTTP／工具／阶段时限 | 6／12／120 秒 | 这是模型阶段而非含采集的总任务上限 |
| audit 排队／执行／受理到结束 | 120／240／360 秒 | 执行内含认证／采集90、规则20、模型120、最终化10秒，子调用取根剩余值 |
| 模型单次时限／请求输出参数 | 最多 30 秒／最多 1024 | 当前私有配置若是 512 则保持 512，不在失败时自行抬高 |
| 模型请求／响应正文／单工具回复 | 128 KiB／256 KiB／32 KiB | 字节约束不冒充 tokenizer 或金额上限；截断必须明确 |
| 采集总 HTTP 尝试／阶段时限 | 100／90 秒 | 认证／凭据交换、两轮配置复读和退避都计入；并发独立读最多2，token依赖分页串行；权限错误不盲重试 |
| 每任务资产／该分区 CFW 策略 | 50／1000；NAT 网关 1 | 网关策略集模式允许零资产但不扩全账号；超限标范围截断 |
| 确定性单查询单元 | 50,000 | 已证明违例可保留，未穷尽不得转为通过 |
| 普通 JSON／离线导入 | 1 MiB／5 MiB | 深度／数组／对象数另外校验，不解压任意文件 |

这些值是可调整设计假设，G2／工程验证时再核对目标机器和案例规模。执行预算、会话累计和应用限额分层取更严值，新建会话不清应用账本；仅执行次数仍不是全账户货币上限；界面和报告如实显示已用尝试及可得 usage，未返回用量保持未知。

工具内容过大时按结构化条目有界选择并标记未返回范围，或直接失败；不能生截 JSON 后冒充完整结果，也不能截掉未知条件后推导通过。

不得由模型、工具参数或错误重试自动扩额度。重复查询无新证据时有限停止；失败后重启不重放，用户显式重试为新任务。对方收到请求后是否计费只能以实际服务账单为准。

## 11. 来源保证进入结果与工具

规则集合运算和输入是否真实／全量是不同问题。统一结果保留 verdict、assessment_basis、assumptions、覆盖／限制、证据与版本：synthetic_assumption、imported_assumption、live_observed 不互相升级。

普通导入在声明覆盖完整、结构／引用闭合且 provider_semantics 合格时，可计算相对给定配置的条件结论；该声明不成为真实云完整性的证明。缺页／矛盾数量／未知引用等已知缺口不能被声明覆盖，仍降级。没有完整性声明时，不自行补出全量假设。

工具返回、Agent 条件、报告与 UI 必须保留导入假设。模型试图删掉 assumptions、把 imported_assumption 写为 live_observed，或把条件 pass 说成当前账号安全，校验拒绝；自由文本正确性仍需复核，原始事实层由服务端模板生成。

汇总区区分已确定的案例／观测结论和条件配置观察，不能把条件项混进“已证实真实风险／全部通过”。评价主体采用明确构造的 synthetic 标签；真实输入和外部导入的保证级别不作为标签偷渡进模型。

## 12. 模型能力证据矩阵

模型配置存在、HTTP 200 或普通文本成功，不代表当前适配器通过 AC-06。验证记录绑定 provider／模型配置引用、协议适配器版本、案例版本、日期与实际预算，不存密钥／私有端点或完整 reasoning。

| 能力 | 本地模拟能验证什么 | 真实所配服务仍需什么 |
| --- | --- | --- |
| 多轮与关联回传 | 同批多个 call ID、非法 ID、连续消息组织和工具结果回传 | 实际多轮工具请求／响应能正确关联，不只一批工具 |
| 依赖式选择 | 驱动循环可处理前次才返回的新引用 | 至少一个后续调用依赖前次结果；另一案例呈现不同路径或因缺信息停止 |
| 可校验结果 | schema、对象／范围、版本、证据、业务和来源保证校验 | 真实输出能进入结构校验；不能靠猜测字符串补成通过 |
| 失败行为 | 网络／限额／取消／截断／未知工具／无效结构的保留与终态 | 按明确预算核对所配服务失败及能力不足反馈，不无限重试或暗换协议 |

每格记录 unverified／passed／failed 及证据来源，不以一项通过覆盖其他项。旧两个人工 MiniMax 样例只证明其记录中的有限行为；本方案不追加真实请求。模型／适配配置变更后旧证据保留但不能无条件沿用为新配置验收。

执行期间能力不足则保留已有规则，Agent 阶段 partial／失败并列出原因；用户可明确使用 rules_only。不能一边回退普通文本、一边把该次标为完整 Agent 成功。

## 13. 推荐目标必须覆盖原有核心需求

FR-13 的覆盖／组件建议不一定对应一条 ACL，不能让所有建议都强制填写 target_policy_ref，否则会遗漏该需求或诱导伪造策略 ID。输出采用带类型的联合契约：

| kind | 允许目标与依据 | 不能做什么 |
| --- | --- | --- |
| policy_change | 当前分区的现有 policy 或 policy_set，明确字段／方向、原发现和业务依据 | 不自动执行；新增条目建议不能伪造一个已存在的 ACL ID |
| coverage_followup | protection_scope／asset_service，已知当前层状态与保护目标 | 不把未知当未部署，不把 CFW 关闭说成所有层失效 |
| component_consideration | asset_service／scope，版本化组件主题、角色／暴露条件与可定位证据 | 不接入新产品；不要求购买全部组件；不把未查询的 WAF／IPS／日志状态说成已知 |
| confirm_information | 当前资产／业务要求／分区及缺项依据 | 不自动确认角色或授权，不用候选代替业务事实 |

所有类型都带 scope、来源保证、条件、影响和下一步；basis_kind 区分已知缺口、适用性评估与未知待核查。适用性建议可以没有 finding_id，但必须有真实引用的事实／基线，不能捏造一个 fail 发现凑字段。

组件目录只使用既有 B2 主题，不含云安全中心；M1 精确状态／日志分析仍默认关闭。建议“核对是否适用”不等于已实现对应 API 或已检测产品状态。界面按 kind 展示，不把这类建议都渲染成“修改某条 ACL”。评价按需求的对象／证据／业务约束／新增开放四项判据进行，不以产品数量评分。

组件主题与条件模板来自已固定的 baseline 版本，通过受控初始上下文或 get_rule_definition 的相关主题返回，并生成可定位的基线证据引用；不需要新的云产品查询工具。模型不能从任意网页或产品名自造目录。没有模型时也可展示规则／模板已有的条件性提示，评价时不人为删去纯规则组的这些基底信息。

## 14. Agent可见事件投影

Eino 执行由后端显式投影为 [前端与事件](frontend-and-events.md) 的阶段、工具开始／结束、发现／公开消息／报告引用和终态事件；只在对应业务记录提交后发送。SSE 是服务端到界面的业务事件流，不改变本设计的非流式模型适配，也不是新增 Agent 能力证据。不能透传原始 Eino 消息、reasoning 或让模型自行标记工具已执行。规则结果先可见，模型失败后原始规则保留。

## 15. 不同会话的运行隔离

整体G2已通过；单进程3个执行槽位，各任务有独立Runner运行状态、输入、call ID、工具闭包、取消和上下文投影。允许共享不可变定义／受验证的连接池，不共享可变当前scope或消息切片。E0／E3验证固定Eino与模型组件并发安全，不满足时每任务实例化，不能全局锁住整个Agent轮次。

全应用模型HTTP并发上限3、单任务1；等待计入阶段／根deadline，每次尝试在共享账本原子预占。并行不增加授权预算、工具权限或可外发字段；取消／失败不波及另一会话。三路模拟HTTP屏障、隔离与额度竞争见[31 §2](architecture.md)。正式评价三组实验不因3会话运行能力而自动并发执行或扩大请求预算。
