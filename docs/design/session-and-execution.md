# 会话、任务执行与恢复设计

基线：需求v0.6／B2、设计v0.6，G1／G2已通过。本文为该领域的现行详细设计；实际运行验收另行取证。2026-10-30按[客户旅程J01～J24](../requirements/customer-journeys.json)整理目标链、已提交缓存复用、同分区分批与统一工作负载保护；正式Go／Vue现已接通对话／目录、同audit准备与晚封存、合格复用、共用业务草稿／可信归属和同分区串行分批。当前代码及限定离线／浏览器结果见[代码记录](../validation/evidence/conversation-implementation-local.md)，完整24旅程／88分支与真实接入尚未验，剩余项见[实现台账](../development/implementation-gap.md)。

## 1. 业务模型：连续会话与客户目标

首版以一个默认审计空间组织单账号来源、目录、画像和基线，不建设组织／多租户平台。空间中可有多个命名会话；会话可在没有快照时建立并保存非敏感目标、澄清和后续任务／报告。对话任务意图决定“本次做什么、审谁、哪个边界与时点”，业务角色／访问要求决定判据，两者不能互相替代。

目标链为：客户话语→本地目录检索与必要澄清→有限发现／资料准备效果预览→类型化计划接受→合格资料复用或必要刷新→一次封存→规则／按模式Agent→固定报告及审阅→人工改后新资料复审。名称／ID／地域／类型或有来源的已确认业务归属都可作为线索，连接配置只提供权限上界，不要求管理员逐台预列资产。规划只查本地目录；若使用模型解析，须有本次明确模型选择和既有授权，但不赋予规划器云Reader。目录不足时可接受同一目标下的有限发现与后续审计效果；单对象请求在结果唯一且未扩范围时继续，重名多候选停在澄清，不取首条；显式有限集合按完整覆盖核对全部成员。

客户只核对业务范围、资料策略、模型模式及外部效果，不逐API确认。必要分页、身份核对、已获准刷新和有限重试沿用同一接受记录；对象歧义、范围／模式／效果实质变化使旧预览失效并重新核对。每个正式任务仍是一个边界／方向／实际策略分区，NAT一次一个网关；多边界在同一会话形成分别接受的关联任务，不引入多分区父任务。

显式“全部”或有限地域ECS集合也可使用非归属组目录选择器：标签键值作为数据，不能再充当名称／ID；明确更换名称／ID时仅采用本轮标签。只有同来源／账号的完整覆盖且分页游标稳定才形成全集，局部目录的一条记录也不代表全部；普通同名查找仍消歧。当前本地绑定包络为1000，达到保护且仍有页时保留未穷尽与收窄提示，不作为目录总容量或永久产品上限。

同一分区匹配对象超过当前批次时，先显示匹配覆盖、批次和结果限制，由客户明确选择分批或收窄。选择分批后可持久化一个父请求和顺序内部批段：各批段具有对象子集与独立固定输入／manifest，父级汇总已覆盖、未处理和失败；不截前N项冒充全部。父请求只占一个会话活动位及一个worker，内部批段不再进入同一队列等待自己，全部共享原接受范围、根期限和外部额度。当前分批编排已实现，父任务只汇总covered／failed／unprocessed及用量，不生成全组合并Audit／Report；covered只指保存审计证据，不等于规则通过或模型完整完成。段报告可分别打开及复审，取消主请求停止新增段，排队取消亦原子记录各段unprocessed；不新增后台队列系统。

典型会话：

1. 空白输入“审计杭州web-prod入向”，系统检索并消歧；20台业务群同样可作为有限对象集合，3会话并发不限制资产数。
2. 接受同范围必要准备／审计后自动推进，先保留规则结果；不知道白名单可继续独立基线，角色与访问要求另行预览、分项确认。
3. “解释昨天报告”绑定原报告、证据和时点，云读取上限为0；可直接读取固定解释，只有用户明确选择新的模型解释时使用获准模型预算。
4. “核查现在”判断已提交资料是否合格；“我已手工修改，重新采集复审”必须取得声明变更后的资料。旧报告、确认与审阅不改写。
5. 刷新／重启后重开会话，恢复已保存消息、资料、报告和中断记录；观察断线不取消，运行中断不重放。

## 2. 持久化层次与边界

| 层次 | 保存什么 | 不做什么 |
| --- | --- | --- |
| 审计空间 | 默认来源／范围、资料指针、基线和会话列表 | 不把它变成云上租户、组织权限或多账号治理平台 |
| 会话 | 标题、当前目标／范围、偏好数据策略、上下文摘要位置、最后访问及归档状态 | 不每次发送就新建，不把新会话当预算重置接口 |
| 用户可见消息／轮次 | 经敏感值处理的用户正文、助手公开答案、目标修订／字段来源、澄清与候选／选择、计划接受引用、业务确认事件、任务与时间 | 不保存密钥或完整内部推理，不把助手建议写成业务授权 |
| 执行任务／阶段 | 请求、数据计划、固定后最终输入、规则／工具事件、尝试／耗时／用量 | 不用执行记录替代可继续对话的消息历史 |
| 资料／证据／报告 | 不可变快照、画像／授权版本、原始规则发现、报告和本地审阅历史 | 新资料不覆盖旧输入，归档会话不级联删除证据 |

入库前拒绝／屏蔽系统已知凭据值和明显密钥输入，正文不先写日志；不能保证识别用户随意贴入的一切未知秘密，界面始终说明不要在聊天贴密钥。消息保存到私有业务库，刷新／重启后由 API 分页加载，不依赖浏览器 localStorage。可见助手正文为本地私有历史，公开报告仍默认采用白名单结构，不能因历史存在就把自由文本导出。

目标发送以稳定`client_message_id`绑定目标修订；纯本地澄清无需强建收费任务。模型规划或固定资料助手的明确发送另绑定范围／投影、`model_use_accepted`与现有预算，执行接受绑定proposal修订、配置／目录／业务版本和幂等意图。可见消息、接受引用与实际执行受理使用短事务，受理答复未知时先查询原提交、同键重试，不新建消息／模型执行。同会话首版只允许一个未结束的 queued／running／cancelling 执行；新输入可等待、保存草稿或由用户显式取消前轮后发送，不能默认自动抢占／重放；本地确认、审阅与历史读取不占执行槽位。不同会话使用3个并行执行槽位；前3个会话可同时推进，槽位占满后后续会话明确排队，不把多标签页等同于业务并发。

## 3. Eino 的职责：历史、上下文与 Checkpoint 分开

F-08 官方示例明确由业务层管理 Session／Memory／Store，再把消息交给 Runner；F-09 的 CheckPointStore 是中断／恢复运行的可选接口，不规定 SQLite、GORM 或固定表结构。E3已在固定v0.9.22上接入每任务独立的ChatModelAgent／Runner，未修改依赖；当前人工协议fixture验证与真实上游模型能力分开记录。

### 3.1 首版选择

- 应用用 GORM／私有库保存可继续沟通的业务历史、确认事实与版本；Eino 负责当前有界轮次内的模型／工具循环。
- 每轮 ContextBuilder 从同空间／会话取当前分区与外发政策允许的最近消息、分区摘要、已确认事实和被引用报告，形成本方案可授权上下文；不是只发最后一句，也不每次把全部历史／原始云数据重发。
- 同轮按模型协议需要在内存保留完整 assistant／工具关联及必要 reasoning；结束后仅保存公开答案、受控工具摘要与引用。
- 首版不持久化完整框架 checkpoint。运行中重启标中断、保留已落地历史／证据，用户可以继续会话，但不会自动重放上次未完成的付费调用。
- E3使用正式ChatModelAgent／Runner驱动单任务循环，guard限制模型／工具次数、同批ID、字节和剩余时限；不共享可变Runner，不让普通追问抢占另一任务。人工协议fixture不替代真实上游兼容验收。

### 3.2 历史回放与新事实

不将截断的旧 assistant 工具调用和孤立 tool 消息拼成“完整协议历史”。重建时使用公开对话内容和证据摘要；必要时把它们作为引用上下文，不复用旧 tool_call_id 或缺失 reasoning 的原始协议片段。

ContextBuilder 按预算选择最近公开消息与摘要，并总是从固定业务版本取得必要约束。历史过长明确记录未带入范围，不丢掉确认约束后假装上下文完整；优先从结构化资料生成摘要，不每轮额外调用模型总结。助手旧答案仍是历史解释，不自动变成当前事实。

用户补充但尚未确认的信息停留在共用草稿。角色、允许集合、必要访问与例外分别绑定规范对象／服务、边界方向、确认版本和适用时间；角色确认不确认访问，来源空白不等于明确空集合。批量确认必须列明实际对象集合，不把一个服务的确认泛用到其他资产或方向。换快照、标签变化或业务版本变化时展示差异／冲突，不静默覆盖已确认内容；“解释昨天的报告”沿用昨天的绑定，“核查现在”需要新的数据计划。

### 3.3 E3上下文与产品结果落地

ContextBuilder以job→plan→turn→接受消息位置及原policy scope绑定读取窗口，最多20条／24 KiB；只投影同范围可见历史，保存included／excluded／truncated与minimal-v1投影版本。范围切换、归档和后续新消息不改变已接受任务的上下文；旧wire／reasoning不回放，历史助手解释不升级为事实。固定输入的evaluation_at／collected_at与一致性声明不被墙钟或新快照覆盖。

Agent产品结果、逻辑模型／工具计数、受控错误和本地证据绑定持久化；保存前重验任务、manifest和引用，原始模型协议不落库。受保护任务结果可见完整经校验解释；公开报告只投影固定模板和公共别名。模型阶段completed与job终态分开，后续取消／中断不能把整个任务误标完成；保存结果不能恢复新外呼。已通过的限定离线证据见[E3记录](../validation/evidence/e3-local.md)。

草稿恢复先GET同稿与current-base并保留本地输入；用户从逐字段差异明确选择后才同稿更新／rebase并重新预览。当前稿revision及刚核对的业务heads双CAS，未选字段、新服务和最新保存的待确认声明保留；不新建替代稿绕过会话绑定。未知rebase答复保原body/key，读最新不改原请求；原回执若旧于当前稿，分开呈现且重新核对，不能回退或直接确认新稿。

## 4. 数据策略：已提交合格缓存与按需刷新

| 策略 | 用途 | 目标行为 |
| --- | --- | --- |
| `pinned_snapshot` | 解释／复验指定历史结果、离线输入 | 固定版本，云读取上限为0；明确显示原时点和来源，不因用户追问自动刷新 |
| `prefer_fresh` | 日常或“核查现在” | 只从已经提交、不可变且覆盖合格的资料中复用；缺失／陈旧／不完整／版本不符时，在已接受效果内按需刷新 |
| `force_refresh` | 用户明确强刷或声明人工变更后复审 | 不用旧缓存满足要求；`fresh_after`不得早于用户声明变更时点，取得新资料后形成新任务输入 |

`allow_stale_fallback`默认false。刷新失败保留失败、缺口与可证实的局部结果；若用户改为用旧资料解释，建立明确的pinned历史分析，不给“当前已修复”。若产品显式允许旧资料回退，计划及报告必须保留原时点和回退原因，保证级别仍是历史条件，不能满足变更后复审。

### 4.1 合格与可复用条件

首版只复用已完成提交的不可变snapshot／数据族，不复用正在采集的中间页或未提交结果，不实现inflight请求合并、跨任务等待同一刷新或复杂共享取消。多个会话并行刷新可能各自消耗已授权额度，不能以未来合并优化代替当前预算核对。

每次资格判断记录账号／连接权限修订、规范分区／网关／方向／地址族、对象选择及覆盖、采集schema／normalizer／semantics版本、原采集窗口、枚举完整性、引用与关联闭合及已知变更。安全组关联变化使相关组资料失效；目录较新不代表策略／引用／保护资料较新，TTL合格也不代表成员完整或来源真实。

CFW策略、保护、适用引用与模式作为相关配置族保持一致窗口；不能拼新策略与旧地址簿证明有效路径。资产元数据、SG及NAT关联可有各自时点，但依赖必须闭合并在manifest中列明。复合输入只引用各自已提交不可变资料，复用原时点不通过新snapshot创建时间续鲜。

时效阈值来自服务端版本化工作负载／资料策略，并需校准；历史15分钟配置族／60分钟元数据仅是未测提案，不是永久默认或厂商SLA。业务确认按对象／服务／方向／版本／有效期判断，不以TTL代替授权。

### 4.2 按需与可选定时

M0交付合格复用和按需刷新。客户接受的有限发现／必要刷新／后续审计在同一执行内共享保护，固定资料九工具不访问云；初始计划已覆盖的准备不逐HTTP重问。当前首版不加入inflight coalescing，也不要求独立采集任务入队后由占位audit同步等待。

定时采集可选、默认关闭。只有另有明确固定范围／周期／额度授权才定时读取，不自动调模型或改策略；前台任务优先，重启不补错过周期。若将来实现，也先复用已经提交的合格产物；同进程待执行调度去重可单独评估，不能把跨任务刷新合并当M0前置。

### 4.3 历史E4切片与当前准备实现

E4历史证据验证的是force collect后独立pinned audit两步切片，见[E4记录](../validation/evidence/e4-adapters-local.md)，其范围不追溯扩大。当前代码已接同一audit的有限元数据发现／必要采集、完整已提交snapshot的M0资格检查与复用、晚封存及父请求串行分批，独立collect／pinned入口仍保留。复用保留原时间，热复用可零云；force_refresh不偷用旧资料。任意族拼接、跨任务inflight合并和可选定时调度未交付；connection_check仍为IDENTITY_ONLY partial，不证明产品权限。

历史解释GDE-05的模型分支只读核对原report→producer job→固定snapshot，选回A资料并预填绑定A的解释短语／模式；不是复审表单。发送只生成零云读取的assistant_turn提议，接受后才运行模型。明确“不用模型”等否定先于正向词解释；历史／当前或模式冲突先澄清，保留原对象／报告锚点，不默认扩大效果或丢掉续句上下文。

## 5. 输入绑定：请求先冻结，实际输入稍后封存

支持按需刷新后，旧设计“接收请求即绑定一个实际快照”不再适用于所有模式，故分两层：

1. `request_manifest` 在受理时不可变：空间／会话／资产范围、数据策略、确认资料基版本、基线／模型配置引用、外发政策、预算和用户意图。
2. `data_plan` 记录预计复用／需刷新数据族和原因；计划与实际结果分开。
3. 合格复用或必要采集、关联与归一化完成、进入规则阶段前，生成一次 `resolved_input_manifest`：实际快照／分区时点、固定业务／规则／规范化版本及 evaluation_at。之后不可替换。

默认评估时点为进入分析的时点并封存；明确复验可引用原值。排队时旧资料被修改，仍使用请求锁定的确认版本并提示，不悄悄改为最新；若实际新资产／新线索与基版冲突则标待确认。

有界工作器池下，audit需要刷新则在本次执行准备阶段内调用采集服务，**不创建子collect入同一队列再同步等待**。只复用已经提交且合格的资料，不等待其他任务的inflight刷新。同分区已确认分批时，内部批段串行，各自一次封存并记实际覆盖，父请求汇总且未处理不冒充通过；不同分区仍分别接受任务。所有阶段／批段共用原根预算，不给子阶段新额度。

## 6. 累计耗时与执行预算

用户等待时间不是模型某一次超时。需分别记录：

```text
总墙钟时间 = 排队 + 准备/认证所在阶段 + 采集关键路径 + 归一化/规则 + Agent循环 + 校验/报告
外部请求累计耗时 = 各云HTTP、凭据交换、模型HTTP（将来MCP）的实测耗时之和
```

并行查询有重叠，累计请求耗时可以大于墙钟时间，不能直接相加当成用户等待时间。认证／SDK续期计入所属阶段，重试退避也计时；不要把嵌套阶段重复加总。保存排队／阶段起止、缓存命中、实际尝试、可得用量和错误，不能拿缺失 usage 当零。

### 6.1 当前统一工作负载与legacy数值

当前[workload](../../server/internal/workload/limits.go)将单次、根／阶段、逻辑模型、物理云／模型、工具／单批、对象及计算保护解析为不可变effective limits，计划、Store、Engine、Runner、Collector和[outbound](../../server/internal/outbound/transport.go)共用。显式`--execution-config`可配置比历史提案更大的合法profile；适配器私限、最新持久授权和显式0始终取严。缺显式profile时使用有legacy标签的30秒、助手4次／审计6次、工具8／12及单批4、助手／采集90秒、审计240秒、采集100次等兼容值。它们仍未校准，不是供应商SLA、永久产品上限或新增付费授权，也不保证全部轮次均有完整窗口。

E3／E4人工协议fixture与2026-10-22两个历史模型样例不足以校准真实延迟、分页、工具依赖或token费用。[采集研究](../research/collection-workload.md)证明同20资产的请求量还受CFW切片、共享SG、ACL页数及引用影响；原逐资产路线的合成算例131次曾超过100暂值，当前批量ECS／SG去重已减少重复，但不能无授权扩大CFW切片来凑低次数。需联合实现选择器、批量／去重和统一工作负载保护，而非只抬常量。

当前非流式模型完整缓冲JSON；业务fetch SSE只传已提交事件，不代表上游模型流式。所核固定Eino模型组件没有提供本项目这些数值，官方兼容文档也不提供项目SLA；来源与限制见[技术研究](../research/collection-workload.md)和[模型／Agent设计](audit-and-agent.md)。

执行并发维持3个不同会话、同会话1个未结束任务，第4个明确排队；当前等待队列10、全应用云2、模型3／单任务1仍是固定运行保护，尚未提供可调并发profile字段；它们不扩大授权。

### 6.2 已实现的统一解析与剩余校准

统一resolver与贯通保护已实现。连接、所配模型与任务种类的工作负载profile由服务端显式配置；它不是机器默认profile、dotenv或凭据兜底。统一resolver一次校验连接能力、模型／协议与输出限制、任务阶段、并发、当前持久授权修订和凭据状态，生成不可变effective limits及来源版本。计划预览、存储准入、工作器、Runner、采集器与HTTP适配器共用该结果，不在各包继续放不同的常量；客户端和模型不能自选更宽profile。已有模型、512等更严私配、显式零额度和已批准范围继续取严。用户正常操作只选择业务范围并确认效果，不每次填写限额或日期。

单任务根deadline、模型每次完整响应timeout、连接／TLS／响应头子时限、模型阶段剩余时间、累计授权到期和credential本身到期分别表达。它们不共用一个expires_at含义；授权或凭据有效不能延长任务deadline，长任务也不能越过授权到期继续新发送。响应头返回不等于TTFT；如将来单独实现并验证上游stream，还须区分首有效事件／首内容token、流idle和总响应时限，定义哪些事件可重置idle，持续零碎数据也不能绕过total。SDK获取凭据、重试退避、槽位等待、解析与结果持久化均须有归属；不能仅给业务函数套协程超时就声称物理请求已取消。后台继续使用typed job context和剩余deadline，不能传入已结束／被复用的Gin请求上下文。首版非流式适配无需为了调整超时同时扩展协议，未来stream也不改变浏览器断线只停止观察的语义。

根预算与串行阶段按下面关系闭合，所有时间均用本次任务记录的时点与单调计时计算，不重复累计嵌套阶段：

```text
D_root    = t_accepted + Q + E
D_execute = min(t_started + E, D_root)
D_stage   = min(t_stage_started + S_stage, D_execute)
D_attempt = min(t_attempt_started + R_overall, D_stage, 已有更早deadline)
允许新发送 = task仍活动 且 policy_revision仍允许 且 ledger可写 且 authorization未到期 且 credential当前有效
串行阶段：Σ S_stage ≤ E；阶段关键路径包含等待、认证、退避、解析和保存
物理模型HTTP数 = Σ每次逻辑模型调用实际产生的HTTP尝试数
物理云HTTP数 = 身份尝试数 + Σ复读轮 Σ操作 Σ实际页 每页HTTP尝试数
```

Q为排队预算、E为执行预算，S为阶段预算、R为单次完整响应预算；上述时长与可选累计授权有效期、STS凭据有效期分属不同约束。连接／响应头／读body或stream-idle子时限都受D_attempt剩余值约束。历史audit的90＋20＋120＋10＝240、排队120＋执行240＝360只用于解释旧提案，不是目标profile的固定数值，也不证明真实工作负载可完成；E4历史证据仍是collect后另开pinned audit；当前同audit准备与串行分批已共用一次接受的总期限和额度，不给每段复制上限。目标profile应为最终校验／保存留出明确阶段空间；不能因前面耗尽而无条件追加时间，也不在错误时把省下的阶段额度自动变成新的模型或云尝试授权。

模型逻辑轮次、物理HTTP／重试、工具总数与工具单批已经分别配置和计数，显式profile要求独立finalize_seconds收尾时间。Runner会拒绝在最后逻辑轮执行无法再形成答案的工具调用；独立最终回答次数／物理重试预留参数仍未交付，以下保留为完善约束。继续补查前检查是否还保留最终答复所需的逻辑轮次、物理尝试和时间；未留足则停止补查，保留已执行证据并返回部分／受限结果，不能用耗尽额度冒充完整回答。重试仅在明确的可重试条件、次数和退避内执行，仍逐物理尝试预记；不无限重试、不自动换模型、协议、授权周期或抬额。

采集成本按所选资产、关联组／引用、实际分页和最多两轮配置族复读估算；已知TotalCount可形成页数估计，NextToken尚未知时记录不确定性，不编造精确剩余请求数。身份、两轮全部页面、允许的重试和解析共享同一根预算，第二轮不另领额度；当前CloudService已从计划次数中先扣身份1次再分配Collector预算。达到次数／时间边界而未穷尽时保留缺页、未解析引用或第二轮不完整，不能转为通过；legacy的50资产／1000策略也不保证任意页数都能在历史90秒窗口内收完，显式profile仍须结合实际页数校准。

原逐资产ECS／CFW路径的50资产两轮下界203次是历史结构推导，不再描述当前源码。当前同地域ECS以最多100 ID批量加NextToken、安全组／引用去重、ACL每轮共享，CFW仍按获准逐ID读取；20人工资产签名loopback记录61次物理尝试。它只证明固定人工协议路径的计数，不是云限额、真实RTT或任意规模可完成承诺；仍须联合实际分页、成本估计、分批与总保护。

## 7. 分层输出，而不是一直等待最终模型回答

| 层 | 何时展示 | 必须标明 |
| --- | --- | --- |
| L0 计划／排队 | 受理后 | 拟复用／刷新哪些数据、范围、预算、等待状态；计划不是模型已执行步骤 |
| L1 事实／完整性 | 读取缓存或采集就绪 | 来源、数据年龄、缺口；缓存预览不是本次已封存输入 |
| L2 确定性结果 | 规则阶段落地后 | 规则事实与待确认项，Agent 补充待完成；可先审阅，不等模型 |
| L3 Agent 补充 | 经过校验的工具／公开结果就绪 | 已执行工具、引用、角色候选／条件解释与错误；不展示完整内部思考 |
| L4 汇总／报告 | 终态结果就绪 | 固定输入、覆盖、阶段失败、本地计划及复审关系，不因部分失败抹掉 L2 |

首版用持久有序事件＋fetch SSE 主通道／JSON 轮询兜底推进，不依赖模型 token 流式；完整协议、重连与终态规则见 [前端与事件](frontend-and-events.md)。订阅／重连仅恢复观察，不重放旧工具消息或付费请求；断线不取消任务，页面恢复不清零预算。阶段名、已知对象／已执行检查数、累计耗时可以显示；无法估计时不伪造百分比或倒计时。任务 running 时 `result` 返回 `is_final=false` 与已完成阶段，正式报告终态生成；如未来导出阶段报告，必须独立版本且标未完成。

3个槽位使不同会话可真实同时推进。历史读取／审阅不占任务槽位；外呼并发引用同一effective profile，迁移前模型3、云／凭据2继续作为当前更严限制；预算与时限分层取严。固定并发、输入／Runner隔离、有界资源等待和三请求屏障验收见[总体架构](architecture.md)。

## 9. B2 的分区缓存与计划时效

### 9.1 缓存键与就绪条件

缓存必须先是已提交不可变资料，合格键至少包含连接权限修订／期望账号引用、规范policy_scope_key、采集schema／normalizer／provider_semantics版本、必要对象选择及覆盖。互联网 in/out、不同控制面或两个 NAT 网关均不得命中同一策略配置族；不能因为 asset_ids 相同就复用。

NAT 配置族包含当前网关元数据／ACL／静态引用／模式，资产上下文与 NAT 关联证据作为另有时点的族。时效阈值引用版本化资料／工作负载profile，历史15／60分钟仅作未校准提案；关联改变或 owner／模式变化要使有关计算输入失效。TTL 合格不代表成员完整、账号正确或两次观察稳定。

真实只读刷新默认最多两轮完整配置族读取，形成 observed_stable／changed／unverified。仅两次相同不声称原子快照；已知变化或第二轮未完成使受影响配置路径保持部分结果。固定离线制品可记 fixed_artifact，不伪造复读；来源真实性／全量性仍独立判断。当前API、认证与重试共用本次effective profile及更严私限／授权，第二轮不获得独立预算；100次／90秒只在legacy兼容路径保留，显式profile也须按实际页数校准，不能描述为真实采集能力。见[云采集设计](aliyun-collector.md)。

### 9.2 预览计划与执行阶段的关系

`execution_plan` 是本地预览和效果授权的记录，建议 5 分钟有效；`data_plan` 是预计及执行时实际复用／刷新选择。用户确认有效计划后，创建 job 的时点才开始计算排队／根时限，不把用户阅读预览的时间伪装成服务执行时间。

计划中的 prefer_fresh 必须预先说明可能刷新；执行时缓存因排队过期，可以在已批准效果上限内更新 data_plan，不能改 request_manifest 的 scope／模式／预算。pinned_snapshot 的云读取上限为零，绝不能自动升级为实时采集。force_refresh 不以旧缓存满足 fresh_after。

计划消费后按原幂等键重试返回原job；受理答复未知先查原提交，不新建键自动重复收费。更改连接配置／范围／业务版本的请求必须重新预览。累计预算修订追加额度不自动扩大已接受计划的冻结上限；收紧／禁用／到期对每次物理发送即时取更严值。手工修改配置产生新修订号；Provider 合法 STS 续期不是换账号或自动扩权，但也计入根预算。排队时配置版本已失效则停止并提示，不偷偷改用最新连接。

运行中的 deadline 使用进程单调计时并受剩余时间约束；queued 的受理／到期时点持久化，重启只续仍有效的排队记录，运行中任务标 interrupted 不重放。时钟信息无法确认时不延长额度。

### 9.3 反馈与验收

L0 明确本次分区、网关／资产模式、预计复用与允许外呼；L1 展示各族原始窗口、稳定性与缺口；L2 保留已计算事实；L3 模型补充不替换分区；L4 报告固定完整 scope 和输入。切换边界是新计划／新任务，不改写历史消息里的旧证据。

验证计划为 B2-11／12／15／16 和原 RC-21～24。本方案静态示例校验不执行缓存、SDK 取消或计时测试。

### 9.4 持续会话的范围隔离

切换分区不删除业务会话，但模型上下文不能直接复用整个会话的原始历史／全局摘要。摘要按 conversation＋规范 scope＋disclosure 版本保存，并记录覆盖消息位置；其他网关／方向的助手事实与工具衍生信息不进入当前输入。当前 scope 的历史仍可连续使用，跨 scope 内容在 UI 保留本地链接。

B2-17 增加“同一会话先审网关 A，后审网关 B”的输入检查：不仅工具要拒绝读 A，上下文和摘要也不得偷带 A 的非授权事实。旧报告追问使用报告固定 scope；不会重放旧 tool 消息或隐藏扩权。

## 10. 持久审阅、准入与工作器恢复（RV4-03／04／06）

### 10.1 审阅也是业务历史

意见与采纳／暂缓理由关联原 finding／job 和 review_revision 持久追加。确认提交完成后才提示已保存；保存失败、响应未知或旧修订冲突时保留草稿，不用本地 UI 乐观状态充当已保存。刷新／重启从服务端恢复历史，旧报告仍绑定其生成时的审阅版本。细节见[数据与API](data-and-api.md) 第 11 节。

### 10.2 明确发送不是隐式刷新

所有执行都经过同一准入。目标解析／澄清先本地保存；audit／collect／connection_check的外呼来自用户接受的限时类型化计划，必要发现与刷新可被同一接受效果覆盖。固定资料assistant_turn明确选择模型后在同一事务产生内部计划，仅允许模型与本地固定资料，云请求上限为零；读取原报告已有解释无需创建模型任务。模型要求新云数据时只产生可审阅动作建议，不自建采集任务。

GET 引导、连接状态、预览、历史读取与保存审阅均不调用模型／云。可选定时采集继续默认关闭，若以后启用，采用已明确授权的 collect 效果，不获得模型权限。

### 10.3 排队与重启顺序

1. 进程先取得数据目录独占锁；第二实例失败退出，不修改第一个实例的 running 记录。锁实现须在目标 Linux／WSL 环境验收，不能用可遗留的普通“文件存在”假装可靠互斥。
2. 锁取得后检查 schema／连接约束，才把上次遗留 running／cancelling 标 interrupted，不回放调用。
3. 未过期 queued 保留原请求／预算；过期的 queued 在获取凭据前失败，错误码 QUEUE_DEADLINE_EXCEEDED。取消 queued 直接终态 cancelled；无需等工作器出队。
4. jobs 表是队列事实来源；入队时在同一短事务检查容量／会话槽位并写计划消费／消息／任务。内存通知只是唤醒，启动和周期扫描能发现已提交记录，不能因通知丢失丢任务。
5. 数据库或队列准入失败不出现已发送但无任务的半记录；界面保留草稿。worker 用条件更新领取任务，不能仅凭一次 SELECT 就认为获得执行权。
6. 运行取消返回“取消已受理／cancelling”，并关闭后续尝试准入；已有请求只能尽力取消，送达未知仍计次数。终态通过条件更新落地，迟到成功回调不能把 cancelled／interrupted 覆盖为 completed，也不能给已取消轮次补一条正常完成答复。迟到的尝试计数／费用信息可另记日志，不改写固定报告。

3个执行槽位和有界排队是首版基线，不是无限并发承诺；排队剩余时间与超时原因可见。新请求不自动抢占长审计，也不反复创建新任务试图绕过排队。

### 10.4 逐物理请求的持久预算

每次云、凭据交换或模型 HTTP 尝试在发出前原子预记，检查任务、用户已明确的批次／会话预算和应用更严上限。预记失败则不发请求；SDK 重试必须重新预记，不能把多次网络请求算成一次逻辑工具调用。

预算记录不随新建会话、页面刷新、配置 key 轮换或重启清零；预算周期／上限由明确配置或授权决定，不让模型或客户端自选新周期。未设置的应用级金额上限不能被描述成已提供全账户费用保证，调用次数与货币仍分开。

当前modelconfig／cloudconfig强制预算ref、未来绝对expires_at和应用／会话次数，且同Ref只许收紧；这是现有策略，尚不支持先云后模型的追加，不能冒称目标已完成。目标的服务端累计策略可以显式无到期或有到期，未配置的累计金额保护不能声称存在；任务仍始终受有限profile保护，已有私有限额／期限必须保留，不因迁移自动转无限。

累计账本按稳定`budget_ref`保留原attempt；配置追加、续期、收紧和禁用采用不可变授权修订，详见[凭据设计§5.5](credentials-and-permissions.md)。初次仅云导致模型0时，之后显式追加模型类别创建新修订而不换Ref或清零；反向同理。追加后的上限是累计允许总量，不给已有plan自动增额；收紧低于已用量时停止新增，不删除已用记录。到期续期只显式修改未来允许状态，不重启顺延、不重放失败调用。正常客户操作只选择范围／资料策略／模式，不逐次填写HTTP数和绝对日期。

模型／云同时启用时，任务冻结上限、当前授权修订、应用／会话剩余配额、共享并发和凭据有效性分层取严；显式0不视为缺省值。缺参数与显式0分别解析，默认值只能填未提供项，不允许`0→默认6`等扩大。授权到期、STS到期、任务deadline与模型单次timeout独立诊断，不用一个日期证明另一个有效。

启动后送达／费用未知的尝试保守记为已用，不自动重发或返还次数。只有能证明尚未发出才允许按既定规则释放预留；首版可保守不回收，不能为了成功率自行加额度。公开记录只保留 attempt 状态／计数与受控错误，不输出密钥或原始服务正文。

E3已用schema 3的budget_policies／outbound_attempts持久化共享应用／会话／任务预记，物理HTTP发送前再次检查执行状态与剩余预算；关闸后不继续发送，预记后未发仍保守占用。模型usage仅在成功响应中明确存在、结构完整且有效时记为known；缺失不从SDK默认零值补齐。attempt_usage分别给出物理尝试、known_usage_responses、unknown_usage_attempts及可空reported_tokens；显式零保留，部分报告不冒充全量，聚合溢出标usage_totals_overflow并使总token为空。次数与token均不等实际费用。

## 11. 事件流 订阅生命周期

事件／可见消息先保存，浏览器后展示；非流式模型只有公开答复提交后产生 message_available，不伪造 token 增量。最后连续 seq 属于当前页面已应用的投影，不孤立持久化游标；刷新重新解锁后从历史恢复。隐藏页／切换路由只释放订阅；显式取消、任务 deadline 与服务停机保持原语义。

SSE 订阅寿命／心跳、重连退避与轮询间隔不增加任务执行额度或重置累计尝试。终态事件必须排空后再停订阅，重启遗留任务终态为 interrupted、不自动续跑。客户端实时／重连／兜底／需解锁状态和业务 running／partial／cancelled 分开显示；详细阈值与 V5 验收见[前端与事件](frontend-and-events.md)。

## 12. 并发与恢复联动

同会话一个未结束槽位不变，全应用从单工作器改为3槽位；共享费用预占必须原子化、凭据续期有归属、Eino状态不能跨任务复用。独占进程启动锁用于单机单实例，不用于锁住三个任务。WAL＋普通共享连接池、事件seq、忙等待与存储不可写故障均见[总体架构的并发与存储](architecture.md)。

正常停机停止新准入／外呼、尽力结束或中断活跃任务；不能写成功不谎报已持久。重启恢复历史并标记运行中断，不重放；仅仍有效queued保留原计划、授权修订和预算，过期／配置失效者停止。按常规流程做本地备份／恢复、错误诊断，不新增存储专项框架；见[总体架构的恢复边界](architecture.md)。
