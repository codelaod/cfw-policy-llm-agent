# 对话主入口与用户引导设计

基线：需求v0.6／B2、整体设计v0.6已通过G1／G2。2026-10-30按[PRD](../requirements/product.md)与[唯一客户场景目录](../requirements/customer-journeys.json)修订。本文设计服务与呈现之间的契约；完整客户目标和合理／受限情境由需求定义，不由后台已有接口反推需求。当前无快照规划、来源隔离Resolver、持久ActionProposal与GuidanceCatalog已接正式Go／Vue；Business／Group分别已有23／27项人工输入浏览器检查，串行分批亦已有正式浏览器证据，见[当前记录](../validation/evidence/conversation-implementation-local.md)。完整24旅程／88分支、真实云／模型和正式评价尚未验收，剩余项见[差异台账](../development/implementation-gap.md)。

## 1. 入口与各层责任

Web对话为M0主入口，五视图辅助核对。没有snapshot也可表达目标、保存澄清；用户不需逐台预配资源或逐API确认。首版单账号，名称／ID／地域／类型／可信业务归属用于定位，同名或指代不清只询问影响执行的缺项。CLI／TUI为未来可选，一旦交付复用同一意图和权限；不编造正式系统命令，独立实验CLI不算交付。

| 层 | 做什么 | 边界 |
| --- | --- | --- |
| MessageRouter | 本地识别状态、取消、历史打开、表单修订、帮助；分流目标解析 | 清楚的状态／取消不先花模型；含糊取消先核任务，不取消其他会话 |
| IntentPlanner | 从消息与本会话获准上下文生成有限schema意图修订 | 可用获准模型协助；不持CloudReader，不把自然语言直接执行为RPC |
| ResourceResolver | 查本地目录、规范身份／范围与覆盖，返回候选或缺项 | 名称非唯一键；不能把未知／陈旧／权限错误当不存在 |
| ProposalService | 绑定选择器／对象、数据策略、模式和效果上限 | 预览本地零外呼；接受后在统一准入内执行 |
| Draft／ConfirmationService | 对话／表单共用草稿与差异预览，保存选定部分 | 角色、允许、必要和例外分别确认；旧预览不能操作新对象 |
| GuidanceCatalog | 从结构化状态挑少量起点与下一步 | 本地、版本化；不额外调用模型生成欢迎短语 |

规划若用模型，同样需要已选模型模式、外发投影、共享额度和有界执行；规则模式首句即生效。模型缺失／未选择时仍支持明确ID、辅助选择、人工资料和规则路径。已配置启用但上游未验证时，允许在既有授权内尝试，不把未验证一律当禁用。

## 2. 意图状态与衔接

| 状态 | 服务端产物 | 客户可见行为 |
| --- | --- | --- |
| intent_draft | 原话、有限动作、选择器、字段来源及未解析项 | 显示当前目标，保留合法信息；不用先选快照 |
| needs_clarification | intent修订、候选／目录版本、影响执行的缺项 | 显示名称、地域、类型、稳定ID、归属来源与时点，等待选择 |
| needs_discovery | 有限地域／类型／名称或ID条件及发现效果 | 说明尚无足够目录，可接受有限准备；未接受零云读取 |
| ready_for_confirmation | 对象或有界选择器、分区、数据策略、模式、缺口、效果上限 | 一张业务计划预览，不展示原始JSON或要求填HTTP次数／绝对截止日期 |
| accepted | 接受事件、冻结请求、幂等计划与排队任务 | 显式按钮或自然确认原子消费原plan／intent revision；重复确认不新建job，自动推进，不逐阶段弹确认 |
| needs_batch | 保留完整有限集合、当前单批保护及缺项 | 可以收窄或明确按完整集合分批；不截前N，提示只预填，仍需发送并接受新计划 |
| stale／cancelled | 失效原因、旧修订及新草稿引用 | 保留历史，重新核对受影响部分；不重放旧执行 |

目录缺失时，用户可接受“有限发现＋唯一匹配后准备审计”的整体效果。发现结果唯一且符合原条件才继续；多个候选结束发现执行并留下持久澄清，不让任务长期占槽等人。选择候选后在原上限内生成新的明确计划；不得自动扩大对象或选第一条。目录未知、权限不足、漏页、可信空集分别表达。

新明确ID／地域／类型优先于冲突旧上下文；例如原目标杭州，后来明确选择北京ID，Resolver应指出地域变化并核对，不输出被杭州过滤出来的“完整空集”。未知客户名不创建租户或猜标签归属。范围改动使不兼容执行预览与业务草稿预览失效；旧任务／固定报告仍可打开。指定A报告后复审从A的原对象与分区构造新计划，不借当前B目标；固定pinned目标的草稿亦不因后来的别任务而丢失。

## 3. 业务资料与上下文绑定

业务确认键至少包括对象集合／服务、规范分区／方向、基版本及草稿修订。单资产已确认来源不能带给整个组；批量／移除成员／换网关均重新核适用性。可复用已确认且仍匹配的字段，冲突并列复核，不重复问全部已知信息，也不静默覆盖。

| 用户表达 | 处理 |
| --- | --- |
| 接受候选／修改为多个服务 | 更新角色草稿，列证据和差异后确认；每服务可有独立访问要求 |
| 拒绝新候选／不知道 | 拒绝是事件，保留旧确认；未知字段不抹掉同句明确给出的角色／必要访问 |
| 确认Web服务、HTTPS必须保留、管理来源未知 | 分别生成角色／必要访问草稿；管理来源保持未知，不能整句被“未知”吞掉 |
| 禁止该服务所有所审访问 | 明确对象、方向、完整空集语义，预览后确认；空输入不等拒绝全部 |
| 忽略／暂缓 | 本地处理意见，需理由；不自动生成风险例外 |
| 明确风险例外 | 单独填写对象／服务、检查、适用范围、理由、授权来源和到期，校验有效再预览确认 |

事实自动读取有来源字段；模型候选不成为confirmed。必要访问与允许上界也分别确认，入向管理来源不反转成出向依赖。独立基线无需等待全部业务白名单，缺业务只影响对应比较。固定任务开始后新增业务资料产生新版本／关联审计，不回改旧结论。当前ConversationBusinessPanel与Inventory共用同一ProfileDraft，角色／访问分项显式选择，未选部分继续留稿；唯一同协议端口的未知服务可确认用途，已有冲突或多个候选须澄清，不静默复制服务或修改端口。可信归属由ConversationGroupPanel单独预览／确认来源限定的有限成员与授权说明；“未知”来源不能授信，普通标签不生效，组变更使未接受计划失效，已接受任务保留原组版本。

当前草稿冲突恢复已经有正式Web入口：读取同稿与current-base不改输入，差异逐字段默认不选；用户选择后才同稿双CAS重绑定／重新预览，不确认任何业务部分。原body/key可回放，旧回执和当前新修订分别标明；新服务与未选字段保留。未知保存不能通过CreateDraft绕过共用映射。

## 4. 客户状态与下一步

| 情境 | 界面表达与可执行下一步 |
| --- | --- |
| 空白／无连接 | 可保留目标、查看公开样例、导入人工资料；不在聊天收密钥 |
| 导入错误／不完整 | 逐项说明结构或版本错误、原目标仍在可重导；部分资料说明受影响检查，不伪装完整云观察 |
| 已有事实无业务 | 展示自动线索，接受／修改／拒绝／未知；可直接规则基线 |
| 已接受计划 | 当前对象／资料策略与阶段，已用时间、已得结果、取消；可返回后查看 |
| 模型慢／失败 | 已存规则可看，模型阶段状态与局限明确；用户可另发有界尝试 |
| 取消／中断 | 显示取消或中断及已得产物，不说审计已完成；重启不重放 |
| 受理答复未知 | 沿原请求标识查状态，同键核对；不换键重建 |
| 保存失败／冲突 | 保草稿、标未保存；成功才已保存，冲突重新核差异 |
| 历史／复审 | 明确选中报告，解释保持旧时点零云；“现在”查缓存资格，“刚改完”强刷 |
| 三会话／第四排队 | 按会话隔离显示，取消只影响本任务，共用累计额度；同会话冲突指向原任务 |
| 结果后 | 解释证据、补资料、记录本地待办／暂缓、导出、人工修改后复审 |
| 分批父任务 | 打开当前父任务的全部段／未处理集；各段分别审阅／打开报告与复审，不编造父级合并报告 |

上述正常缺项、等待和失败属于合理使用情境，不当作用户违规。受限输入另分：云写／越账号／超范围／未知API阻止对应效果，保留合法只读目标；无关问题给回主线短语，不创建伪审计；外部描述中的指令只是数据；识别到凭据时在保存／模型前阻断原值并给受控配置提示，不能承诺识别所有未知秘密。

## 5. 共用GuidanceCatalog

后端版本化条目至少有id、catalog_version、display_text、intent、behavior、required_refs、effects、state、missing_inputs。ResourceCatalog负责对象，GuidanceCatalog负责建议，分别版本化。建议文本不是系统指令或授权凭证。

| 条目 | 客户短语 | 行为／效果 |
| --- | --- | --- |
| GDE-01 | 从人工样例开始 | 本地导航，无模型／云 |
| GDE-02 | 看这些对象已有的资料 | 打开事实、时点与缺口 |
| GDE-03 | 帮我判断可能的用途 | 已有材料走获准模型；缺材料先预览准备效果 |
| GDE-04 | 用途未知，先检查基础风险 | 规则模式、明确数据策略 |
| GDE-05 | 解释这份旧报告的发现 | 无模型时导航原报告；模型分支核原A报告／producer／snapshot后选A并预填，发送先出零云解释提议，接受后才模型，绝不打开复审表单 |
| GDE-06 | 哪些判断还需要业务信息 | 本地缺项清单，按对象打开草稿 |
| GDE-07 | 只检查规则，不用模型 | 模式立即生效，是否读云另说明 |
| GDE-08 | 沿用这份资料检查 | pinned固定时点，零云 |
| GDE-09 | 我已人工修改，刷新后复审 | force_refresh＋fresh_after，可能云／模型，绝无云写 |
| GDE-10 | 继续历史会话和待办 | 本地历史，不重放 |
| GDE-11 | 连接不可用，先用离线资料 | 导入／人工路径 |
| GDE-12 | 看本次等待和用量 | 本地阶段与可得usage；未知不填0 |
| GDE-13 | 看这些资产的外部依赖 | 出向独立草稿，不复制入向来源 |
| GDE-14 | 检查一个NAT网关 | 名称／ID检索消歧；未知目录预览有限发现 |
| GDE-15 | 这条NAT结论缺什么 | 原发现缺项，不推演未知路径 |
| GDE-16 | 以此边界重新核查 | 新计划，不改旧报告 |
| GDE-BATCH | 按完整对象集准备串行分批计划 | 仅预填“按完整对象集分批审计”，发送后生成新计划，仍须明确接受 |
| GDE-BATCH-RESULTS | 查看各批段报告与未处理对象 | 导航原父任务，逐段选择报告，不伪造父级report_id |

fill_input只预填，navigate_local可直接打开，open_plan_preview只预览；用户明确发起才外呼，同一已接受效果内不逐HTTP再问。模型自由建议默认预填，结构化动作也须服务端既有schema校验，不能注册新工具或服务器。M1／MCP关闭不推荐依赖动作，云安全中心始终排除。

## 6. API与正式Web映射

GET `/api/v1/guidance`已注册并由正式对话与五视图共用，只读本地，带会话／surface／job／report上下文，返回版本化少量可用项和缺项原因；实际字段／路径由Go DTO生成规范。自然输入与建议产生同一意图schema，记录消息、目录版本、引用与用户动作。模型和云凭据不进入DTO；服务端生成authorization_origin，不信客户端自称已授权。

当前WorkspaceShell／ConversationWorkspace承载目标与追问、候选消歧和计划卡；ConversationBusinessPanel与Inventory共用草稿及差异，ConversationGroupPanel单独核可信归属；ConversationTaskStatus／PreparationResults／BatchResults显示固定任务、资料准备和逐段证据，Audits／Findings／Reports固定历史引用。五视图和对话复用状态服务，不维护两套确认版本。具体事件协议见[前端设计](frontend-and-events.md)，意图／确认字段见[数据设计](data-and-api.md)。

Web首屏为对话＋上下文，普通流程不暴露JSON、源码事件、私有endpoint或配额日历。未来CLI用编号／文本、TUI用键盘面板，也须展示同意图、范围、外部效果、取消和下一步；不要求像素一致，不复制后端逻辑。

模式否定和冲突澄清保留原对象／报告锚点，不以“不用模型”触发模型，也不把含当前／历史冲突的句子直接执行。复审改善只指严格可比的违规集合真子集，保留原fail与前后证据；原评估时点、新采集时点分列，NAT原始身份变化不可比。以上正式代码和限定人工浏览器结果仍不替代完整88分支formal验收或真实整改取证。

## 7. 验证与原型边界

RC-27～31继续覆盖本地空态、跨入口语义、失效上下文、刷新复审与历史幂等；本轮按最终J01～J24全部分支逐项核对实际输入、可见结果和下一步，而非仅检查编号存在。目标改动、同名、新ID、组变更、分项确认、多服务、例外、规则模式、慢云模型、取消／中断、历史选择、导入错误与受限输入均有交互出口。

[离线原型](../prototypes/audit-workflow/README.md)是人工状态机、内存资料，模拟事件和故障仅证明交互可观察；不证明正式Vue组件、真实模型、持久恢复或SSE。正式实现须从空白对话完成同等行为并执行接口／组件／持久回归；真实接入、人工整改与正式评价另行取证。CLI／TUI未交付时如实记录，不因共用目录宣称已通过终端测试。
