# 用户引导与入口设计

基线：需求v0.6／B2、设计v0.6，G1／G2已通过。本文为该领域的现行详细设计；实际运行验收另行取证。

## 1. 产品要求与交付边界

不能只提供一个空输入框让用户猜怎么用。每个交付的交互入口至少提供：首次进入说明与可选示例、当前上下文、推荐起点、结果后的下一步、失败／缺信息时的恢复入口。

首版 Web 落地为 M0；共用引导目录和跨入口契约也是设计必需。CLI／TUI 仍依既有范围是后续可选入口，不因本要求自动扩为完整终端产品；但一旦实现／交付，就必须实现同等业务引导，不得以“只显示 --help”代替相关情境的建议。已有 Go 实验 CLI 不是正式产品，本文不新增或承诺已可运行的产品命令。

## 2. 共用目录，不是三套业务提示词

后端维护版本化 `GuidanceCatalog`，前端／CLI／TUI 只决定呈现。目录定义可用场景、普通用户可理解的短语、意图、所需对象、动作效果、缺项与下一步；不能把短语当系统指令或绕过工具授权。

依据空间／会话、数据来源及年龄、连接／模型可用性、角色确认、当前任务／结果和 M1 开关筛选，默认只展示最相关的少量建议。空态和本地引导不调用模型或云 API。

| 状态 | 推荐内容 | 不应出现 |
| --- | --- | --- |
| 首次打开／无数据 | 从人工样例开始、选择离线输入、说明要做什么 | 默认扫描整个账号、要求把密钥贴聊天 |
| 已有快照／未确认画像 | 用已有线索判断用途、保留未知做基础检查 | 把候选当授权、重新询问全部已知事实 |
| 正在执行 | 当前阶段、已得结果、耗时／尝试及取消入口 | 伪造完成百分比、用新任务隐式重试 |
| 有结果 | 解释某发现、查看证据／待补项、采纳本地计划 | 自动修复、自动认定业务中断或合规 |
| 续聊／重开历史 | 接着上次会话、解释指定报告、核对资料时点 | 把旧模型答复当当前事实或重放请求 |
| 数据陈旧／人工已变更 | 看时点影响、选择刷新后复审 | 把陈旧缓存当最新、默认每次全量收集 |
| 模型／连接不可用 | 人工标注、离线／规则路径、查看配置状态 | 提示切到全局账号或安装云安全中心 |

## 3. 首批目录提案

这些是产品普通输入／动作示例，不是当前 shell 命令。具体资产／会话引用由后端从已授权上下文补齐，不能把厂商凭据、私有端点或其他会话内容插入短语。

| 编号 | 推荐短语／动作文字 | 意图与默认行为 | 外部效果 |
| --- | --- | --- | --- |
| GDE-01 | 从人工样例开始了解审计流程 | 导航到内置样例选择 | 仅本地，无云／模型 |
| GDE-02 | 先看看这些资产已有的信息 | 打开当前快照事实／缺口 | 仅本地 |
| GDE-03 | 帮我判断这些资产可能是什么用途 | 预填画像引导输入，补齐范围后发起助手轮次 | 仅模型与固定资料；需要云数据时另开采集预览 |
| GDE-04 | 用途还不确定，先检查基础风险 | 预览适用基线、未知项与数据策略 | 数据策略可能读云；模型默认不必调用 |
| GDE-05 | 解释上次审计中的这条发现 | 绑定历史发现／报告，普通追问 | 可能模型，不默认刷新云 |
| GDE-06 | 哪些建议还需要我补充业务信息 | 打开待确认清单，必要时引导追问 | 先本地，不为生成清单额外调模型 |
| GDE-07 | 只运行规则，暂不调用模型 | 预览规则审计与数据策略 | 不调模型；是否读云明确展示 |
| GDE-08 | 沿用这份快照复验，不刷新云数据 | 固定快照／时点，选择解释模式 | 不刷新云，模型依选定模式 |
| GDE-09 | 我已手动改了策略，刷新数据并复审 | 打开范围／fresh_after／预算预览，再新建复审 | 明确云读取，模型依模式，无云写 |
| GDE-10 | 继续这个会话，看看前次待办 | 打开历史消息／本地处理记录 | 仅本地，不重放模型 |
| GDE-11 | 连接暂不可用，先用离线数据 | 打开离线入口或手工资料 | 不自动检查所有账号或获取凭据 |
| GDE-12 | 查看本次耗时和已用调用次数 | 打开阶段／尝试／可得用量 | 仅本地；缺失用量不填零 |

模型可在当前回答中建议后续追问，但必须与代码目录区分来源。来自模型的自由短语默认只填入普通输入框；若带结构化动作，只允许后端既有意图、范围和参数 schema，不因模型输出而注册新工具／连接／权限。

## 4. Web、CLI 与 TUI 的不同表现

| 入口 | 首次／空态 | 有上下文后的引导 | 用户动作边界 |
| --- | --- | --- | --- |
| Web | 短说明、样例入口、3～5 个推荐卡片／快捷短语 | 在画像、结果、历史和失败区显示相关追问，当前来源／会话可见 | 普通短语先填输入；需外部调用的动作进入明确预览；本地导航可直接打开 |
| CLI（未来产品入口） | 命令帮助／交互欢迎提供场景例子、当前会话和数据范围 | 单次输出后给 2～3 个相关下一步／可复制短语，结构化模式保留同类元数据 | 编号或短语选择不等于默许全部账号／刷新；非交互调用也须显式范围／数据策略 |
| TUI（未来产品入口） | 欢迎面板、键盘可选建议、上下文摘要 | 状态栏／侧栏展示会话、来源年龄、阶段；结果页相关下一步 | 键盘选择填入或打开预览，不用默认 Enter 触发未说明的付费／采集 |

不追求三个入口像素一致，也不为后续 TUI 复制后端业务逻辑。终端不支持卡片时用编号、状态和简洁说明，仍必须能识别下一步、作用范围、是否调用模型／云以及如何取消。

## 5. 建议不是隐式执行许可

- `fill_input`：填入普通短语，用户发送后按正常业务规则处理；不是高优先级系统提示词。
- `navigate_local`：仅打开本地样例、事实、历史或帮助，无外部调用。
- `open_plan_preview`：刷新／审计等显示范围、数据策略、模型模式、预算和缺项；用户明确发起后才执行。同任务内不逐 HTTP 请求反复询问。
- 若缺连接验证、外发授权、资产范围、业务确认或预算，提示缺少什么并给离线／人工路径，不后台探测其他账号来填齐。
- M1／MCP 关闭时不推荐依赖它们的动作，云安全中心始终排除；不存在“全面合规”或“自动购买／下发”短语。

## 6. 数据与 API 契约

设计新增本地查询 `GET /api/v1/guidance`，带当前会话／视图和 `surface=web|cli|tui`；它只读本地状态，不能因渲染建议获取 STS、采集云数据或调用模型。返回少量可用项和缺项原因，仍受本地应用访问保护。

```json
{
  "id": "GDE-09",
  "catalog_version": "guidance_v1",
  "display_text": "我已手动改了策略，刷新数据并复审",
  "intent": "recheck_after_manual_change",
  "behavior": "open_plan_preview",
  "effects": {"cloud_read": "after_explicit_start", "model": "by_mode", "cloud_write": false},
  "required_refs": ["conversation_id", "baseline_job_id", "target_scope"],
  "state": "needs_input",
  "missing_inputs": ["fresh_after"]
}
```

发送／动作请求记录建议 ID、目录版本、解析后的引用与业务意图、用户动作和幂等键，便于历史重现“从哪个建议开始”。模板变量是数据，转义显示；没有上下文的变量不能凭模型猜测补全。新开页面／换入口使用同一会话与状态，不重新收费或清预算。

## 7. 验收提案

| 案例 | 预期 |
| --- | --- |
| RC-27 首次／无配置／无数据 | Web 与已实现的终端入口有本地起点／示例，不触发云／模型，不要求聊天填写凭据 |
| RC-28 跨入口语义 | 同一建议 ID 在 Web 卡片、CLI 文本／TUI 编号中产生相同意图和确认范围，表现可以不同 |
| RC-29 失效上下文／能力 | 过期快照、无权引用、M1 关闭、模型缺失、预算耗尽给明确下一步，不推荐无法执行或越权动作 |
| RC-30 刷新复审建议 | 打开数据策略／scope／fresh_after 预览，不直接云写，不自动用旧数据声称当前修复 |
| RC-31 历史／重试 | 建议来源入历史、重复提交幂等、重开会话不重放调用；未确认短语不改变授权 |

首版验收包含共用目录／DTO 和 Web 流程；CLI／TUI 尚未实现时记录“未交付”，不冒称其交互测试通过。未来实现任一入口必须执行相关同义契约和交互检查。现有低保真仅作此前流程样例，尚未实现本目录、连续会话或真实 API。

## 8. B2 的上下文推荐与正式 Web 对接

| 编号 | 建议文字／意图 | 需要的上下文 | 行为与禁止项 |
| --- | --- | --- | --- |
| GDE-13 | 看看这些资产的外部访问要求 | internet/out 或已选 NAT scope、资产／服务引用 | 打开 IntentEditor 的出向分支；不把管理来源字段或历史流量填成已批准目标 |
| GDE-14 | 选择一个 NAT 网关预览审计 | 当前来源的本地 scope 目录／能力状态 | 打开 ScopePicker；目录未知时给显式连接／采集入口，不自动扫描账号 |
| GDE-15 | 这条 NAT 结果还缺哪些关联证据 | 固定发现／网关／snapshot 引用 | 本地缺口清单或受限历史解释；不主动读取转换表、推演路径或换账号 |
| GDE-16 | 按这个边界准备一次新的复审 | 历史报告、稳定 scope 键、资料时点 | 创建本地 execution-plan 预览；明确效果上限后用户另行启动，不立即消费模型额度 |

GuidanceCatalog 继续由后端维护，目录版本随 B2 升级；模型不能注册新意图或自行将建议升级成执行。点击只导航／预填，计划必须对 scope、对象、数据策略、模式、外发和配置版本进行服务端核对。

正式 Vue 页面用共享 ScopePicker、GuidanceChips、AuditPlanPanel 和 ConversationDrawer；跨入口使用相同意图与稳定引用，不把可见文字当授权凭据。未来 CLI／TUI 若交付，必须等价显示 NAT 网关、零外呼／可能刷新、缺口和确认边界，不用后台自动扫描替代预览。

页面内正常切换边界只改变当前视图／草稿；原任务和证据不变。带未保存授权草稿时提示保留／丢弃，不能自动把入向草稿变成出向允许集合。

对应 B2-15／18 与 AC-14／20；现有 B2 业务流程不变，本方案按用户确认同步调整原型视觉与内存订阅情境，不生成正式组件。

## 9. 正式前端的状态一致性（RV4-03／04／10）

- 保存意见／计划先显示保存中；只有服务端持久成功才显示已保存。冲突展示新旧修订，网络响应未知允许原幂等键核对／重试，不能自动换键重复创建。失败保留草稿，并标未保存，不让刷新掩盖失败。
- 普通助手发送按钮明确标出将使用模型、当前 scope 与资料；用户明确发送才进入内部计划，推荐词点击不收费。没有有效资料时引导选择／采集，不偷偷刷新云。
- 入向、出向、NAT 及 asset／gateway 模式由统一 ScopePicker 呈现；collect 的地域发现不是 audit 的空资产列表。输入模式不适用时显示字段错误，不自动切全账号。
- 只对固定本地输入运行规则、读取历史、补人工资料、保存审阅、生成报告均保持可用；模型／连接故障不让这些入口整体失效。
- imported_assumption 的结果始终带“导入声明条件下”提示，不能把条件 pass 变成当前云账号安全；信息缺口、未运行与不支持各自展示。
- 真实环境准备、人工修改及还原／清理的页面文案仅是操作说明／记录，不提供系统云写按钮。案例数不显示成建议创建的 ECS 数。

界面按这些状态建立正式组件用例；原型 v0.3 只映射视觉与模拟连接状态，不把新旧原型回归作为正式 Vue／Nuxt UI／Tailwind 或真实 SSE 的通过证据。

## 10. 前端与连接引导

Web 使用 Vue/Vite/Router＋Nuxt UI v4／Tailwind v4 映射现有五视图，保留同一引导目录和明确发送边界。连接中断时建议“恢复实时更新／查看已得结果”，不是“重新运行”；恢复 SSE 或轮询只恢复只读订阅。Nuxt UI 的聊天控件不直接对接云／模型，不新增模板自带 /api/chat 或 AI SDK 服务端。组件／网络状态映射见 [前端与事件](frontend-and-events.md)，CLI／TUI 的未来复用边界不变。

## 11. 并发、存储错误与下一步

3个不同会话可同时推进，各自显示running／阶段／事件与累计等待；同会话新任务冲突指向现有执行，不推荐自动取消。第4个任务明确queued，取消只针对当前job。STORAGE_BUSY／STORAGE_UNAVAILABLE保留草稿／原幂等键并先查受理状态，不能以新键自动重提收费请求；SSE断线仍不等于任务取消。接口文档与事件schema共同约束这些错误与恢复行为，见[总体架构](architecture.md)。
