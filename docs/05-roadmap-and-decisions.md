| 阶段 | 主要工作 | 完成标志 |

## 4. 下一轮优先讨论

本轮先补足真实技术背景，不推进论文大纲。后续按以下顺序收敛：

1. 审阅语言、框架、TUI 两种运行方式和云 API 分层建议，区分用户偏好与待确认方案。
2. 模拟模型的 Go + Eino 工具循环、证据、事件、预算与错误处理已验证，见 [验证记录](09-offline-validation-record.md)；后续需接入实际模型服务验证自主工具选择和协议能力，关键阻碍出现时再比较 Python。
3. 根据官方字段和一个明确业务案例确定必需/可选采集项；真实账号验证需授权，不为文档调研提前开通资源。
4. 再确认首版边界、技术栈和规则支持矩阵；通过后同步需求、架构和实验方案。

论文仍是项目目标；这里只是按用户要求先补技术前提，后续开题与正文写作时序待学校要求明确后安排。
