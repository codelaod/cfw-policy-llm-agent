## 3. 批准、实现与外部操作分开

G1／G2不再是未决事项。E0～E5的入口／退出条件见[实施计划](../development/implementation-plan.md)；依赖构建、真实SSE、SQLite／并发、模型能力、账号接口、性能及整改复审仍未取得正式运行验收证据。

真实模型／云请求须有明确的数据、账号／资源、权限和预算；设计通过不自动采购、开通产品、增加云写或执行清理。此前一次普通推送和一次累计设计本地提交已完成，不能重复消费。2026-10-27用户明确授权将当前文档治理结果提交并普通推送一轮；仅本次，不强推、不改历史，完成后不重复消费。实际发布结果以Git记录为准。

## 4. 文档维护原则

当前项目采用按职责分类的一份正文，不再新增“第N轮review”作为主入口。修订结论直接落实到对应需求／设计；跨文档的阶段结果只更新此决策页，待执行事项列入实施或验证计划，实际结果保存在证据区。

本轮目录治理合并了重复G2审核包、设计增补和自审过程；接口／并发内容进入正式设计，DFX进入验证计划；论文修订记录压缩为一份维护说明。旧过程统一由Git追溯，不将review重新堆入archive，也不额外保存批准文档副本。
