# 首版出向／NAT 范围复审与原型 v0.2

日期：2026-10-26。状态：**用户已明确确认需求，CR-1 纳入需求 v0.6／B2；继承 B1，设计 G2 仍未通过。**

本轮用户提出两点：仅审互联网入向可能不足以体现防火墙业务；原型信息混乱且视觉粗糙，不能直接沿用为正式前端。本文记录范围建议、联动影响、设计辅助方案和原型改进。不是云接入、模型或审计效果验收。

## 1. 已确认范围：扩展有限闭环，而不是全网络矩阵

用户本轮确认后，首版从“只有互联网入向”调整为**互联网入向＋有限互联网出向＋有限 NAT 边界 ACL**。不引入跨云、跨 VPC／路由／安全组的全路径矩阵。

| 对象 | 已确认的首版需求深度（B2） | 明确排除 |
| --- | --- | --- |
| 互联网入向 | 保留现有 B1 有限语义、规则和确认流程 | 不扩大到所有应用／动态对象 |
| 互联网出向 | 按本机资产→外部依赖建模；有限 IPv4、协议／目标端口、启用状态、动作、顺序、静态引用和默认行为；在证据充分时核对明确必要访问、允许目标范围、精确重复配置 | 不把全网出向自动判成违规；不复用入向管理来源白名单；不从历史访问生成授权；不增加恶意域名库或全量流量平台 |
| NAT 边界访问控制 | 单账号、有限地域／指定网关；按 NAT 防火墙／网关独立分组，检查本层 ACL、覆盖状态、资产关联与证据完整性；离线与真实采集分别验收 | 不把 NAT ACL 与互联网 ACL 混排；不跨网关比较规则顺序；不把未采集关联当成没有 NAT |
| SNAT／DNAT 转换条目 | 与 ACL 分开。首版仅展示显式提供、可定位的关联上下文及未知状态；是否补充最小只读采集由 G2 细化 | 不承诺完整转换模拟、自动发现全部映射、端口映射安全规则或转换后端到端可达性；如用户希望这些成为主功能，需单独确认工作量与接口范围 |
| VPC／跨云／复杂路径 | 继续明确显示不支持或未覆盖 | 不建立全网络可达矩阵，不自动下发策略／切路由／开防火墙 |

**为什么这样分：**互联网策略接口公开支持 `Direction=in/out`，出向不是需要另造一个完整平台的业务；但流量发起方和接收方、明确依赖、返回流量边界都需要单独定义。阿里云 NAT 边界 ACL 管控私网资源经 NAT 网关访问公网的出向流量，与网关的地址转换配置不是一个对象。依据见 S-01／S-02；目标账号的具体产品版本、地址观察位置、授权与分页仍待验证。

“有来源支持”不等于“本项目已实现”。本轮没有授权或调用真实云接口、开通 NAT 产品、修改网关／路由，也没有新增模型调用。公开资料中的不同 NAT 版本／历史限制不直接套用到用户账号，不声称所有版本均支持或均不支持 DNAT。

## 3. 自动辅助设计方案与本轮选择

这里区分三个问题：**设计方法**、**可编辑设计稿／远程生成**、**实际浏览器验证**。安装 skill 不等于获得额外模型，也不自动接通 MCP 账号。没有可靠依据把某一项称为“最好用”；公开维护来源、采用信号、是否适合本项目和权限成本比“插件越多越好”更重要。

截至 2026-10-26，通过 GitHub 公共 API 核对：Anthropic skills 仓库 183,842 stars，Vercel agent-skills 33,031，OpenAI skills 28,310。**这是整个仓库的关注量，不是单个 skill 的用户数、下载量、满意度或客观效果评分。**

| 方案 | 作用与限制 | 本轮处理 |
| --- | --- | --- |
| Anthropic `frontend-design` | 从业务主题出发制定布局、排版、色彩和设计令牌；避免模板化页面。属于指令型 skill，不提供额外云模型额度 | 已按固定提交安装，阅读并采用先设计、后制作、再截图复核的方法 |
| Vercel `web-design-guidelines` | 检查语义、可访问性、表单、响应式和交互细节；不是视觉生成器，也不要求采用 React | 已按固定提交安装，读取官方清单用于本原型审查 |
| OpenAI `playwright` skill＋Playwright CLI | 实际打开页面、操作、检查结构、截图；不是画图工具 | 已按固定提交安装；本地 Chromium 及所缺库仅缓存／解压到 `/tmp`，未安装系统服务 |
| Figma 官方 MCP／客户端插件 | 官方已提供读取设计上下文及写入画布等工作流，适合需要可编辑设计源文件与协作的阶段；需要用户账号授权及适配的客户端 | 核对官方文档，未自动登录、授权或上传项目；不把“已安装本地 skill”冒充 MCP 已连接 |
| Google Stitch MCP＋Google Labs skills | 适合从设计描述探索屏幕方案，Google Labs 仓库有配套 skills，但声明并非 Google 正式支持产品；属于远程服务工作流，配置与授权需单独确认 | 列为后续备选，未配置凭据、未发起远程生成、未上传私有数据 |

本轮不接入不明来源的 GPT 插件，不为了原型更漂亮切换正式前端技术栈，也不把生成截图代替可交互原型。后续如需要 Figma 可编辑源稿，可在确认账号与上传范围后再接官方方案。

## 4. 原型 v0.2 的改进与限制

- 左侧导航和工作台建立定位，不把五个工作区挤成一排操作按钮。
- 每页有清楚的目的和主操作；证据、候选、用户确认、执行过程、处理计划分层展示。
- “载入样例”“预览范围”“启动模拟”是不同动作，查看建议不会隐式执行。
- 使用统一留白、排版、状态颜色和控件；详细设计依据见 [DESIGN.md](prototypes/audit-workflow/DESIGN.md)。
- 发现采用列表＋证据详情，报告用可读版面；调试信息不占据主界面。
- 有空态、确认预览、修改失效保护、暂缓原因、部分完成、取消保留结果和旧版本提醒。
- 新增出向与 NAT 的固定人工样例，标明需求已确认但尚未实现；不同边界与任务独立，不以原型结论证明规则实现。
- 保持离线、零外部请求和页面内存状态。连续会话持久化、真实 Agent、云采集、SNAT／DNAT 模拟仍未实现。

**正式前端的约束：**不能把旧低保真或本 HTML 原封不动当最终前端。G2 应同时审核设计令牌、主页面、典型空态／错误态与键盘／窄屏行为；正式组件、数据契约与构建在 G2 后实现。
