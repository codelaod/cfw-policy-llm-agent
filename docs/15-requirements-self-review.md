# 需求 v0.3 作者自审记录（历史阶段）

本记录保留 v0.3 时点的自审和 31 项资料检查；最新阶段为 [交叉审核／B0](17-requirements-cross-review-and-design-baseline.md) 后的 P2，系统设计待 G2。下文“当前 G1”等指当时状态，不作最新任务指令。

日期：2026-10-22。对象：需求主文档、领域需求、业务价值与画像、规则目录、PRD／离线原型及其引用／交接文档。

**性质：同一作者完成的需求自审，不是独立专家评审、用户批准、业务测试或真实云验证。当前仍停在 G1，需求和系统设计均未建立批准基线。**

## 1. 审查方法

1. 按用户本轮四项要求核对内容是否进入需求，而非仅停留在调研笔记。
2. 对产品事实、指南原则、厂商控制、项目政策和业务授权分别核对来源与结论强度。
3. 用三台 VM、同机多角色、未知角色、缺少白名单、防护状态未知、观察模式和日志缺段进行文档级场景推演；这些不是执行测试。
4. 检查功能、领域判据、优先级、可选范围与验收的追溯关系，复核历史文档的版本／下一任务。
5. 运行文档链接、编号、引用清单和格式检查；不运行模型、云接口或尚不存在的业务测试。

## 2. 审查发现与文档修正

| 编号 | 问题／风险 | 修正与当前结论 |
| --- | --- | --- |
| RV-01 | 原需求缺少正式价值论证，容易误写为“首次 AI 推荐” | 补充产品／AI 背景和可验证价值目标；明确不替代完整安全平台、不提前声称收益 |
| RV-02 | 仅有检查项名称，难以实现或约束模型 | CHK-01～12 逐条给依据、前提、逻辑、例外、输出和边界；先区分 M0／M1，版本和 schema 在批准设计中落实 |
| RV-03 | 无白名单时所有审计都停住，与基础安全价值冲突 | 拆分安全基线和业务一致性；CHK-07 可独立运行，CHK-01 等继续待确认，不编造来源 |
| RV-04 | 普通标签／安全组端口／历史流量可能被当成数据库角色或授权 | 技术线索、角色和授权分开；加入人工／受信映射确认、对话草稿预览、未知和冲突处理 |
| RV-05 | 一台主机只能单角色，容易误封同机 Web | 角色关联具体服务，允许多角色；同机必要访问纳入 RC-04 |
| RV-06 | “未防护”可能被夸大为所有组件不存在或从未保护 | CHK-05 仅判当前该层覆盖，其他层未知不等于缺失；组件建议分适用性、证实缺口和未知 |
| RV-07 | 推荐默认购买全部安全产品，脱离工作量和产品条件 | 给分层条件清单，区分 Web／数据库，不默认开资源或接入所有产品 API；费用不作未核实承诺 |
| RV-08 | IPS 观察模式被误当未检测，可能直接开启拦截 | 按检测／拦截目标分别比较，说明误拦截、业务验证及人工决策；精确状态检查为 M1 |
| RV-09 | 日志零记录可能被当无攻击、未开启或规则无用 | 新增类型、窗口、覆盖／缺段、低频与例外边界；零命中仅复核，M1 不自动删规则 |
| RV-10 | ACL／IPS 标识、历史配置版本或 NAT 位置可能错误关联 | 日志输入记录映射与时间，无法对应时降级；记录数不冒充独立连接或攻击数 |
| RV-11 | 其他云控制或 NIST 原则被当成本产品完整规则／合规认证 | 保留原始控制主题和条目层级，按阿里云顺序／默认放行重定义；端口表明确是项目子集 |
| RV-12 | 新增画像、组件和日志改变范围，但未同步验收／交接 | 补 FR-12～14、NFR-08、DR-09～12、AC-11～13、RC-01～10；Q7／Q8 单列范围；仍须两次用户审核 |
| RV-13 | 优先级含义混杂或按模型自报置信度排序 | 分离 M0／M1 实现范围、风险严重程度、R1～R3 整改顺序及 V0 核实；不虚构 SLA |
| RV-14 | 规则输出的 CFW 有效允许被读成真实端到端可达 | 保留保护状态／语义前提和本层结论边界；推荐不自动添加全局拒绝，云／业务实际效果另验收 |
| RV-15 | 候选资料入口不匹配或混同产品能力 | 原有入口／日志能力修正保留；v0.3 已移除 A-23 资料及接入依赖，新增 ECS／安全组／必要网卡的公开 API 核读；不将文档可读当账号验收 |
| RV-16 | 轻量方案仍有额外安全产品／客户端依赖 | 从方案、角色来源、候选摘要和主机防护建议中移除云安全中心；索引编号停用，当前只用 ECS／安全组／必要网卡线索 |
| RV-17 | 自动取得的字段与推断结果混同，忽略共享组／策略条件 | 补三份 API 核读摘要和输入映射，模型只据关联配置提出候选／限制；不证明服务监听、可达性或授权 |
| RV-18 | 系统功能有清单但缺少实际使用路径 | 增加 PRD：五视图、八条端到端流程、确认／拒绝／未知／失败、审阅与复审；用 UX-01～08 映射 FR／AC |
| RV-19 | 资料补充可能原地篡改旧任务，或形成无限挂起会话 | 原任务固定输入版本，补信息后新建审计／复审；缺信息输出待确认，不要求长时间等待恢复工作流 |
| RV-20 | 方向认可被错误当需求整体批准 | 登记用户认可的方向与排除边界；PRD 细节和完整 G1 仍待审核，正式设计／业务实现未启动 |
| RV-21 | 可点击原型被误当正式前端／模型验证 | 人工数据、固定候选和报告均显式标注；无外部网络；补初始无数据空态，关联缺失时不归因其他组端口；仅用 Node 最小 DOM 做状态检查，不声称浏览器视觉／业务规则／AI 测试通过 |

上表“修正”指文档约束已补齐，不表示相关代码、安全控制或实验已经通过。
