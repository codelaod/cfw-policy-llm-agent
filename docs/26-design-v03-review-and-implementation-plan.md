## 2. 本轮解决的设计缺口

| 缺口／风险 | v0.3 处理 | 仍未证明的事项 |
| --- | --- | --- |
| 三种边界共用 ACL ID 导致混排／错证据 | 规范分区键；一次任务一个边界／方向，NAT 一个网关；所有规则、引用、报告均绑定分区 | 真实接口的账号／网关一致性 |
| NAT API 名与版本未核实 | 核读当前两个 Describe 接口及官方 v11 SDK；移除两个未经核实的候选名与“废弃”断言 | SDK 项目构建、真实账号可用性 |
| 分页字段看起来一样就共用解析 | NAT 元数据整数分页／总数；NAT ACL 字符串分页／总数，集合 `Policys`；不同适配器 | 实际返回 nil／缺字段／限额等 fixture |
| StrictMode 被误解为默认 drop | 默认动作与语义依据独立记录；相关高级条件降级 | 目标产品 profile 和控制面状态实测 |
| 只复用旧快照却没有分区／配置族条件 | scope-aware 缓存键，配置族整体复用／两轮观察一致性，保留原时点 | 请求账本、取消和并发缓存实测 |
| 前端可能直接沿用原型 HTML | Vue／TS／Vite＋Vue Router＋Element Plus 的正式组件建议；原型仅作版式／行为参考 | 依赖构建、真实组件布局／可访问性 |
| SDK context 只能猜测 | 已核对 `WithContext → CallApiWithCtx` 源码路线 | 真正超时、底层取消、SDK／凭据重试计数 |
| 需求通过被误当作架构或业务已通过 | B2／G2／实现验收分开，公开资料、静态校验和未来业务测试分开记录 | G2 用户确认及后续各层验收 |

## 3. G2 需要确认的六项技术取舍

| 编号 | 推荐取舍 | 如不采用的影响 |
| --- | --- | --- |
| G2-01 技术组合 | Go＋Gin＋Eino；Vue／TS／Vite＋Vue Router＋Element Plus；SQLite 纯 Go，GORM 适配先过门槛，不满足退直接 modernc | 替代组件／驱动需调整工作量和验证，不能退回 CGO |
| G2-02 任务范围 | 同一会话可多任务，但每任务一个分区；NAT 一次一个网关，支持显式网关策略集或有证据的资产子集 | 跨分区任务会增加预算分摊、部分结果和复审复杂度，不建议首版做 |
| G2-03 语义子集 | IPv4、TCP／UDP、字面／完整静态引用；保持模式、默认、顺序、状态与未知边界 | 不支持的 L7、动态引用、完整转换／路径保持显式排除，不静默简化 |
| G2-04 数据与费用控制 | 本地计划预览＋显式执行；按分区复用配置族，刷新最多两轮；沿用根 360 秒／执行 240 秒及原请求上限 | 如实测不足，应缩小规模或经用户调整预算，不自行提高 |
| G2-05 本地部署与安全 | loopback、同源、最小应用口令、显式 CredentialProvider、只读 RAM 与工具投影；不把 UI 变成密钥控制台 | 对外部署需另审 TLS／代理／认证，不直接公开本地演示方案 |
| G2-06 验证顺序 | 先纯 Go 存储／协议／契约，再离线业务闭环，最后在独立授权内做真实模型与只读云验收 | 不能用人工原型或公开 API 文档替代真实集成；真实条件不足须保留未验收记录 |

这些是本轮推荐的技术方案，**不是请求用户批准立即付费调用**。G2 通过后才能建立正式工程；真实调用仍遵循数据、权限和预算授权。

## 4. B2 专项验证矩阵（计划，尚未执行业务测试）

| 编号 | 场景／预设条件 | 预期与验证层 | 需求追溯 |
| --- | --- | --- | --- |
| B2-01 | 同一 ACL ID 出现在入向、出向和两个 NAT 网关 | 归一化／查询／证据不混用；单元＋契约 | CR-1-F02／04、AC-03 |
| B2-02 | NAT 返回网关不符，或存在未核实的成员账号 | 封存失败／范围拒绝，不自动换身份；适配器模拟 | CR-1-F02、AC-09／18 |
| B2-03 | 资产模式空列表；显式网关策略集无资产列表 | 前者 422，后者只执行适用网关检查，不扩全账号；API 契约 | CR-1-F02／04 |
| B2-04 | 出向允许上界完整且已确认，策略额外放行目标范围 | OUT-01 报确定的差集及条件，不使用入向来源；纯规则 | CR-1-F01、AC-05 |
| B2-05 | 宽泛出向但无完整依赖要求 | 待确认，不生成虚构白名单或确定性业务违规；纯规则＋Agent 负例 | CR-1-F01、AC-04 |
| B2-06 | 明确必要外联在完整本层语义下被拒绝 | OUT-02 报本层差异，不宣称实际网络故障；纯规则 | CR-1-F01、AC-05 |
| B2-07 | StrictMode=1，但默认动作依据未核实；查询未命中 | unknown／信息不足，不由严格模式推导 drop；纯规则 | CR-1-F02、AC-05 |
| B2-08 | 潜在匹配的 L7／观察／动态条件位于前序 | 超出支持时不得跳过后报告允许；明确无关者不牵连；纯规则 | AC-05、NFR-02 |
| B2-09 | TotalCount 字符串非法、漏页、重复页或空页矛盾 | 不完整而非空列表／通过；适配器 fixture | AC-02、CR-1-F02 |
| B2-10 | 同 VPC／私网 IP 存在，但资产与网关／观察点缺证据 | NAT-01 信息不足；网关静态检查可独立；规则＋证据 | CR-1-F03 |
| B2-11 | 将入向快照复用于出向，或用网关 A 缓存给 B | 拒绝匹配，不能自动 widening；缓存契约 | CR-1-F04、AC-16 |
| B2-12 | 两轮配置语义指纹不同／第二轮预算耗尽 | 标 changed／unverified，受影响路径检查不通过；采集模拟 | AC-02／16／17 |
| B2-13 | NAT closed／normal／transition／unknown | 只报告当前层状态；unknown 不是未部署；规则＋适配器 | AC-12、CR-1-F02 |
| B2-14 | 复审边界／网关／观察点／语义版本不同或对象缺失 | 不直接计算已修复，旧报告不改写；报告契约 | CR-1-F04、AC-10 |
| B2-15 | 计划过期、连接配置改变、确认内容改变、双击启动 | 409 重新预览；同键同内容只建一次，无隐式外呼；API／事务 | AC-07、CR-1-F04 |
| B2-16 | 认证＋两轮分页＋退避＋模型链超过次数／时间 | 停止后续请求，保留已落地结果；WithContext／HTTP 计数模拟 | AC-17／18 |
| B2-17 | 工具读跨网关引用、伪造 evidence_id、跨 scope 摘要外泄、外部描述注入指令 | 上下文／摘要与工具均按 scope／版本／字段拒绝；无写工具；Agent 模拟 | AC-06／07／09 |
| B2-18 | 正式 Web 边界切换、历史恢复、缺数据／模型、导出与预览 | 统一组件／状态；缺口与业务未知不混为通过；产品验收 | AC-14／15／20 |

纯规则基线、固定模型流程和 Agent 比较必须使用相同的分区、输入与规则版本。各边界和可确定／待确认／信息不足分别报告，不把只测入向的结果冒充 NAT 效果。矩阵中的预期是预先声明的验收标准，不是本轮运行结果。

## 5. G2 后的工程顺序与退出条件

| 阶段 | 工作与范围 | 退出条件；失败时怎么办 |
| --- | --- | --- |
| E0 依赖与契约门槛 | 独立验证 Go／Eino／Gin、GORM 纯 Go 驱动、Vue／Element Plus 兼容；锁版本；无云／模型请求 | `CGO_ENABLED=0` 构建、foreign_keys／false／空集合／条件更新／事务回滚／重启通过；驱动不满足退直接 modernc，不能默认 CGO |
| E1 核心领域与输入 | 分区身份、有界导入、证据、三值内核、版本化规则／业务要求；固定人工样例 | 原有 DC／RC 加 B2-01～14；小全集参考穷举与区间算法一致；不需要模型或真实云 |
| E2 持久服务与 Web | 会话／消息／确认、任务／计划、API、统一 UI 组件、阶段结果和报告 | 幂等、重启、空态／错误态、跨边界隔离与原型行为追溯；不是只做聊天页 |
| E3 受限 Agent | 本地工具、依赖链、结构化建议、字段投影、预算与失败 | 模拟端点覆盖 ID／链路／取消／越界；实际依赖决策仍须后续真实模型证据 |
| E4 真实只读接入 | 在明确账号／资源／权限／数据／预算授权内验 CFW、ECS、NAT 与所配模型 | 分接口核对字段／分页／身份／模式，与控制台复核；缺能力保留未验收，不用离线冒充 |
| E5 实验与论文 | 固定标签和对照条件，分别评估规则正确性、Agent 补查与产品闭环 | 保留误报漏报、失败／未支持、实际开销与局限，不预设 Agent 一定提升 |

未编造学校排期、企业容量、固定费用或性能收益。真实模型和云验收可集中安排，但不能被前面的工程通过替代。

## 6. 文档级自审记录

本轮纠正了一处资料断言：两个早期候选接口名没有取得可靠的“已废弃”依据，已撤除该说法；只把已核实的两个 Describe 文档与 SDK 作为方案依据。官方 NAT 资源权限按 AclUuid／ProxyId 描述，不笼统写成只能全资源授权。

本轮自审重点：分区隔离、厂商字段、默认行为、NAT 关联、快照一致性、权限与取消、界面契约、需求／设计／实现状态分离。

已修订的风险包括：未经核实的接口与废弃状态断言、分页／总数字符串被当整数零、模式被当默认拒绝、按 VPC 推断 NAT 路径、跨边界缓存／复审混用、只给协程 timeout 冒充底层取消、把原型当正式组件、同会话跨分区历史经摘要泄露，以及新增范围却仍引用 B1 作为当前输入。

实际完成的文档级检查：

- `python3 scripts/check_design_docs.py`：本地文档链接、围栏、3 段设计 JSON，以及人工示例的分区／计划／封存／预算／历史投影关系通过。
- 用临时错误示例验证文档校验器：跨分区封存、pinned 隐式外呼、根预算不一致、启动覆盖 scope、跨分区摘要和历史这 6 类均被拒绝；这不是 6 项业务规则测试。
- `python3 scripts/check_references.py`：70 份资料文件的来源、大小和 SHA-256 通过，其中本轮新增 12 份自写摘要；12 个本轮公开来源 URL 均核对为可访问。可访问不等于内容／产品能力已完成实测。
- `git diff --check` 通过；本轮没有新增业务工程、模型／云调用、数据库或正式依赖。

不宣称已运行本节以外的业务、SDK 构建或集成测试。此前 45 项浏览器回归只属于原型 v0.2，不作为本轮新技术设计的验收。
