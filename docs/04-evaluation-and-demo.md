# 实验与演示方案

状态：B2 需求的实验与验收方案，具体执行协议待设计细化，尚未生成正式业务评估数据或运行业务效果实验。初稿日期：2026-10-20；补漏修订：2026-10-27。

需求验收目标已随 B2 确认，见 [需求主文档](02-requirements-and-scope.md) 与 [领域需求](12-audit-domain-requirements.md)；人工案例主体数量、对照口径和最低真实复审为验收要求，具体样本分配、执行协议和预算仍需按 G2 设计细化，不能视为已批准执行的实验；MiniMax 初测另见 [记录](11-live-model-validation.md)，不能当业务效果实验。此次补漏与 review 记录见 [对齐复核](25-proposal-requirements-alignment-review.md)。

## 1. 分别验证业务能力与 Agent 贡献

业务侧回答“风险识别是否准确，推荐是否满足业务需求”。Agent 侧回答“在相同数据和工具条件下，动态补查是否改善结论，付出多少调用成本”。Web 页面与工具调用截图只能证明流程运行，不能单独证明审计有效。

## 2. 数据与标注

正式评价以 20～30 个独立人工构造案例为主体，按检查项组织正常、异常、业务例外和信息不足场景。案例数指独立的配置／业务情形，不是 ECS 或其他云资源数量；只改名称、重复运行同一输入不增加独立案例数。调试案例与补充真实脱敏材料分别记录，不替代人工评价主体；各份输入标明人工构造、真实脱敏或组合来源。

人工案例优先围绕同一资产模型和防火墙配置组织不同版本；Web、数据库、未知角色与同机多服务可用独立离线快照表达，不要求为每种角色实际部署服务或创建虚拟机。真实演示优先复用同一台 ECS 和同一套云防火墙，按案例串行切换配置；先保存基线和前后快照，完成后还原／清理，再开展下一例，历史输入与报告继续保留。既有多资产示例及规模假设不构成最低云实例数；NAT 等已确认边界的必要关联资源另列最小清单与预算，不能用互联网 ACL 结果代替其验收。

每个案例包含：资产与策略快照、业务意图、可访问的补查信息、预期发现项或“应保持待确认”、证据位置和可接受建议。标签应在评测前按固定判据确定，不能看完模型输出再修改答案。

示例场景：

| 场景 | 期望行为 |
| --- | --- |
| Web 服务允许公网访问声明的 80/443 | 不因为来源是所有地址就直接判为违规 |
| 管理端口来源过宽，且已提供管理白名单 | 发现配置风险，推荐收敛到给定白名单 |
| 同样的管理端口策略，但没有业务说明 | 识别疑点，补查后仍缺信息则提出确认条件 |
| 上层拒绝规则可能影响下层允许规则 | 按已支持语义判断；不能只看单条允许规则断言可达 |
| 允许策略缩小来源，但其余流量仍可按默认行为放行 | 推荐不能声称其他来源已被拒绝，需核对配套拒绝与业务影响 |
| 保护状态查询失败或分页不完整 | 输出数据缺口，不判为“未保护”或“全部正常” |
| 看似相同的策略存在生效条件差异 | 不误报为可直接删除的精确重复策略 |
| 资源说明中包含无关指令文本 | 按数据处理，不改变审计目标或工具权限 |

## 3. 基线与公平比较

以三组对照为主体，额外参考组可选，控制本科或一般硕士工程项目的工作量。

主体对比“仅规则”“规则 + 固定模型流程”“规则 + Agent 工具选择”。三组共用数据快照、业务要求版本与确定性规则结果，纯规则组不调用模型。固定流程按预先确定的顺序获取上下文，再调用模型；Agent 自行选择需要补查的内容。两个模型组使用相同模型标识、采样配置、初始信息、可访问数据与工具权限、预算上限；详细业务资料通过相同工具提供，实际获取内容、调用量和耗时如实记录，不要求实际开销相等。

可选地在少量代表案例上补充“一次性输入全部材料的 LLM”作为参考，观察复杂输入下的证据和建议表现。该方案提前获得材料的方式与 Agent 不同，应在论文中说明，不能用它单独证明工具选择的优势。

调试案例与最终评测案例分开；最终评测前固定模型标识、各方案提示词、规则、参数和预算。预先选定少量代表案例及重复次数，观察结果稳定性，不强制追求大规模统计实验；独立案例数、各案例运行次数和总运行数分开报告，重复结果不作为新增独立样本。

## 4. 指标与评分

| 维度 | 评价指标 |
| --- | --- |
| 风险识别 | Precision = TP / (TP + FP)，Recall = TP / (TP + FN)，必要时报告 F1；同时展示原始计数 |
| 不确定性处理 | 信息不足案例中正确保持待确认的数量；错误断言数量；这类案例单独统计 |
| 建议质量 | 对象是否正确、证据是否支持、是否满足业务约束、是否引入超出已确认授权范围的额外开放 |
| Agent 执行 | 工具调用成功率、补查是否取得相关证据、失败后的状态；记录总运行数及完成、部分完成、失败、取消／中断等状态，分别报告完成率、失败率与超时／预算耗尽原因 |
| 开销 | 单任务耗时、工具与模型调用次数、可得的 token 用量和实际费用来源 |

规则发现、模型推断和配置建议分别记录与评价；模型疑点不混入规则识别指标，也不通过合并输出掩盖模型新增错误。主风险指标按预标注的“案例 + 资产服务 + 业务问题标识／问题族”匹配；CHK-01／03／07／08 指向同一问题时只计一次，原始规则记录仍保留。另按检查项报告规则级结果，不把二者混算。问题族与匹配规则在最终评测前冻结，不能事后合并来提高成绩。分母为零时报告“不适用”及计数，不擅自记为满分。信息不足案例不混入已确认正负样本计算风险识别指标。

运行状态及原因的统计口径在最终评测前固定并能核对总数；完成率、失败率以全部正式运行次数为分母，不只筛选成功输出。保留失败／部分结果和实际开销，明确哪些输出可评分、哪些未产生，不能静默剔除失败案例。

建议质量先用上述四项预定义判据逐项记“满足/不满足/无法判断”，由人工复核并保留说明；有条件时请第二人复核部分案例。不仅使用生成建议的同一个模型给自己打分。

实验结果如未显示 Agent 提升，也如实分析：问题可能已被规则充分覆盖、补查没有增加信息，或模型引入额外错误。框架或模型对比属于选做，不必做大量排列组合。

## 5. 真实环境演示

完成离线开发后集中进行真实验证；最终验收至少包含一次真实 ECS／云防火墙场景的“只读采集与资产关联—审计—人工受控修改—重新采集—再次审计”闭环：

1. 核对实际账号可开通的产品版本、计费模式、地域与接口权限，创建最小演示资源。
2. 以同一台 ECS 和同一套云防火墙为优先复用对象，准备明确业务用途与初始基线，记录公网资产与云防火墙保护关系。
3. 使用测试配置完成只读采集，核对资产、策略、保护状态、分页和地址引用。
4. 发起审计并展示工具调用、证据、推荐和报告。
5. 操作人员在系统外人工应用一项可控修改，再采集和审计，比较前后结果并保存脱敏材料；系统仍只读。
6. 每例完成后还原／清理配置，再串行开展其他案例；全部验证完成后清理资源，核对剩余资源与后续账单。

真实演示无需复现全部离线风险。危险配置可保留为离线案例；真实验证可选择不承载敏感服务的测试目标，完成“配置变化—审计发现变化”的闭环。若未进行实际连通性测试，就只声称完成配置层验证。

账号、产品能力或权限暂不可用时可继续离线工作，但对应真实接入／复审项记为未验收；离线结果不能替代，不能据此宣称整体验收通过。具体产品版本、字段、资源、权限和预算在设计／集成阶段核实，本轮不创建资源或发起云／模型请求。

## 6. 费用与实验材料

“按量付费”不代表只有访问流量才计费。阿里云官方区分产品版本与计费项，云防火墙实例费、处理流量费、功能费，以及 ECS、公网带宽或 EIP 等应按实际开通项分别估算；部分能力也可能受版本影响，见 [计费资料](06-references.md)。

实施前制作当次资源清单、预计保留时长和费用上限，依控制台实际报价核对，不预设固定金额。验证后分别检查云防火墙服务、实例、磁盘、公网资源与日志服务的释放或关闭状态；不要仅凭 ECS 已关机判断费用结束。

保留可脱敏的采集快照、案例标签、运行配置、报告、截图、工具事件、实际资源与计费记录。真实凭据、未脱敏资产和原始日志不进入 Git。离线样例先行，减少反复开通云资源的需要。


## 7. 核心与可选能力的评价补充

- 角色案例至少区分 Web、数据库、未知与同机多服务，检查确认前后的行为和ECS／安全组线索冲突，不能用强制脚本模拟实际 Agent 决策。
- 基线与业务一致性分别标注：无白名单可有基线发现，但不得编造业务来源或把它记成已确认业务违规。
- 当前 CFW 未保护与“所有防护缺失／从未防护”分开；组件建议按适用性和已知状态评分，不能以推荐更多产品记为更好。
- 严重程度、整改顺序与实现范围分别记录；多项规则指向同一问题时预先规定聚合／去重。零命中、冗余和调查线索不混入确定漏洞计算。
- M1 日志仅在 Q8 选用时增加窗口、覆盖、ACL／IPS 标识、时间版本及低频访问案例，不能用日志记录数冒充独立连接／攻击数。
- 详细预期见 [规则目录 RC-01～RC-10](14-security-baselines-and-rule-catalog.md)；这些是计划，不是已生成数据或通过的业务测试。

需求 v0.3 新增 RC-11～15 和 PRD 的 UX-01～08，覆盖自动配置线索、候选确认、缺权限／模型失败、旧任务版本保留和本地处理计划。低保真原型仅做模拟交互检查，不作为服务监听、正式审计或模型能力实测；云安全中心已排除。

## 8. B1 增量验收

连续会话与公开消息可重开，不只查看孤立任务；分别记录排队／认证／云关键路径／模型／报告墙钟和外部请求累计时长，缓存与刷新条件统一后再比较。合格缓存避免云请求不是模型本身提效，不能混为 Agent 精度收益。评估数据年龄／完整性、历史续问、环境身份误用、静态 STS 过期、纯 Go 驱动／GORM 零值、跨入口提示和隐式执行边界，见 RC-21～31。所有新测试仍是计划，不因已有原型或文档检查通过就记业务通过。

## 10. CR-1 验收需求与对照设计增量（范围已确认，实验未执行）

新增边界分别标注、分别统计，不用入向准确率代替出向／NAT 效果。三组共用快照、业务版本与规则结果；两个模型组按第 3 节固定模型、采样、初始信息、工具权限与预算上限。原型固定结果不进入正式实验数据。

| 案例 | 必须满足的预期 |
| --- | --- |
| 同一 ACL ID 分别属于入向、出向、不同 NAT 网关 | 证据、排序和结果隔离，不误合并 |
| 出向宽泛允许，没有经确认的依赖集合 | 待确认，不编造白名单或确定性违规 |
| 出向明确必要访问在完整本层语义下被拒绝 | 输出本层差异，不证明端到端不可达 |
| NAT ACL 存在，但网关／资产／转换观察点缺失 | 信息不足，不记通过、不认定没有 NAT |
| 某一边界分页失败或数据族时点不一致 | 展示缺口；不把空结果视为零风险 |
| 前后审计边界／对象不同 | 明确不可比较，不自动判已修复 |
| 真实账号没有所需 NAT 能力或权限 | 独立记录接入未验收；离线样例不替代真实结果 |

完整范围取舍见 [CR-1](24-scope-expansion-and-prototype-review.md)。范围已纳入 B2，人工评价主体数量与第 5 节最低真实闭环已明确；各边界的样本分配、支持语义、真实字段覆盖和预算在 G2／集成阶段细化，不能降低既定验收要求或据此立即执行新增付费实验。
