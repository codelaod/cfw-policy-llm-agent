# 技术背景与选型评估

状态：基于一手资料的调研与候选建议，**不是最终技术选型，也不是实现或实测结论**。更新日期：2026-10-21。

2026-10-22 最新流程：本文保留前期调研背景，不是开工授权。用户已条件授权交叉审核后进入设计，当前 [B0](17-requirements-cross-review-and-design-baseline.md) 与需求 v0.4 为输入，[系统设计 v0.1](03-architecture-discussion.md) 待 G2。下文早期候选不是最新下一任务，正式实现仍须 G2。

本轮先补技术背景，不推进论文大纲。关联资料编号见 [官方资料与核实记录](06-references.md)；云平台能力、字段与离线文档缓存见 [云平台接入与能力映射](08-cloud-integration-and-capability-map.md)。

## 1. 本轮新增的用户背景

- 语言熟悉度：Go 高于 Python，Python 高于 Node.js；尚未决定后端语言。
- Web 前端倾向独立开发，与后端分离；这与已有方向一致。
- 需要考虑未来 Agent 的 TUI 运行方式，但不代表首版已经增加 TUI 交付承诺。
- 对计算、网络等云平台 API 接入没有抵触；是否接入应由审计需求决定。
- 同意小功能起步，但需要先了解实际产品、接口与代表性论文/项目，避免凭空规划。

不能把上述背景改写为“已选 Go”“已选 Eino”“已决定实现全部网络审计”。

## 2. 结论摘要

1. **优先验证 Go + Eino，Python + PydanticAI 作为备选。**这是结合维护者熟悉度、审计业务和未来 TUI 的项目适配判断，不是语言流行度或性能排名。
2. **推荐复用 Agent 框架的工具循环，自己实现审计领域逻辑和安全边界。**不必从零制造通用 Agent SDK，也不能把业务正确性托付给框架。
3. **推荐有限接入云平台只读 API。**以云防火墙为核心，补充 ECS 资产与安全组上下文，必要时补 EIP 关联；不以首版完成完整网络拓扑与实际可达性分析为目标。
4. **资料可以本地保存、按需查阅。**已下载相关官方页面，选定正文与来源清单根据用户要求随 Git 保存，原始 HTML 缓存仍忽略；归档不是把全文预先塞进模型，也不会自动保证减少模型费用。
5. 先做一条小型验证链，再确认技术栈；不同时建设 Go/Python 两套正式后端，不因框架宣传就声称兼容所有模型。

## 3. 语言评估：区分模型能力与运行时生态

本项目主要使用远端模型、结构化工具、配置归一化、地址/端口计算、任务状态和报告，不涉及本地训练模型。因此，语言选择的重点是接口适配、工具执行和维护成本，而不是能否训练神经网络。

另核实了阿里云官方 Go 云防火墙、Go ECS SDK 仓库和 Python SDK 入口（A-14～A-16）；不能因为云接入就认定必须用 Python。仓库存在不等于已完成安装、版本兼容或权限验证。

### 3.1 对本项目的比较

| 维度 | Go | Python | Node.js / TypeScript |
| --- | --- | --- | --- |
| 用户熟悉度 | 当前最有利 | 次之 | 当前最低 |
| 代表性 Agent 选择 | Eino；Google ADK Go 可作为其他候选 | PydanticAI、LangGraph；另有 OpenAI Agents SDK | LangGraph JS/TS、OpenAI Agents SDK 等 |
| Web 后端与独立前端 | 可采用单后端，前端通过 API 接入 | 同样可采用单后端 | 可与前端共用 TS 类型，但不是前后端分离的必要条件 |
| 本地 Agent 与 TUI 共用核心 | Go 应用服务与 Bubble Tea 可在同一程序中组合，是值得验证的路线 | 可用 Textual 共用 Python 服务逻辑，需要考虑分发和环境管理 | 可用 Ink 等方案，但对当前维护者增加学习成本 |
| 实验与分析 | 核心服务输出 JSON；后续分析脚本可独立编写 | 使用同一语言组织实验脚本较直接 | 可以完成，不因前端使用 TS 就必须选其为后端 |
| 本轮主要风险 | 选定框架与实际模型服务的协议兼容程度、事件与错误处理尚未实测 | 框架/provider 行为同样需验证；不能只因 Python 常见就忽略学习和维护成本 | 当前没有足够的项目收益抵消更低的熟悉度 |

依据：Eino、ADK、PydanticAI、LangGraph 和 OpenAI 官方 SDK 文档（F-01～F-06、M-03）；TUI 项目的官方说明（T-01～T-03）。此表不包含生态市场份额统计，也不声称某语言一定生成更好建议。

### 3.2 推荐如何收敛

- 先用 **Go + Eino** 实现一个离线业务意图补查案例；不要先开发完整 Web 或云采集平台。
- 如果实际模型服务的工具调用、事件、超时和输出校验均可用，就保留 Go 主后端。
- 若关键能力存在明确阻碍，再用同一案例评估 Python + PydanticAI。不能仅因 Go 调试不熟悉，就把问题笼统归为“Go 不适合 Agent”。
- 如果两者都满足要求，优先选择维护者更熟悉、业务边界更容易解释、运行记录更容易复核的方案。
- 前端继续独立开发；React/Vue 等具体框架不需要与后端语言绑定，本轮不替用户做决定。

技术调研阶段没有运行框架；后续用户已同意优先进行 Go + Eino 离线验证。独立实验见 [实验说明](../experiments/eino-offline/README.md)：模拟模型只能验证集成机制，不能用于真实服务兼容率、模型效果或 token 成本结论。

## 4. TUI 要提前考虑什么

“未来能在终端使用”至少有两种不同含义，不能只用 TUI 框架名替代架构决定。

### 4.1 TUI 是远端审计服务的客户端

```text
浏览器 Web ─┐
            ├─ API / 任务事件 ─ 单个审计后端 ─ 审计核心
终端 TUI ──┘
```

TUI 负责发起任务、查看工具事件与结果，模型和云凭据留在后端。此时 TUI 可以用 Go 写、后端用 Python；后端语言不被 TUI 强制决定。但多语言客户端仍有接口、错误模型和发布成本。

### 4.2 TUI 内嵌完整的本地 Agent

```text
Web API 入口 ─┐
              ├─ 同一审计应用服务 ─ 规则 / Agent / 工具 / 快照 / 报告
本地 TUI 入口 ─┘
```

终端进程直接执行工具循环，离线样例不要求先启动 Web 服务。若用户重视这种本地独立运行，Go 与 Bubble Tea 共用 Go 核心是优先候选。能否最终以单文件分发仍取决于实际依赖和静态资源，不能提前承诺。

Python 也有 Textual，Node/TS 也有 Ink，因此不能说只有 Go 能做 TUI（T-01～T-03）。

### 4.3 无论选哪种方式，都先固定服务与事件边界

- UI 只调用审计应用服务，不将规则和工具循环写进页面或终端组件。
- 任务输入、结果、取消、错误与事件结构统一；首版可以使用 API 轮询，未来按需增加事件推送。
- 建议事件包含 run/tool 标识、状态、时间、证据编号和脱敏错误摘要，不存储完整内部推理。
- 增加 TUI 不应复制一份规则引擎，也不应产生不同于 Web 的工具权限。
- 先保留接口边界，不为了未来 TUI 提前引入独立服务、消息总线或跨语言核心。

## 5. 框架与自研：不是二选一

### 5.1 三种路线

| 路线 | 优点 | 成本与风险 | 本项目建议 |
| --- | --- | --- | --- |
| SDK + 自写有限工具循环 | 状态、提示词和协议控制直接；依赖少 | 多轮消息、调用 ID、错误、重试、取消、并行、用量等均需自行维护 | 可以做理解机制的小原型，不作为默认长期方案 |
| 框架工具循环 + 自有领域与权限层 | 复用通用执行能力，保留审计规则、证据和安全边界 | 需理解框架终止、输出与 provider 行为，封装依赖 | **优先推荐** |
| 大型预置工作流 / 多 Agent 系统 | 某些复杂任务可直接复用 | 容易引入不需要的状态、角色和基础设施；业务过程反而难解释 | 当前没有必要 |

论文中的系统设计与工程工作可以体现在数据关联、策略语义、工具契约、证据校验、推荐约束和实验方法中，不要求原创实现通用 Agent 调度器。

### 5.2 主要候选的具体定位

| 候选 | 一手资料确认的能力 | 对本项目的判断 |
| --- | --- | --- |
| Eino / ChatModelAgent（Go） | 官方文档描述模型—工具循环、工具配置与最大迭代数；源码有 `MaxIterations`。OpenAI 组件源码提供 `BaseURL`、超时/HTTP 客户端等配置 | Go 路线首个验证对象；接口可配置不等于兼容所有第三方服务（F-01～F-03） |
| Google ADK Go | 官方提供 Go 快速开始和工具 Agent 示例 | 作为 Go 路线的其他候选；本轮不因此增加第二套实现或承诺任意模型适配（F-06） |
| PydanticAI（Python） | 官方文档提供类型化依赖、工具、输出类型、用量限制等机制 | 若采用 Python，是单 Agent、结构化审计输出的首个候选；输出 schema 正确不等于结论正确（F-04） |
| LangGraph（Python / JS/TS） | 官方定位为有状态编排，强调持久执行、流式与人工参与 | 真有暂停/恢复、持久化工作流需求时再考虑，不为一次受限工具循环先建设完整图流程（F-05） |
| OpenAI Agents SDK（Python / TS） | 官方提供 Agent 运行与工具相关文档 | 可作为对应语言的其他候选；需单独验证实际模型协议，不把 OpenAI 模型 SDK 与 Agent 框架混为一谈（M-03） |

这里的“有官方框架/文档”不等于“已验证足够成熟”。本项目的成熟度验收应包括依赖许可、版本维护、工具行为、故障处理和可观测性；独立实验已固定 Eino v0.9.22 及 module 校验和，但不代表正式系统依赖已经定稿或已完成所有依赖许可审查。

### 5.3 必须自己实现或掌握的部分

- 云数据归一化与完整性判断、快照版本、来源和时间。
- 地址、端口、方向、动作、顺序、启用状态及已支持的匹配语义。
- 工具授权范围、输入输出契约、只读 allowlist、调用/时间/大小/模型预算上限。
- 证据编号、对象引用、推荐条件、业务约束校验以及人工复审。
- 规则原始发现与模型建议分离，模型不能覆盖确定性发现。
- 实验案例、固定标签、评分和可复核运行记录。

建议在应用服务里封装框架：领域对象不直接依赖 Eino/PydanticAI 的消息类型。模型协议适配同样隔离；Chat Completions 仍是候选，不因本次调研自动成为最终协议。

## 6. 为什么建议有限接入计算与网络 API

只接云防火墙适合完成**防火墙配置层审计**，不是错误方案，但对资产业务上下文和其他访问控制层的了解有限。ECS 接口则可以补充实例、地址、安全组关联等信息；安全组接口可以补充另一层配置证据（A-02、A-03、A-11、A-12）。

推荐层级如下，仍待用户确认：

1. **核心采集**：云防火墙资产、防护状态、互联网边界策略、被引用的地址簿/端口对象。
2. **上下文补充**：ECS 实例、标签、地址、安全组关联；读取已关联安全组的规则。规则语义未完整支持时只展示上下文，不把它伪装成已完成可达性证明。
3. **按需补查**：EIP 到实例/网卡的关联；具体绑定路径需要时才增加 VPC API。ECS 本身已返回的 EIP 信息应先利用，不重复拉取所有网络数据。
4. **暂不纳入**：完整 VPC 路由、NAT、SLB/ALB、全部网络拓扑和端到端可达性验证；不接云上写操作。
5. **日志与命中统计选做**：先核实版本、权限、时间窗口、费用和数据完整性。策略 API 有 `HitTimes` 字段不等于有长期完整日志，零命中不能直接判定无用。

采集建议由后端受控执行并建立快照；Agent 通过授权的领域工具读取快照或受控补查结果，不提供任意云 API、Shell 或 URL 访问工具。真实采集与离线样例共享统一输入与证据结构。

## 8. 阿里云原生能力与课题定位

官方已经提供“安全运营 Agent”用户文档：其基于大模型与近期业务流量日志生成 ACL 建议；文档涉及日志前提、生成原因及人工应用流程（A-10）。这些是厂商文档描述，不代表本账号已开通或本项目已验证其效果。

因此不能将“首次使用 AI 推荐防火墙策略”作为论文创新，也不能无实验地声称优于厂商系统。可考虑将本项目工程重点收敛到：

- 离线快照与真实只读采集的统一、可复现实验。
- 显式业务意图、确定性规则与模型疑点的区分。
- 工具选择和补查过程的证据记录、信息不足时停止断言。
- 不同模型服务的能力验证和预算控制。
- 自定义案例上的规则、固定模型流程与 Agent 对照。

这些仍是待实现、待验证的工程贡献，不代表厂商必然缺少同类能力。不把厂商原生 Agent 设为必须复现的对照组，避免因日志积累、产品权限等额外要求扩大首版成本。

## 9. 用什么小验证来做决定

### 9.1 语言与框架验证

用同一个离线场景，提供 `get_asset`、`get_business_intent`、`list_related_policies` 等少量只读工具，测试：

1. 模型选择工具、参数校验、工具调用 ID 与结果回传。
2. 至少一次工具结果回传后继续调用另一工具；并覆盖工具结果已足够时直接结束的路径。
3. 白名单存在时引用给定证据；缺失时保持待确认。
4. 超时、非法参数、工具失败、无效证据引用、调用/模型预算耗尽和取消。
5. 可输出前端/TUI 无关的事件与结构化结果。
6. 实际服务的接口路径、流式行为、工具协议、schema 与用量字段。仅可配置 `base_url` 不算通过。

先验证 Go + Eino；只有关键失败或需要比较时才增加 Python 原型。通过条件和失败记录先确定，不以模型输出看起来更流畅作为选型证据。

### 9.2 云接口验证

在用户授权的真实账号中，使用最小只读权限核对资产、策略、引用对象、ECS、安全组和分页。当前没有凭据验证，不能在记录中填“通过”。本轮下载公开文档不属于账号接入，也没有产生云资源。

### 9.3 目前不做的事

不立即生成论文大纲，不创建完整业务脚手架，不固定最终语言/框架，不扩展多 Agent、自动下发或完整拓扑。验证后再把用户确认的决定同步到阶段计划。
