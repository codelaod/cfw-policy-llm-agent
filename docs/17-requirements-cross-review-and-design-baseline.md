# 多角度交叉审核与设计输入基线 B0

版本：v0.1。日期：2026-10-22。性质：**单一作者从不同角度开展的文档／场景审核，不是独立专家评审或业务测试**。

用户本轮授权：“我觉得差不多……通过各种角度再审核一下，没问题了再进入研发设计系统架构设计啥的”。据此先修正可发现的文档问题，再以显式默认范围建立 B0 设计输入；本记录不伪造用户对所有细项逐一签字，也不授权越过设计 G2 开始正式业务编码。

本文件保留 B0 的进入设计记录；当前 B1／设计 v0.2 的新增会话、时序、认证及推荐引导，见 [23](23-design-v02-review-and-publication.md)。旧 40 项校验是当时实际数量。

## 1. 审核范围与结论

审核了系统需求、领域判据、PRD、低保真原型、来源清单、前期技术实测及交接说明；从业务价值、成本范围、产品流程、策略语义、数据证据、Agent 边界、访问安全、可复验性、故障与工作量十个角度推演。

结论：**下列文档级问题已修订或已在设计中明确控制，未发现必须先扩大业务范围／追加真实调用才能进入系统设计的剩余阻塞。按用户的条件授权进入 P2 系统设计；设计稿仍待 G2 用户审核，正式业务系统未实现。**

“允许进入设计”不表示审计效果、真实接口、协议全兼容、部署安全或性能已经通过验收。未知账号能力、模型连续依赖补查及新增依赖的构建保留后续验证门槛，不用自审替代实测。

## 2. 审核发现与处置

| 编号 | 角度／发现 | 风险与修正 | 状态 |
| --- | --- | --- | --- |
| XR-01 | 成本范围 | 用例还残留“标签／指纹”输入；改为 ECS／安全组线索，云安全中心、客户端与主动扫描继续排除 | 已修订 |
| XR-02 | 基线措辞 | “全部公网来源开放”容易被理解为必须证明全部 IPv4 都可达；明确 CHK-07 检查存在由全地址来源条目／默认放行形成的配置允许范围，不声称整体公网可达 | 已修订，见领域／规则与设计 |
| XR-03 | 顺序与默认行为 | 单看宽泛允许会误报，被高优先级拒绝遮蔽时应区分；只缩一条又可能被默认放行绕过；设计三值匹配并保留路径来源 | 设计控制 |
| XR-04 | 配置与数据面 | API 返回新配置、保护开关开启均不能证明策略已下发或端到端可达；结论限定快照配置逻辑，复审记录采集／变更时间与限制 | 已澄清 |
| XR-05 | 支持子域 | ANY、观察动作、应用／域名和未知引用可能被静默简化；TCP／UDP 投影与未支持范围分别表达，相关未知前置规则不可跳过 | 设计控制 |
| XR-06 | 角色与授权 | 候选确认、服务角色、访问授权和风险例外不能由同一含糊聊天回复隐式批准；确认提交显式区分字段并在服务端校验 | 设计控制 |
| XR-07 | 版本竞争 | 旧草稿覆盖新画像、多标签冲突、补信息改写旧任务；采用基版本条件更新、不可变版本和新建复审 | 设计控制 |
| XR-08 | 可重复性 | 例外到期／采集时间影响同一输入结果；审计清单固定评估时点、输入／归一化／规则版本，不能使用无记录的当前时间 | 已增强需求与设计 |
| XR-09 | 完整性 | 全局“部分采集”过粗；按接口／边界／资源分区标记缺口，每项判据核对所需分区，局部事实可保留但不能全局通过 | 设计控制 |
| XR-10 | 资源关联 | 共享组、多网卡、账号与地域、NAT 观察位置可能错误归因；稳定资源身份和关联证据优先，无法关联保持未知 | 设计控制 |
| XR-11 | 重复消费 | 重复点击、网络重试及重启恢复可能重新收费；新建操作幂等，实际 HTTP 尝试计数，运行中任务重启后标中断，不自动重放模型 | 已增强需求与设计 |
| XR-12 | 取消与故障 | 取消不能撤回已到达上游的请求；只承诺停止后续请求、尽力中断并保留结果；阶段失败与业务待确认分开 | 已澄清 |
| XR-13 | 本地入口安全 | 绑定 localhost 不足以证明敏感／付费端点安全；设计最小访问口令、Host／Origin 限制、同源和限流，不引入账号组织体系 | 已增强质量约束；G2 审核默认方案 |
| XR-14 | 真实数据外发 | 标签／名称、业务来源等可能含敏感信息；任务绑定获准字段投影，默认资产别名和最小证据，原始快照不直接送模型 | 设计控制 |
| XR-15 | 提示注入与输出 | 描述、标签和报告可能带指令／脚本；工具授权在后端，模型不能选择任意 RPC／SQL／URL，前端文本渲染，结构化输出由后端校验 | 设计控制，非已证明绝对安全 |
| XR-16 | 证据与推荐 | 引用存在不等于所有自然语言正确；机械检查对象、规则、证据与条件，模型疑点独立，不能覆盖原始发现 | 设计控制 |
| XR-17 | 任务与风险状态 | “任务完成”“采纳待办”“暂缓”不等于全部通过或修复；单独统计执行状态、结论状态、覆盖和本地处理状态 | 设计控制 |
| XR-18 | 工作量 | 把全部日志／IPS／额外产品状态纳入会放大首版；B0 默认 M0，M1 默认关闭，不接 SIEM、实时 SLS 或多产品 API | 明确设计默认，不冒充历史用户逐项选择 |
| XR-19 | 存储与部署 | 队列／Redis／多库并非当前必要；单进程、SQLite 短事务与单任务工作器，故障恢复与私有数据边界明确 | 设计取舍 |
| XR-20 | 实测边界 | 现有两个人工样例只证明一批工具回传，不能当连续依赖补查／正式规则效果；设计验证矩阵保留这些门槛 | 记录后续验收 |
| XR-21 | 验收追溯 | 原验收能描述流程但缺少并发、幂等和重启场景；补 RC-16～20，FR／NFR 到模块、接口和测试的映射 | 已补齐 |
| XR-22 | 实验重复计分 | 原“案例＋对象＋检查项”主口径与跨规则去重意图冲突；主指标改为预定义业务问题族，规则级指标单列，保留原始发现 | 已修订 |

“设计控制”表示设计稿给出解决方案，仍需实现与测试，不表示控制已经生效。低保真状态检查不是上述安全控制的运行证据。

## 3. B0 设计输入与默认值

以下是本轮进入设计所采用的**可调整设计默认**，不改写为用户此前已确认的细项。若 G2 改变这些值，回到相应需求／设计同步修订。

| 编号 | B0 输入 | 理由／边界 |
| --- | --- | --- |
| B0-01 | 首个闭环采用阿里云互联网入向、单账号、显式地域与资产列表、IPv4 的已支持子域 | 延续现有范围建议，避免全网／多云；其他边界显示不在范围 |
| B0-02 | 最终有离线快照与真实只读采集，CFW＋ECS／安全组，网卡／EIP 按必要关联补查 | 真实联调后置；没有据此开通资源或授权云上写入 |
| B0-03 | CHK-01～08 作为 M0 设计目标；CHK-09～12／日志 FR-14 默认不启用 | 不把未知 IPS／日志接口当核心依赖；保留清晰扩展口 |
| B0-04 | 画像通过自动线索、模型候选与人工确认；业务授权单独声明，受信标签映射默认空 | 不强制确认未知，不依赖新安全产品，模型不写业务事实 |
| B0-05 | 基线以当前五个风险端口主题和项目规则版本为起点，角色模板与例外有版本 | 不称监管或整体合规，不由模型补阈值或白名单 |
| B0-06 | 单操作者、同源、默认 loopback，最小访问保护；外部／公网部署不在默认形态 | 访问口令不是云／模型密钥，也不是新增组织账号系统 |
| B0-07 | 以 3～10 个演示资产、约 200 条策略组织案例；算法另有限额和降级 | 是工作量与测试设计假设，不是性能实测、容量保证或用户数据事实 |
| B0-08 | 正式栈建议 Go＋Eino、Vue 3＋TypeScript＋Vite、SQLite；一进程与一工作器 | 依据熟悉度、既有实测与部署成本；具体选择仍待 G2，新增依赖未构建 |

未知学校排期不阻止架构设计；性能阈值在 G2／工程验证时按目标机器确定。未确定的真实产品版本、账号权限和字段覆盖在实际接入验收，不把资料已下载等同账号已可用。

## 6. B1：本轮用户反馈后的设计输入增量

B1 延续 B0 的云只读、成本、有限范围和 M0 规则，不把新增使用细节扩成通用平台：HTTP 层建议 Gin；SQLite 必须纯 Go，考虑 GORM；业务必须持久连续会话／消息／确认／任务／报告；数据策略与根耗时覆盖认证、采集和模型，分层反馈；应用／云／模型／工具认证统一；Web 与交付的 CLI／TUI 都有情境推荐短语和下一步。

用户同时授权本轮自审修订后提交推送，但未批准 G2 前正式业务编码／真实调用。新增要求见需求 v0.5、PRD v0.3、设计 v0.2 和 20／21／22，Review／发布核对见 23。不把用户允许“考虑 GORM／框架”误写为用户指定了某个社区驱动。
