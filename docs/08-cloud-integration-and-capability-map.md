# 云平台接入、能力映射与资料使用

状态：官方文档核对与接入建议；**尚未调用真实云账号 API**。资料更新日期：2026-10-21；审核顺序及 ECS／安全组字段补核：2026-10-22。

本文是背景依据，不是接口验收记录。当前按用户条件授权及 [B0](17-requirements-cross-review-and-design-baseline.md) 已进入 P2，[系统设计 v0.3](03-architecture-discussion.md) 待 G2；不按早期验证清单自动追加调用，也不因资料齐全就编码。

资料编号见 [官方资料与核实记录](06-references.md)，技术选型背景见 [技术背景与选型评估](07-technical-background-and-options.md)。

## 1. 接不接计算与网络 API

用户已明确不接入云安全中心；画像使用已有 ECS／安全组上下文并经用户确认。建议采用“云防火墙核心采集 + ECS 最小上下文 + 网络关联按需补查”，而不是“完全不接”与“接入所有云产品”二选一。该分层仍待用户确认，不改变首版只读的边界。

| 方案 | 可以支撑 | 局限与成本 | 评估 |
| --- | --- | --- | --- |
| 仅离线快照 | 规则开发、Agent 工具流程与重复实验 | 不能证明真实只读接入成功 | 必须保留，不作为唯一最终验证 |
| 云防火墙 API | 资产视图、保护状态、策略及引用对象的配置审计 | 不能预设完整替代 ECS 资产元数据；其他访问控制层不可见 | 首版核心 |
| 云防火墙 + ECS/安全组 | 关联实例、地址、标签、安全组，补充配置上下文 | 多一层权限、分页和安全组语义；不自动获得真实可达性结论 | 优先建议 |
| 再加有限 EIP/网卡查询 | 在已有数据不足时补公网 IP 与资产关联 | 具体绑定模式、地域与间接关联需验证 | 按案例需要增加 |
| 全量 VPC/路由/NAT/负载均衡/日志 | 可以支持更广的配置与路径研究 | 数据、语义、费用与实验范围明显增加，仍不等于运行时可达性 | 暂不纳入首版 |

读取安全组可先用于上下文展示和有限检查；在多安全组、前缀列表、源安全组引用等语义未支持前，不能把跨层结果称为完整路径验证。

## 2. 候选 API 与输入映射

以下为公开接口文档中的名称与字段，**不是已完成的采集器或最终数据库 schema**。示例字段只列与审计相关部分，实际响应、分页与账号版本仍需验证。

| 对象 | 官方接口与资料 | 已核对的相关信息 | 需要验证/实现的内容 |
| --- | --- | --- | --- |
| 云防火墙资产 | `DescribeAssetList`，A-02 | `ResourceInstanceId`、`BindInstanceId`、`InternetAddress`、`RegionID`、`ProtectStatus`、`TotalCount` 等 | 资源 ID 与绑定实例的语义；当前账号视图、过滤条件、支持状态、分页及 ECS/EIP 关联 |
| 互联网边界策略 | `DescribeControlPolicy`，A-03 | `AclUuid`、`Direction`、`Order`、`Release`、`SourceType`、`DestinationType`、`Proto`、`AclAction`、`ApplicationNameList`、端口/地址簿信息、`HitTimes` 与总数 | `Order` 越小优先级越高；`Release` 为字符串状态；不能混用请求与响应字段或假定全部数值都是整数 |
| 地址/端口引用 | `DescribeAddressBook`，A-07 | 引用对象标识、`GroupType`、成员、成员数量、动态标签相关信息 | 识别 IP、端口、域名、标签等类型；固定时点的成员展开；未解析对象不能当成空集合 |
| ECS 资产 | `DescribeInstances`，A-11 | 实例标识、`SecurityGroupIds`、`PublicIpAddress`、`EipAddress`、网卡相关信息等 | 明确地域范围和分页方式；优先用稳定资源标识关联，不只按 IP；先利用已返回的 EIP/网卡信息 |
| 安全组规则 | `DescribeSecurityGroupAttribute`，A-12 | 方向、`IpProtocol`、`PortRange`、`Policy`、`Priority`、源/目标 CIDR、组/前缀引用等 | 先读取已关联安全组；与 CFW 分开归一化；多个安全组、默认行为与有状态语义需另行核实 |
| EIP 关联 | `DescribeEipAddresses`，A-13 | 公网地址、实例类型与实例/网卡等关联线索 | 本轮缓存的是旧版官方入口；实施前核对当前 OpenAPI/SDK、地域与绑定模式，不默认直接绑定 ECS |

云防火墙 API 概览（A-06）还包含 NAT、VPC 等其他边界接口，不能把它们当作互联网边界接口的同义词。本次未定位并验证互联网 ACL 引擎模式的完整只读采集路径；可先保留人工填写或未知状态，不编造接口名。

### 2.1 语言相关 SDK 路线

阿里云官方已有 Go 云防火墙、Go ECS 和 Python SDK 仓库入口（A-14～A-16），本轮核对仓库存在且未归档。当前没有安装、编译或冻结具体版本；选择 Go 不代表需要自行实现签名，也不代表可以将整套 SDK 方法暴露给 Agent。接入时仍需选择允许的只读接口、验证凭据链与版本兼容。

### 2.2 自动画像线索：文档可得性与业务流程

2026-10-22 公开文档核对：A-11 返回名称、标签、系统和关联安全组／网卡等，A-12 返回安全组方向、协议、目的端口、动作、优先级和来源／引用；关联不足时才按所选资源补 A-27。字段可以作为模型的角色线索，但无标准“业务角色”字段保证，不能证明服务监听或业务授权。

流程为自动展示证据 → 模型提出候选／不确定性 → 对话或表单补缺项 → 预览差异 → 用户确认本地画像／访问要求。只读 API 不负责写回用户确认，系统不回写云标签或安全组。多组、共享组、多网卡、ALL 协议和未解析引用均保留歧义，不能只按端口数字贴标签。

不接入云安全中心、不安装主机客户端、不主动扫描。已核对文档不等于已写采集器或账号实测；权限、分页、地域／资源关联在后续批准的集成中验收。具体产品使用路径见 [PRD](16-product-requirements-and-user-flows.md)。

## 3. 官方用户文档对规则设计的约束

### 3.1 默认行为与顺序

官方策略原理说明：按优先级匹配；未命中全部已配置策略时默认放行。接口文档中 `Order` 数字越小优先级越高（A-03、A-08）。

因此：

- 缩小某条允许规则的来源，不足以证明其他来源已被拒绝。
- 不能只看一条低优先级允许规则就断定实际访问路径。
- 推荐需要说明单条修改还是配套修改，并检查其他规则、兜底与业务影响。
- 不把观察动作无条件当作拒绝；精确行为在支持矩阵与真实验证中明确。

### 3.2 匹配条件不只有地址与端口

官方文档还讨论应用、域名与严格/宽松 ACL 模式（A-05、A-08、A-09）。

建议初始开发用已明确的直接 CIDR、协议、端口、方向、动作、顺序和启用状态场景。对域名、应用识别、地理区域、动态组、生效时间、IPv6 等未支持语义，保留原字段并标记，不把未知条件丢弃后给确定结论。

### 3.3 保护状态、命中与运行时可达性

- `ProtectStatus` 文档区分保护中、开启中、未保护、关闭中；接口失败或资产未返回不能直接变成“未保护”。
- `HitTimes` 文档存在不代表长期流量日志完整，也未在本轮核实计数窗口和重置规则；不按零命中自动推荐删除。
- 云防火墙配置允许，不代表安全组、主机防火墙、监听服务、路由等全部放行。
- 引入 ECS/安全组后仍只能在已支持条件下作配置层判断；实际可达需要额外证据与明确授权的测试。

## 4. 数据、权限与采集完整性

推荐实现原则：

1. **后端受控采集**：明确允许的读接口、账号、地域、资源范围和参数；不向 Agent 开放任意 API 名、任意 URL 或任意 SDK 方法。
2. **最小权限**：根据 API 授权信息逐项配置实际需要的 RAM 权限并验证。不为方便直接授予全权限；“名称以 Describe 开头”不能替代授权核对。
3. **凭据隔离**：云凭据与模型凭据留在后端/本地私有配置；公开事件、报告和前端不携带密钥。
4. **分页与失败记录**：记录请求参数、页数、总数、去重、限流、错误和缺失字段。总数或分页信息不一致时标为部分采集。
5. **来源与版本**：每个对象保留原始位置、采集时间、归一化版本和证据引用；不同产品采集有时间差，不声称天然原子快照。
6. **身份与关联**：以账号/地域/资源 ID 为主要关联依据，公网 IP 作为证据之一；关联失败显示原因，不凭名称相似强连。
7. **统一输入**：真实采集与离线样例通过同一归一化服务供规则和工具使用。人工构造数据必须标明来源。
8. **外部文本不可信**：标签、资源名、策略描述都是数据，不得改变提示词、工具范围或模型预算。

本节是设计要求，不代表本项目已实现这些控制。

## 5. 不建议由 Agent 随意实时查询所有产品

推荐基本采集先由受控流程建立快照，再由 Agent 根据疑点选择 `get_asset`、`get_business_intent`、`get_policy`、`resolve_address_reference` 等领域工具。

工具既可读快照，也可在授权范围内发起必要补查；真实补查应生成新的证据与时间标记。基线与 Agent 实验应使用相同事实集合、快照和预算条件，避免实时数据漂移影响比较。

这既能体现 Agent 的补查决策，也能限制云 API 次数、账号权限和运行成本。只读不等于无数据泄露风险，工具输出与日志仍需脱敏。

## 7. 下载、联网与 token 的关系

下载文件到磁盘本身，不等于把文件全文输入模型；但将文件内容、检索片段或工具结果送进模型上下文仍会占用相应用量。在线阅读也同样需要处理返回内容；不能承诺本地或联网方式一定免费、一定更省。

建议使用：

```text
官方索引与来源清单
        ↓
只下载当前范围相关的页面
        ↓
去导航、去脚本，保留正文和原始来源
        ↓
本地关键词检索，只读取需要的字段/段落
        ↓
在需要时重新打开官方页面核对更新
```

不要每轮把全部 HTML、PDF 或近十万字符正文送入模型；也暂不因此引入向量数据库。具体上下文、缓存和检索计费以所用模型服务/平台为准，不能用文件字节数直接换算 token 或账单。

## 8. 资料缺口与后续验证安排

- 当前先审 G2 的数据与接口设计；B0 的必需／可选范围已明确，不把全部资料接口变成首版功能。
- 系统设计已形成必需字段、最小只读范围和关联规则提案；影响已选能力的资料缺口在设计审核前补齐或明确降级。
- 真实账号版本、权限、分页和资产关联在批准的后续只读集成阶段验收，不要求在需求审核前真实调用；尚未验收的能力不写成已验证。
- 新的模型／云端验证不是当前自动执行任务；涉及预算、真实数据和权限时保持既有授权边界。
- 真实资源开通、日志开启、策略应用与费用支出不由本份资料调研授权；本轮没有进行这些操作。

## 9. CR-1：B2 已确认范围的采集设计影响（2026-10-26）

用户已确认有限出向／NAT 需求，但不等于增加全部 VPC／路由采集；具体 API、权限和真实接入仍未验收。公开资料核对与摘要见 [CR-1 资料](references/scope-and-prototype/2026-10-26/manifest.json)。

| 数据族 | 当前可核实依据 | 尚需核实与权限边界 |
| --- | --- | --- |
| 互联网出向 ACL | `DescribeControlPolicy` 的 `Direction` 支持 `in/out`；请求与响应的方向必须保留 | 按方向独立分页／计数、动作／状态／顺序／引用、默认行为与账号实际响应；不是已验证采集器 |
| NAT 边界 ACL | 官方产品文档按 NAT 网关选择规则，说明源／目标／端口／动作／优先级／状态和引擎模式 | 现已核实当前 DescribeNatFirewallControlPolicy／DescribeNatFirewallList 的公开契约及官方 SDK 类型；真实响应／账号能力／默认 profile 与权限仍需验收，详见 25 |
| NAT 保护与资产关联 | 需要可定位的网关、防火墙、资产和观察点上下文 | CFW 信息不足时，再评审最小网络查询权限；不得自动读取其他账号 profile 或补开产品 |
| SNAT／DNAT 资料 | 与防火墙 ACL 分开；当前仅建议保留显式来源的关联资料 | 是否采集转换条目、地址观察位置、产品版本差异和时点一致性待 G2，不声明全转换审计或实际可达性 |

每族数据独立记录时间、来源、完整性、失败／未纳入状态；资料不足降级为未知，不以网络调研替代真实接口验收。外部查询仍须既定授权，不因 CR-1 自动调用。
