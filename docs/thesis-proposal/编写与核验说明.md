# 开题文稿维护与核验说明

本文件合并旧自审、提纲／文献调整和排版过程记录，仅保留后续维护需要的结论；不是新的系统审核包或学校最终批准记录。

## 1. 唯一正文与组织结构

[开题报告](开题报告.md)为唯一正文，Markdown阅读／修改，不维护Word／PDF副本。旧排版页码和中间候选题录不再作为活动文档。

论文按七章组织：绪论、系统相关技术分析说明、系统需求分析、系统设计、系统实现、系统测试、总结。设计讲准备怎样实现，实现和测试只能按实际代码／证据写；不因提纲存在就声称系统完成。

## 2. 引文与来源

正式15篇题录以[references.json](references.json)和[阅读指南](文献核验与阅读指南.md)为准：国内9／国外6，中文9／英文6，正式发表年份2023—2026。年份采用正式发表信息，在线首发与正式卷期区别保留；不改年份装新，不把官方页面可访问或摘要核对说成完整全文评审。

维护作者、标题、期刊／会议、卷期页码／文章号、DOI和原始入口的一致性。来源核验深度／方法适用边界集中记录在阅读指南，不再保留另一份未采用文献列表。正文编号、题录和指南修改时联动对账。

## 3. 正文语言与项目状态分开

正文用正式学术语言说明业务问题、研究对象、方法、功能和评价计划；G1／G2、提交、待审、工具输出和本轮改动写入[项目决策](../project/decisions.md)，不混入提交正文。

业务信息补充、画像确认、信息不足和支持语义写成明确功能流程。阿里云是首版适配／验证平台，不把课题写成厂商定制或已支持多云。业务角色不等于授权、配置不等于可达，已有方法不因本项目采用而变成原创。

## 4. 维护检查与当前局限

保留题目、七章结构、15篇引文与需求／设计边界的一致性；系统需求B2和整体G2已通过，但实现、正式实验、真实云和整改复审尚无完整验收证据。学校模板、个人信息、正式提交排期等属于独立事项，不伪造完成情况。

本轮目录治理不修改开题正文或正式题录，仅合并过程说明与修正内部链接。具体运行结果见验证区，不复用旧Word排版、自审次数或原型回归来证明业务效果。
