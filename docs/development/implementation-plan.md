# 研发实施计划

需求B2与设计v0.6已通过。当前未建立正式业务工程；本计划规定下一步开发顺序和退出条件，不是业务交付声明或真实调用授权。

## 1. 分阶段实施

| 阶段 | 入口 | 工作与交付物 | 退出条件 |
| --- | --- | --- | --- |
| E0 依赖／契约 | G2已通过，按后续明确安排启动；无云／模型外呼 | 固定Go／Gin／Eino／纯Go SQLite和Vue依赖；常规WAL／3会话骨架联调；验证Swag生成入口、SSE与模拟HTTP契约 | 构建、关键事务和3会话隔离、生成路线可行；不建SQLite专项框架 |
| E1 离线核心 | E0关键项通过 | 输入／分区／证据、三值规则、固定人工样例，先打通输入→规则→保存→审阅→导出 | 正确性、未知／缺失／超限和版本追溯通过；无云／模型也可用 |
| E2 持久服务／Web | E1通过 | 会话／确认／任务／审阅／报告API和五路由；3会话、SSE补发、接口规范保留 | 幂等、重启、保存失败、数据隔离及文档／实际接口一致 |
| E3 受限Agent | E2关键契约通过 | 每任务独立运行状态、工具选择／依赖补查、结构化建议和规则保留 | 模拟模型验证并发、ID／scope／失败和预算；正式模型仍待授权实测 |
| E4 真实接入 | 本地契约稳定；另行明确账号／地域／资产／权限／数据／预算 | 所配模型、CFW／ECS／NAT只读验证及至少一次人工整改→强制重采集→复审 | 分能力有证据，缺项明确未验收，不自动扩API／权限／资源 |
| E5 正式评价／论文 | 案例、标签、模型条件和预算冻结 | 20～30独立案例，三组运行、全部终态、误报漏报、建议评分和实际开销 | 条件公平、总数可对账，论文仅陈述实际证据，不预设Agent一定提升 |

## 2. 先形成最小离线闭环

E0先固定关键依赖和契约，不接真实云／模型；E1先打通一个固定人工案例的输入→规则→持久保存→审阅→导出，再扩有限出向／NAT。无模型／无云时，人工确认和rules-only路径仍可用。E2／E3逐步联动Web与受限Agent，不能一开始同时接全部真实服务来掩盖故障来源。

3会话并发是最低产品体验，不是多Agent平台。SQLite按WAL＋普通池正常使用，不为假想流量自建调度／备份／监控框架。接口文档随实现生成并保留，字段、头部、错误、路由与前端契约同步维护。

## 3. 退出条件和证据

- 规则／输入／版本／证据：见[审计设计](../design/audit-and-agent.md)和[验证清单](../validation/verification-plan.md)。
- 会话、幂等、取消、恢复、3会话和SSE：用人工数据、本机模拟端点和正式存储验证；当前未执行。
- Go／SQLite与前端依赖：固定版本、无CGO存储、正常事务和构建；不要以更换成CGO驱动绕过失败。
- Swagger生成：选定版本可重复生成、产物保留、实际路由双向对账；SSE状态机另有事件契约，不假定生成器自动实现流解析。
- 真实模型／云／整改复审：按[评价计划](../validation/evaluation-plan.md)另行明确范围和预算；缺能力只记未验收，不能用模拟替代。

验证失败时保留实际结果和未完成项。影响已批准范围、核心技术或验收目标时记录并由用户决定，不静默放宽阈值、扩大权限或自动收费。

## 4. 现有命令与未来产物

现有可运行命令只属于[独立实验](../../experiments/eino-offline/README.md)、[交互原型](../prototypes/audit-workflow/README.md)和文档检查。正式server／Web命令、迁移和部署在实际工程建立后再提供。

接口产物目标是`docs/api/swagger.json`、`docs/api/swagger.yaml`、生成说明／变更记录及SSE schema；当前不创建空的伪生成规范。私有库、原始云数据、备份和执行报告保留在忽略目录，不混入公开接口示例。
