# 稳定 B2 需求下的整体架构与技术复核

版本：v0.2；日期：2026-10-27。输入：需求 v0.6／B2、当天补漏、PRD v0.4 和本地技术设计 v0.3。v0.4 复核输出保留；用户随后确认 UI／SSE 调整，当前输出为 **技术设计 v0.5，仍待整体 G2**。

用户要求需求暂不再变，按整体需求复核架构与技术。本轮不修改需求功能、验收目标或资源约束，不创建正式工程、迁移或部署，不运行真实模型／云请求，不提交／推送。八份需求／PRD／验收输入的内容摘要在审查开始前冻结，结束后核对不变。

面向用户逐项做决定的主入口已整理为 [G2 整体系统设计审核包 30](30-g2-system-design-review-package.md)；本文继续作为技术复核依据和历史检查记录，不要求用户先拼读所有详细文档。

## 1. 总体判断

保留 Go＋Gin＋Eino、Vue／TS／Vite／Router、纯 Go SQLite 和单进程／单工作器路线；按用户本次确认把 Element Plus 建议替换为 Nuxt UI v4＋Tailwind v4，事件传输改为 fetch SSE 主通道＋轮询兜底（见 29）。不扩展多云、复杂拓扑、微服务或多 Agent。

问题主要在需求到设计的衔接与契约一致性，而不是需要推翻技术栈：AC-21 与串行真实验证尚未充分承接；审阅保存契约偏粗；不同任务的外呼准入表述不统一；导入声明与可信完整性混用；确认修订与 HTTP 条件语义、队列恢复和请求账本需要收紧。

本轮修订只完成文档级设计闭合。依赖构建、纯 Go ORM、SDK transport／取消、模型真实能力、性能、真实云及整改复审仍是 G2 后的实际验证，不因设计完整而宣称通过。

## 2. 发现与处置

级别表示未实现设计中的风险优先级，不是生产漏洞或已发生事故。

| 编号／级别 | 设计问题与影响 | v0.4 修订位置／处置 |
| --- | --- | --- |
| RV4-01／P1 | 20～30 案例、串行复用及至少一次真实复审未完整进入技术退出条件，多资产容量可能被误读为云资源下限 | 03／26／28 明确案例、运行和真实 episode；单台串行优先，AC-10／21 不可用离线替代 |
| RV4-02／P1 | 旧设计泛称三组固定模型／预算，缺少共同规则结果与全运行分母，易混报 Agent 收益 | 19／28 规定三组共享输入／规则，两个模型组同条件；三类输出、失败、重复与实际开销分开 |
| RV4-03／P1 | 审阅意见的版本、幂等、历史读取与保存失败反馈不具体 | 18／20／03 增加审阅追加记录、修订 CAS、同键重试和明确保存确认；不修改原始发现 |
| RV4-04／P1 | 只明确 audit 计划，其他 job kind 的准入笼统；助手“可能刷新”又与仅快照工具矛盾 | 18／20／21／22 统一 ExecutionAdmission；计划执行与明确发送都生成受控意图，助手轮次禁止隐式云刷新 |
| RV4-05／P1 | 导入的声明完整性不能升级为云事实，但全部按未知处理又会使离线分析无法完整使用 | 18／19／25 分开覆盖条件与来源保证；声明条件下的配置推导必须显式限定，缺页／缺引用仍不能通过 |
| RV4-06／P1 | 尝试计数、排队超时／取消与重启恢复缺少明确事务顺序，可能重复执行或多进程误标中断 | 03／18／20／21 补持久准入、逐物理尝试预记、独占启动锁、queued 直接取消和恢复顺序 |
| RV4-07／P1 | 文本接入或模拟协议检查容易被当成当前模型多轮能力通过 | 19／28 规定能力证据矩阵和配置版本；真实依赖链证据缺失仍未验收，失败保留规则 |
| RV4-08／P2 | If-Match 与业务修订冲突、数据发现模式与审计对象模式表述混杂 | 18 统一动作请求的 expected_revision／409；采集发现与审计固定对象分开；不把空资产当全账号 |
| RV4-09／P2 | 规则单元上限不足以约束预先构造的大笛卡尔积，云响应／并发预算失败处理仍需实测 | 19／21 增加预估溢出检查、有界逐段计算和解码前限额门槛；不以外层超时冒充底层取消 |
| RV4-10／P2 | 当前追溯主要到 AC-20，新增验收和前端异常状态缺少可检验落点 | 27 的完整追溯、v0.4 验证矩阵及设计示例检查覆盖全部 FR／NFR／AC 和 CR-1；不把映射存在当测试通过 |
| RV4-11／P1 | 统一建议字段默认强制策略目标，覆盖／组件评估无 ACL 时可能遗漏 FR-13 或伪造引用 | 18／19／03 采用 policy／coverage／component／confirmation 联合契约，所有类型保留条件与证据，不新增产品 API |
| RV4-12／P2 | NFR-06 要求 G2 明确环境、负载与阈值，但旧稿只有硬超时和未测容量 | 03 给出本地测试档位和待 G2 的完成／延迟／内存目标，强调不是云采购要求或实测性能 |

未重新打开已确认的需求范围。M1 日志增强仍可选且默认关闭；核心画像、条件化组件建议、有限出向／NAT 及持久会话／审阅均保留。
