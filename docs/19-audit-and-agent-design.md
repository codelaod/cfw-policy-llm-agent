## 1. 三类输出分工

1. **输入事实**：配置、标签、关联、保护状态、已确认业务要求及其来源／时点。安全组只是画像线索，不等于发现监听服务。
2. **规则结果**：在明确支持子域内计算配置语义、范围差异和覆盖缺口；保留原始发现、证据与未检查范围。
3. **模型内容**：角色候选、补查选择、条件解释和推荐；无依据时待确认。模型疑点不写成规则事实，也不能删除或修改原始规则输出。

只读 SDK 适配、纯规则内核与 Eino 编排分离；规则单测不需要云账号或模型。真实云采集由受控任务先建立快照，Agent 默认只读快照和固定业务版本。

## 2. 归一化与可支持子域

规范化策略至少保留边界／方向、身份、来源／目标类型与集合、协议、端口、动作、顺序、启用、时间及应用／域名等条件、引用与原始位置。

B0 的精确计算只涉及互联网入向、明确端点、IPv4、TCP／UDP、字面 IP／CIDR 和完整展开的静态 IP／端口引用。作用于本查询的应用／域名、动态引用、复杂时间或未知生效条件均不能丢掉后当作普通策略。

- IPv4 与 CIDR 转为有界区间并合并，端口转有效闭区间；厂商 ANY／空值哨兵按已核实字段映射，不猜测请求与响应同名字段的含义。
- 协议 ANY 在 TCP／UDP 查询中可以匹配，但原策略其他协议含义不能被缩成 TCP；结论始终说明只覆盖所选子域。
- 明确关闭的条目不作为生效匹配；启用未知、重复／缺失顺序或相关高级条件无法判断时保留不确定性。稳定 ID 排序不能用来编造同优先级的实际顺序。
- 观察 log 动作不等于 drop；B0 不对相关观察／高级条件给出完整有效路径推导，只标该查询超出支持。其他明确不相关规则不必拖累全部检查。
- 默认行为绑定 provider-semantics 版本和资料依据；阿里云互联网 ACL 的未命中允许不能套成安全组默认拒绝。导入声称与该 profile 矛盾的默认值时报告语义冲突，不静默改写。
- 原文和未支持字段保留在私有数据；只有已知与匹配无关的描述性字段可以不参与计算。

请求先固定范围、资料基版和数据策略；准备完成后，规则输入只封存一次 `snapshot / profile / intent / baseline / normalizer / kernel / provider_semantics` 版本及 `evaluation_at` 清单。例外按固定评估时点判定有效期；时点变化是新输入，不以未记录的当前时间产生不可复验结果。

## 3. 端点与三值首匹配

### 3.1 先确定比较对象

按账号／地域／资源身份和已知地址映射建立所审端点；同机多个地址／服务分开查询。未知代理／NAT 观察位置、无法归属的安全组或端点不能直接证明某项访问路径。

CFW 配置逻辑分析需要该对象的适用范围、保护状态及相关策略分区足够明确。关闭／切换／未知保护状态不能凭一份 ACL 列表说实际受保护；可保留静态配置观察与 CHK-05 的当前覆盖事实。

**配置逻辑允许／拒绝不是数据面实测**：API 中看到配置、开关开启或人工修改后重新采集，都不证明策略已下发、链路可达或业务恢复。结果使用快照时点和限制措辞，不将传播延迟当成自动修复成功。

### 3.2 匹配结果是 yes／no／unknown

对一个地址／端口单元，按已知策略顺序：

```text
for rule in 已采集的相关顺序:
    若明确禁用: 跳过
    match = 比较所有已知匹配维度及可支持条件
    若可证明不匹配: 继续
    若可能匹配但条件／状态／顺序不明: 返回 unknown 与原因
    若可证明匹配且动作支持: 返回 accept 或 drop 与路径证据
若没有匹配: 返回已核实的默认行为；未知则 unknown
```

如果策略分区漏页，未知规则可能更早匹配，不能仅因为已读到一条 accept 就给确定允许。若未知高级条件只存在于可证明不相关的规则，可跳过那条，而不必一概放弃全部事实检查。

### 3.3 区间划分，而不是随机探测

对于所审端点和 TCP／UDP，收集相关策略、业务集合与查询范围的地址／端口边界，划分为匹配结论一致的单元，逐单元首匹配并合并相邻同类结果。跨端点逐一处理，避免构造全网络拓扑。

这是支持子域内的集合运算，不是向主机发连接，也不通过几个样本地址声称穷尽全部空间。单查询单元上限暂定 50,000 作为设计防护：达到上限／超时则返回未穷尽范围与原因；没有发现不能算通过。已证明的一处违例可以保留，但必须注明未发现全部问题。

复杂度取决于端点、策略及边界数；不承诺在任意输入下都完整计算。实现时应先过滤明确不相交规则并复用解析结果；不得为了通过性能指标在未知处直接假定允许／拒绝。

## 4. M0 检查器如何使用内核

| 检查 | 计算／证据 | 降级或特别约束 |
| --- | --- | --- |
| CHK-01 管理来源 | 对明确管理服务计算配置允许来源与已确认允许集合之差 | 白名单未知只给业务待确认，CHK-07 可独立运行 |
| CHK-02 协议／端口 | 配置允许集合减去完整的业务允许上界 | 不完整列表不能把其余全判违规；TCP／UDP 外不作整体通过 |
| CHK-03 服务来源 | 按服务比较来源差异，保留相关引用 | 不把未知引用当空集合；与同问题的其他检查关联 |
| CHK-04 重复候选 | 完整匹配／生效／动作条件的规范化比较 | 身份、描述、位置单列为上下文；未知语义不宣称完全等价，不自动删除 |
| CHK-05 覆盖 | 保护适用范围／已采用要求与可信当前状态比较 | 不知道不等于未保护；该层关闭不等于所有防护缺失 |
| CHK-06 必要访问 | 支持范围内的必要访问与配置拒绝集合求交 | 私有／VPC 等超出所审边界的访问标不适用，不能证明实际故障 |
| CHK-07 宽泛来源 | 高风险端口上，由全地址条目或默认允许形成的未被完全覆盖的配置允许范围 | 只报明确剩余范围，不要求证明全部 IPv4 可达；没有 wildcard 路径不代表任意 CIDR 都合理 |
| CHK-08 角色差异 | 已确认数据库服务＋明确不需公网／限定访问的声明，再比较对应配置 | 角色本身不推导私网要求；同机 Web／其他服务独立，不误封必要访问 |

CHK-07 的证明示例：全地址 accept 被更高优先级全地址 drop 完全遮蔽则不成立；只有部分来源被 drop 时，报告剩余配置允许区间；没有显式 accept 也可能由未命中默认允许形成该路径。全地址来源可以由完整 IP 引用等价表达；未知引用不强行认定。

每项分别输出适用范围、`pass / fail / needs_confirmation / insufficient_data / unsupported / not_applicable`、覆盖／限额与证据。多个检查可以指向一个业务问题族，原始记录全部保留，主实验指标不重复计分。

## 5. 画像引导与审计 Agent

### 5.1 两种任务，共用能力而非多 Agent 平台

- `assistant_turn` 的画像引导场景从固定实例上下文、会话历史与已确认基版本开始，必要时查询关联组／引用；产生候选与缺项问题。用户回答继续同一业务会话，已确认事实和公共历史由应用持久化；若需模型整理，创建关联本轮的有界执行，不从零拼一次性问题，也不无限维持旧执行。
- `audit` 在已保存规则结果之上补查业务要求、策略／引用证据和判据，形成条件解释。细节不足时提出待确认，不强制凑出具体变更。

业务会话、可见消息、公开摘要、确认与任务／报告关系必须持久；ContextBuilder 组装获准历史，不能只发最后一句。完整 wire assistant／reasoning 仅在当前执行内保留，不把裁剪后孤立旧 tool 消息当合法历史回放。Eino Session Store 由业务实现，Checkpoint 与产品历史分开，详见 20。一次确认需服务端预览与基版本条件；模型没有确认工具。

### 5.2 B0 工具目录

| 工具 | 输入及返回 | 权限／边界 |
| --- | --- | --- |
| `get_asset_context` | 任务内资产别名 → 元数据、关联引用和证据／完整性 | 只读所选快照及获准字段，不暴露所有账号资产 |
| `get_security_group_rules` | 已关联组引用 → 方向／协议／端口／动作／来源及歧义 | 关联验证；共享组不是主机实际服务，不调用实时云 API |
| `get_business_intent` | 任务内业务引用／服务 → 已固定的确认内容或未声明状态 | 不取“最新”偷偷改变输入，也不生成白名单 |
| `get_policy` | 策略引用 → 规范化条件／原始证据位置 | 同快照且关联所审端点／发现的范围；快照中无关对象不自动获准，未知条件不得隐藏 |
| `resolve_reference` | 引用标识 → 已采集成员／完整性 | 不因模型请求扩大采集；不可展开时明确 unknown |
| `get_finding_evidence` | 原始发现编号 → 证据、相关策略／业务引用 | 不能覆盖发现或伪造新证据 |
| `get_rule_definition` | 已启用检查编号 → 当前基线版本的适用条件与禁止推断 | 只读，不能由模型修改判据或阈值 |

没有通用 shell、SQL、文件读取、任意 HTTP、云 RPC、写策略／标签／例外或确认授权工具。工具参数、对象存在性、归属关系和任务授权均由后端校验，不依赖提示词说“只能只读”。

### 5.3 真正的依赖补查案例

初始只给任务目标、有限资产／发现概况及资料是否可查，不一次性提供全部细节。代表案例让 `get_asset_context` 返回此前未知的关联组引用，再据该引用决定是否查规则；另一个案例因业务资料不存在停止具体建议。工具执行和结果回传必须记录真实 call ID，不用函数名代替同批多个调用 ID。

必须在所配真实服务上观察到“依据前次结果再发起后续工具查询”的路径后，才能声称该能力验收；不以脚本 fixture、提示强制顺序或批内执行先后冒充自主决策。现有 MiniMax 初测尚未覆盖，当前不追加真实请求。

### 5.4 推荐引导与专用认证

首次／续聊／失败的推荐短语由本地 GuidanceCatalog 提供，不额外调模型。模型可同轮返回受控追问，不能因此注册新动作或直接云写；Web／CLI／TUI 的同意图和确认契约见 22。Agent 工具仅获 QueryService，不持云／模型凭据；采集时 CloudCredentialProvider 对 CFW／ECS 复用明确身份，启动／环境／STS／MCP 边界见 21。

## 6. 协议与输出约束

首版仅接已配置的非流式 Chat Completions，复用固定 Eino 模型组件和应用 guard。OpenAI 官方工具调用指南是协议概念依据，不代表所有第三方支持相同能力；Chat Completions 的工具结果关联与 Responses 字段不混用。

保留用户当前模型配置，不把文档推荐模型替换进来。MiniMax 所需的完整 assistant 消息连续性按已验证路径在内存处理；`reasoning_split` 不被误当关闭思考。JSON 依靠 schema／本地校验，不预设原生 strict JSON Schema。截断、未知工具、非法 ID、越界参数或不合法最终结构均失败／降级，不静默换协议或无限重试。

角色输出至少含候选服务／角色、支持与反对证据、未知项和待确认问题；不能直接写 confirmed。审计推荐引用 `finding_id / rule_version / evidence_ids / business_ref`，用声明来源引用代替编造字面网段，并给条件／影响／人工复核动作。

校验顺序：严格结构与大小 → 对象／范围 → 版本／引用 → 业务约束 → 来源／建议目标。已确认来源、必要端口和明确禁止不能被输出扩大或抹掉。校验无法证明每句自然语言都正确，因此事实字段由服务端生成，模型正文作为独立解释／疑点，不改变规则结论。

## 7. 拟议预算与限额（不是当前授权）

以下是 G2 待审的工程默认上限，用于阻止无限执行；**不是模型服务费金额保证，也不授权现在按这些值发请求**。实际采用值取用户私有配置与项目上限中更严格者，不自动提高现有实验的次数／输出配置。

| 项目 | 设计默认 | 说明 |
| --- | --- | --- |
| 并行长任务／排队 | 1／10 | 前台优先、后台定时默认关；不代表业务只有一次性任务 |
| 助手轮次模型 HTTP／工具／执行时限 | 4／8／90 秒 | 连续会话内有界轮次，排队和总时限见 20 |
| 审计模型阶段 HTTP／工具／阶段时限 | 6／12／120 秒 | 这是模型阶段而非含采集的总任务上限 |
| audit 排队／执行／受理到结束 | 120／240／360 秒 | 执行内含认证／采集90、规则20、模型120、最终化10秒，子调用取根剩余值 |
| 模型单次时限／请求输出参数 | 最多 30 秒／最多 1024 | 当前私有配置若是 512 则保持 512，不在失败时自行抬高 |
| 模型请求／响应正文／单工具回复 | 128 KiB／256 KiB／32 KiB | 字节约束不冒充 tokenizer 或金额上限；截断必须明确 |
| 采集总 HTTP 尝试／阶段时限 | 100／90 秒 | 认证／凭据交换和退避也计时；并发独立读最多2，token依赖分页串行；权限错误不盲重试 |
| 每任务资产／CFW 策略 | 50／1000 | 输入硬保护，不是全量分析性能保证；超限标范围截断 |
| 确定性单查询单元 | 50,000 | 已证明违例可保留，未穷尽不得转为通过 |
| 普通 JSON／离线导入 | 1 MiB／5 MiB | 深度／数组／对象数另外校验，不解压任意文件 |

这些值是可调整设计假设，G2／工程验证时再核对目标机器和案例规模。执行预算、会话累计和应用限额分层取更严值，新建会话不清应用账本；仅执行次数仍不是全账户货币上限；界面和报告如实显示已用尝试及可得 usage，未返回用量保持未知。

工具内容过大时按结构化条目有界选择并标记未返回范围，或直接失败；不能生截 JSON 后冒充完整结果，也不能截掉未知条件后推导通过。

不得由模型、工具参数或错误重试自动扩额度。重复查询无新证据时有限停止；失败后重启不重放，用户显式重试为新任务。对方收到请求后是否计费只能以实际服务账单为准。

| 模型真实验收 | 在明确预算下测依赖查询、不同工具路径、缺资料、失败行为与结构化结果 | 不推广为所有模型／协议兼容 |
| 云端真实验收 | 必需查询、分页／字段、保护范围与资源关联，和控制台核对；无写操作 | 不把配置一致当数据面测试或整体合规 |
| 产品流程 | PRD UF-01～08／UX-01～08，人工回退、确认、计划、导出与复审 | 低保真测试不能替代正式 Web 功能测试 |

规则、固定模型流程和 Agent 比较固定事实集合、规则和预算上限，记录实际调用开销；全材料一次性 LLM 为独立参考条件。主指标按预标注业务问题族去重，规则级结果单列。模型可能不改善规则结果，仍如实报告误报漏报、错误断言和局限。

## 9. 仍需后续验证而非假定成立的事项

当前没有正式规则引擎、Web／任务持久化或数据库迁移；上述算法和防护尚未实际执行。现有 Go／Eino 试验只证明限定机制及两个小模型样例，不能代替这些测试。真实账号版本、SDK 字段映射、权限、完整性、模型连续链与新依赖构建在 G2 后分层验收，云安全中心和自动下发仍不在范围。

新增历史、数据策略、认证、纯 Go 存储和跨入口引导对应 RC-21～31／AC-15～20；固定 Eino／SDK／驱动版本的验证尚未执行，不以设计文本或供应商示例推导已通过。
