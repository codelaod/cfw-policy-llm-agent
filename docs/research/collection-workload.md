# 只读采集接口与工作负载依据

官方核读日期：2026-10-29；实现状态同步至2026-10-30。本文区分整改前观察、当前源码行为和条件方案，记录官方公开契约与工程取舍，供现行需求／设计引用；不是新增审批包、真实账号测试或性能验收。没有读取私有配置，没有调用云／模型接口，没有开通资源。官方来源索引见[W-01～W-14](../references/README.md#2026-10-29资源检索采集工作负载与工具边界)。

## 1. 先分开四种规模

资产数、策略条数、引用对象数和模型调用轮次分别计量。20台ECS共用一个云防火墙时，互联网同一方向通常读取同一个策略分区；其ACL数量可能是0、80或1000，不能由20台资产推出。资产可能分属多个地域、共用安全组、绑定多个地址。一个账号／云防火墙也不代表只存在一个互联网方向或一个NAT网关策略集。

首版继续采用一个Go进程、普通SQLite WAL、最多3个不同会话任务并进、云端只读和人工整改。资源目录是本地索引；云采集先形成不可变输入，规则先计算确定事实，Agent再对封存资料做有界补查、解释和条件推荐。无需为这条链新增SaaS、微服务、向量数据库或自研MCP服务。

### 2.1 RegionNo不能统一翻译成资产地域

`DescribeAssetList.RegionNo`官方说明为“云防火墙的地域ID”，而返回资产地域为`RegionID`；它不等于ECS查询的`RegionId`。`DescribeNatFirewallList.RegionNo`说明为VPC地域，返回字段为`RegionId`。SDK客户端的控制面Region／endpoint又是第三件事。相同字符串不构成相同语义证明。

现有资产采集刻意不向`DescribeAssetList`传资产地域作为`RegionNo`，而是在响应中核对`RegionID`。后续优化仍须保留这一点；若无法证明某筛选的语义，不用它制造“全部所选对象均不存在”的结论。操作的控制面、对象地域和返回owner分别校验。

### 2.2 完整分页与语义边界

- string计数先严格解析非负整数；缺字段、格式错误、总数变化、页重复、ID冲突、异常空页、token循环和触顶均不能变成完整空集。`TotalCount`是该查询结果数，不是资产数、ACL容量或整个账号已覆盖证明。
- 按页号的操作覆盖到可信总数，按token的操作跟到空token；任何一页失败保留已取得证据和受影响范围。不能“取前50条”后声称完整。
- 互联网每个所选方向／NAT每个选定网关均须保留所有相关动作、启用状态、顺序、地址／端口引用和高级条件。查询按某台IP过滤策略会丢失广域／地址簿／兜底规则，不能代替策略集全量。
- 官方匹配手册W-09说明优先级、默认放行、观察、应用识别与严格／宽松模式。规则不支持的条件标不支持或信息不足；`StrictMode=1`不能翻译成未命中默认拒绝。两轮一致也只是观察稳定，不能宣称原子快照或真实可达。
- CFW的资产接口展示公网资源视图，ECS是资源目录，NAT防火墙和VPC网关目录是不同对象；没有返回某台资产／网关不能直接证明云上不存在或没有防护。

## 3. 从自然语言到可执行选择器

可实现的链路是“本地目录检索→必要时有界发现→候选消歧→固定对象→准备数据→执行审计”。用户可给名称、ID、类型、地域、标签或已确认业务归属，无须先逐台填写管理员JSON。

1. 后端将输入解析为类型化选择器，保留原话与条件。限定已配置账号、允许地域、资源种类和边界；租户／客户名称只匹配有来源的已确认映射，不猜云标签或切账号。
2. 先查本地目录，以`provider/account/region/type/resource_id`识别资源。名称／标签只辅助查找；同名、多个地址、多个网关时展示少量可区分候选，不能自动选第一条。
3. 目录不足才准备有限地域、类型，以及名称／ID／标签或明确有限地域ECS集合的发现计划，并绑定页／对象／HTTP上限。接受计划后调用固定操作；候选发现只取元数据，不给每个候选完整读取策略和安全组。适配器核对允许的参数组合；已知ID可精确查询后再核对名称／标签条件，不假设所有过滤项都能任意组合或由厂商保证交集。
4. ECS按有限地域使用名称／标签检索；ID已知时用同地域`InstanceIds`批量核对。云防火墙按返回的稳定绑定关系合并保护视图；名称相似、同IP或同VPC不能独自完成强关联。
5. 达到发现上限时保留游标与覆盖范围，告诉用户“当前结果未穷尽，可缩小条件或继续有界查找”。未授权地域／账号、未知资源类型或未支持标签规模须明确提示，不静默扩大查询。
6. 单对象请求唯一且符合原选择器才固定计划；重名候选歧义先澄清，明确集合则核对完整成员和覆盖。执行确认绑定账号／地域／对象／分区、数据新鲜度和最大影响范围；预览本身零外呼。额外刷新若属于原已接受效果且未越预算，不再逐个API反复确认。

连接配置定义认证、账号和读取上界；目录保存可检索资源及来源；本次审计选择定义实际对象。三者分开。原始ID落在已授权范围内时，不因未预先写入静态资产清单就拒绝。反过来，账号可读全量也不等于本次计划可以扫描全账号。

## 4. RAM与数据范围

官方操作页逐项列RAM action、资源类型和条件键。CFW资产／地址簿的授权表包含`*All Resource`；互联网策略、NAT策略与NAT防火墙表列各自资源类型。策略的ACL资源标识、NAT防火墙的`ProxyId`和请求`NatGatewayId`不是同一种标识，不能把查询参数存在写成已经实现逐网关RAM隔离。列表读往往需要资源模式，应在只读动作和账号边界内明确说明，真实授权策略与列表完整性仍须账号验证。

每次计划以预期账号核验、应用允许地域／类型／选择器、固定只读操作和返回身份共同约束；不传`MemberUid`跨owner，不读机器profile，不让模型提供RPC／URL／RAM action。`GetCallerIdentity`只核身份，不证明CFW／ECS权限或产品就绪；权限错误不能变成空目录。当前env_ak／env_sts静态Provider不产生自动角色续期流量，若未来加入交换或重试，每次物理HTTP都须计入同一账本。

## 5. 可复核请求量模型

记号如下；所有页数均为实际查询／分页的页数，可信空集仍至少请求一页。

| 量 | 含义 |
| --- | --- |
| `A` | 本次选中资产数 |
| `D` | 必要的目录发现物理请求数；本地目录命中为0，单次有限地域名称检索可为1，但不是保证 |
| `I` | 新云执行的身份请求数；示例为1，纯缓存复用且无云读取为0 |
| `c_i` | 当前逐资产CFW资产查询的页数；可能多于1，因为一台ECS可关联多个公网资源 |
| `e_i` | 整改前逐资产ECS查询的页数 |
| `S_i`、`s_g` | 实例i关联组集合、组g完整双方向规则的页数 |
| `C` | 优化后、已授权CFW资产切片的总页数；若只允许逐ID查询，仍为`Σc_i` |
| `E` | 同地域分批ECS查询的总页数；20个ID同地域、每页至少20且实际一页时为1；多地域分别相加，token有续页仍须继续 |
| `G` | 账号／地域／ID去重后的安全组集合，SG读为`Σ(g∈G)s_g` |
| `P` | 所选互联网方向或NAT网关的ACL页数，与A无直接等号 |
| `B` | 本轮唯一必需静态引用的查询页数之和；NAT可信完整内联成员可减少它，模糊名称匹配可增加它 |
| `N` | 指定NAT防火墙元数据页数，单网关正常命中时示例为1 |
| `X`、`R` | 显式凭据交换请求、实际重试请求；当前静态凭据且无失败的示例均为0 |

2026-10-29整改前每轮对每资产分别读取`DescribeAssetList`、`DescribeInstances`和关联安全组，SG仅在单资产内去重；ACL与引用当时已共享。2026-10-30当前实现已按地域批量ECS、跨资产按地域／组ID去重SG，CFW仍按已选ID读取，ACL和引用继续每轮共享。下式第一行为历史成本，第二行在`C=Σc_i`时对应当前基本路线；CFW获准切片一次枚举关联仍只是条件方案，不当作已交付。两轮观察均保留。

```text
Q_legacy_per_asset = I + D + 2 × [Σ_i c_i + Σ_i e_i + Σ_i Σ_(g∈S_i) s_g + P + B] + X + R

Q_batched_internet = I + D + 2 × [C + E + Σ_(g∈G) s_g + P + B] + X + R

Q_batched_nat_assets = I + D + 2 × [N + E + Σ_(g∈G) s_g + P + B] + X + R

Q_nat_gateway_only = I + D + 2 × [N + P + B] + X + R
```

`2×`保留现行真实刷新两轮观察的保证；优化的是每轮内部重复，不把第二轮删掉。第一轮出现失败、变化或第二轮预算不足时可能提前终止，不能将较小的实际请求数写成完整任务成功。

### 5.1 20资产、同一CFW的人工算例

以下全为**合成工作负载，未观测任何真实账号**：20台同地域ECS，每台关联1个SG；20次CFW精确资产查询和20次单ID ECS查询均各一页；策略80条，项目profile每页50，故`P=2`；3个必要静态引用各一页，故`B=3`；`I=1,D=X=R=0`。共享组算例共4个SG，每组20条双方向规则，一页可读完。优化后的CFW切片算例包含40条公网资产，恰一页；这40条数据必须在计划读取范围内。

| 路线 | 每轮请求算式 | 两轮加身份 | 条件与含义 |
| --- | --- | --- | --- |
| 整改前逐资产 | `20+20+20+2+3=65` | **131** | 共享组逐资产重读；历史100次暂值无法完成此工作负载 |
| 批量ECS＋SG去重，CFW仍逐ID | `20+1+4+2+3=30` | **61** | 无需扩大CFW资产读取范围即可减少重复 |
| 再复用获准的CFW资产切片 | `1+1+4+2+3=11` | **23** | 不是CFW新增批量ID接口；是一次完整枚举获准切片后本地关联 |
| 20个不同SG的对照 | `1+1+20+2+3=27` | **55** | 资产数相同，组分布不同使成本上升 |
| 策略1000条／12个引用的对照 | `1+1+4+20+12=38` | **77** | 同20资产、同4共享SG，ACL／引用规模仍可主导成本 |

不能为得到23而无条件取消CFW筛选或整账号拉取：若本次只准读取20个ID，采用61的路线；若被允许的公网切片实际有更多页，代入真实`C`，不能按20／50硬算一页。当前collector及API已实现ECS批量和跨资产SG去重，合格不可变缓存也已接入；第二行61次已由20资产签名loopback路径限定取证。获准CFW切片关联尚未实现，后三行仍为条件式人工算例，不能把23次当作当前默认请求量。限定证据见[现行代码记录](../validation/evidence/conversation-implementation-local.md)。

若目录首次查询需要1次，则相应总量加1；如果20台跨3地域，ECS至少按3地域分批；如果4个SG各有120条且仍每页50，SG页数为12，23增为39。互联网入向、互联网出向、不同NAT网关分别计量策略分区，不能用“同一个防火墙”合并它们的ACL。共享资产元数据能否跨任务复用，另按合格缓存条件核验。

### 5.2 费用与耗时只作公式和敏感性情景

当前没有真实RTT、限流等待、页分布、模型轮次或token测量，因此不能回答“20台实际需要N秒”。API文档的QPS／速率限制是吞吐约束，不能当成请求RTT。当前90秒／100次以及30秒／4或6次等是历史工程暂值，不能写成供应商SLA或永久产品上限，也不能仅为通过示例就放大私有授权额度。

```text
T_collect = T_queue + T_identity + T_round1 + T_round2
            + T_normalize + T_persist + T_backoff

串行、每请求耗时相同的敏感性简化：T_cloud = Q × r

T_total = T_collect + T_rules + Σ_j T_model(j) + Σ_k T_local_tool(k) + T_report
```

下表仅将人工`r=0.1/0.3/1.0秒`代入`Q×r`；这些r不是任何实测、供应商承诺或推荐超时，也未计排队／规则／模型／持久化／退避。

| 合成请求量 | r=0.1秒 | r=0.3秒 | r=1.0秒 |
| --- | --- | --- | --- |
| 131 | 13.1秒 | 39.3秒 | 131秒 |
| 61 | 6.1秒 | 18.3秒 | 61秒 |
| 23 | 2.3秒 | 6.9秒 | 23秒 |
| 55 | 5.5秒 | 16.5秒 | 55秒 |
| 77 | 7.7秒 | 23.1秒 | 77秒 |

同一轮内批量ECS、去重后不同SG等依赖满足后可有限并行，但token链、引用发现及两轮屏障仍有顺序；不能简单用`Q/3`预报时间。3会话共用外呼准入、剩余额度与限流；并发本身不产生三份授权。先减少重复再决定小规模并行，SQLite事务不跨网络等待。

模型费用按真实服务计价与已报告输入／输出token累计；缺usage记录未知，不由文件字节或请求次数推算账单。可预处理字段投影、规则事实和证据索引，但不把整份云原文／每台资产全部ACL反复发送给模型；模型调用次数也不等于资产数。真实校准须记录分阶段耗时、终态、页数、字节、物理尝试、缓存命中、token已知／未知和相同输入下的模型轮次；在明确后续云／模型授权范围内进行。

## 6. 刷新、缓存与定时的取舍

| 方式 | 合理用途 | 必须保持的边界 |
| --- | --- | --- |
| 按需冷刷新 | 首次无数据、资料过时、人工整改后的复审 | 两轮完整配置族；相同owner／选择器／分区；不足降级，不能隐式扩页／扩权 |
| 合格缓存复用 | 用户允许当前观察时点，目录、配置族和输入覆盖满足任务 | 真实云HTTP可为0；保留原采集窗口、完整性、一致性、normalizer／schema／语义profile和实际读取清单，不以新snapshot时间续鲜 |
| 部分族需要刷新 | 目录新鲜而策略旧，或新增对象／组关联 | 按独立数据族时点、范围及依赖核验；所需关联变化必须刷新并重建绑定；不能只检查ACL首页来冒充整个族未变 |
| 同进程共享刷新 | 多会话同时需要相同账号、选择器、配置族与版本 | 可在授权一致时合并同一刷新、各自封存输入；不共用模型上下文、业务确认或任务取消；不是首版必须新增的复杂调度器 |
| 可选定时采集 | 用户明确授权固定范围／周期／额度，减少交互时等待 | 默认关闭；预取仍花云请求并占共享预算；保留每族时点，服务重启不重放未结束调用；定时不等于自动审计或自动整改 |

缓存键不能只有资产ID或“最近一份”：至少绑定账号、规范分区／网关／方向／地址族、对象选择与覆盖、配置／适配／归一化版本、采集窗口和引用／关联闭合。目录缓存与策略、保护、SG数据族分开判断；权限收紧、scope版本变化、已知变更或不完整缓存不能满足强时效审计。只复用获准字段投影，不能把更宽快照的全部资产交给模型。结果复用还需核对画像／意图／规则版本，不因云配置相同而套用旧业务结论。

规则在本地从固定输入先计算公网暴露、确定重复／冲突等可支持事实；Agent围绕发现取证据、解释未知、提出需确认的角色和访问要求。固定资料工具只查同一输入，不通过工具调用实时刷新云数据；若缺资料，返回缺项并由计划链准备获准的新快照。这样保留真实的有界工具决策，同时不把资料准备委托给模型自由循环。

## 7. Eino函数工具与MCP

Eino v0.9.22已有`BaseTool.Info`、`InvokableTool.InvokableRun`、`ToolsNode`以及`utils.InferTool/NewTool`。当前`agentrun/runner.go`的`queryTool`已实现前两者，并通过`ChatModelAgent`运行固定领域工具。官方W-10解释该组件和JSON schema；W-11提供现成MCP工具适配，不需要为“支持Agent”重写协议。该README示例仍使用旧SSE，项目没有锁定／安装该MCP依赖；未来采用前另验所选版本与stdio／Streamable HTTP兼容。

| 路线 | 必要工作 | 首版取舍 |
| --- | --- | --- |
| 同进程Eino函数工具 | 固定schema、参数范围、任务上下文、证据引用、结果投影、时间／轮次／用量限制及事件持久化 | 继续采用；复用现有Runner与Query层，业务权限不能只靠提示词 |
| Eino现成MCP客户端接外部工具 | 额外服务／进程生命周期、连接、协议与工具发现、身份与输出信任、故障与取消；可用现成适配器 | 有明确外部复用需求时再评估，不是当前缺口的前置条件 |
| 自建MCP server再从同Go进程调用 | 在同样业务工具外新增协议封装、随选定版本的发现／初始化／能力协商、`tools/list`／`tools/call`、传输、部署和兼容测试；HTTP还增加授权边界 | 当前没有跨客户端复用需求证据；保留备选，不为单Web入口和3会话提前引入 |

W-12的固定2025-11-25工具规范、W-13的传输规范说明的是互操作接口。W-14当前架构入口已跳转2026-07-28版本，其发现机制与2025固定规范不同，不能拼成一套已兼容实现。MCP不规定模型编排，不负责云RAM范围、共享预算、领域证据、持久会话或结果正确性，也不替代模型供应商的工具schema。函数工具与MCP都需要这些业务控制；MCP不自动让工具更安全／智能，也不减少CFW分页或模型token。未来要给外部客户端提供领域工具时，在已稳定Query层外加协议适配，复用同一业务逻辑、API与合格缓存，保留单Go和现有业务Store，不建设两套domain实现。

## 8. 当前实现差异与可离线推进的验证

2026-10-29曾发现静态资产预列、单资产ECS请求、SG未跨资产去重及元数据／SG未进入固定输入等缺口。截至2026-10-30，正式对话已接来源隔离目录／消歧、有限发现、同audit准备／晚封存、ECS批量／SG去重、结构化固定资料及合格复用；普通对象不要求管理员逐台预配。CFW仍按选定ID的SearchItem／IPv4读取，未实现通用获准切片关联；DescribeNetworkInterfaces、真实账号字段／权限和性能也未验收。当前逐项状态见[实现台账](../development/implementation-gap.md)，实际限定结果见[代码证据](../validation/evidence/conversation-implementation-local.md)，不把历史缺口重述为当前未实现。

现有人工离线回归覆盖了以下主题的限定路径，完整组合仍按现行台账验收：选择器映射与同名消歧fixture；多地域批量ID与缺失ID；共享SG去重且关联保留；所有数据族空集／缺页／总数变化／token循环；20资产上述请求数人工fixture；两轮配置变更；缓存范围／时点／版本／权限不合格；取消与3会话共用账本；模型只读投影和外部名称／标签注入防御。达到上限的例子应验证“未穷尽／信息不足”，不能为了展示成功截断数据。

真实账号后续另验权限、筛选实际语义、字段与产品适用性、所有页完整性、阶段耗时和至少一次人工整改后重采集复审；这些不可由人工HTTP响应或公式替代。公开HTTP文档能证明可设计，不能证明本账号已配置、已授权或已通过业务验收。
