## 1. 接不接计算与网络 API

用户已明确不接入云安全中心；画像使用已有 ECS／安全组上下文并经用户确认。建议采用“云防火墙核心采集 + ECS 最小上下文 + 网络关联按需补查”，而不是“完全不接”与“接入所有云产品”二选一。该最小采集路线已随整体G2确认；实际账号能力仍待验证，首版只读边界不变。

| 方案 | 可以支撑 | 局限与成本 | 评估 |
| --- | --- | --- | --- |
| 仅离线快照 | 规则开发、Agent 工具流程与重复实验 | 不能证明真实只读接入成功 | 必须保留，不作为唯一最终验证 |
| 云防火墙 API | 资产视图、保护状态、策略及引用对象的配置审计 | 不能预设完整替代 ECS 资产元数据；其他访问控制层不可见 | 首版核心 |
| 云防火墙 + ECS/安全组 | 关联实例、地址、标签、安全组，补充配置上下文 | 多一层权限、分页和安全组语义；不自动获得真实可达性结论 | 优先建议 |
| 再加有限 EIP/网卡查询 | 在已有数据不足时补公网 IP 与资产关联 | 具体绑定模式、地域与间接关联需验证 | 按案例需要增加 |
| 全量 VPC/路由/NAT/负载均衡/日志 | 可以支持更广的配置与路径研究 | 数据、语义、费用与实验范围明显增加，仍不等于运行时可达性 | 暂不纳入首版 |

读取安全组可先用于上下文展示和有限检查；在多安全组、前缀列表、源安全组引用等语义未支持前，不能把跨层结果称为完整路径验证。

## 2. 候选 API 与输入映射

以下为公开接口文档中的名称与字段，**不是已完成的采集器或最终数据库 schema**。示例字段只列与审计相关部分，实际响应、分页与账号版本仍需验证。

| 对象 | 官方接口与资料 | 已核对的相关信息 | 需要验证/实现的内容 |
| --- | --- | --- | --- |
| 云防火墙资产 | `DescribeAssetList`，A-02 | `ResourceInstanceId`、`BindInstanceId`、`InternetAddress`、`RegionID`、`ProtectStatus`、`TotalCount` 等 | 资源 ID 与绑定实例的语义；当前账号视图、过滤条件、支持状态、分页及 ECS/EIP 关联 |
| 互联网边界策略 | `DescribeControlPolicy`，A-03 | `AclUuid`、`Direction`、`Order`、`Release`、`SourceType`、`DestinationType`、`Proto`、`AclAction`、`ApplicationNameList`、端口/地址簿信息、`HitTimes` 与总数 | `Order` 越小优先级越高；`Release` 为字符串状态；不能混用请求与响应字段或假定全部数值都是整数 |
| 地址/端口引用 | `DescribeAddressBook`，A-07 | 引用对象标识、`GroupType`、成员、成员数量、动态标签相关信息 | 识别 IP、端口、域名、标签等类型；固定时点的成员展开；未解析对象不能当成空集合 |
| ECS 资产 | `DescribeInstances`，A-11 | 实例标识、`SecurityGroupIds`、`PublicIpAddress`、`EipAddress`、网卡相关信息等 | 明确地域范围和分页方式；优先用稳定资源标识关联，不只按 IP；先利用已返回的 EIP/网卡信息 |
| 安全组规则 | `DescribeSecurityGroupAttribute`，A-12 | 方向、`IpProtocol`、`PortRange`、`Policy`、`Priority`、源/目标 CIDR、组/前缀引用等 | 先读取已关联安全组；与 CFW 分开归一化；多个安全组、默认行为与有状态语义需另行核实 |
| EIP 关联 | `DescribeEipAddresses`，A-13 | 公网地址、实例类型与实例/网卡等关联线索 | 资料归档的是旧版官方入口；实施前核对当前 OpenAPI/SDK、地域与绑定模式，不默认直接绑定 ECS |

云防火墙 API 概览（A-06）还包含 NAT、VPC 等其他边界接口，不能把它们当作互联网边界接口的同义词。本次未定位并验证互联网 ACL 引擎模式的完整只读采集路径；可先保留人工填写或未知状态，不编造接口名。

### 2.1 语言相关 SDK 路线

阿里云官方已有Go云防火墙、Go ECS和Python SDK仓库入口（A-14～A-16），初始调研只核对仓库入口。选择Go不代表需要自行实现签名，也不能将整套SDK方法暴露给Agent；适配仍只采用允许的只读接口并核对凭据链与版本兼容。

当前正式`server/go.mod`已锁定CFW v11伪版本`v11.1.1-0.20261009173233-c44859c166b7`及Eino v0.9.22，已有E4限定离线适配证据；ECS／STS走通用OpenAPI，未单独依赖生成ECS SDK。2026-10-29又只读核对本机缓存的固定CFW字段模型和WithContext路线，仍不代表真实账号接口已验收。

### 2.2 自动画像线索：文档可得性与业务流程

2026-10-22公开文档核对：A-11返回名称、标签、系统和关联安全组／网卡等，A-12返回安全组方向、协议、目的端口、动作、优先级和来源／引用；2026-10-29又核对当前操作页。关联不足时才按所选资源补A-27。字段可作为模型的角色线索，但无标准“业务角色”字段保证，不能证明服务监听或业务授权。

流程为自动展示证据→模型提出候选／不确定性→对话或表单补缺项→预览差异→用户确认本地画像／访问要求。只读API不负责写回用户确认，系统不回写云标签或安全组。多组、共享组、多网卡、ALL协议和未解析引用均保留歧义，不能只按端口数字贴标签。

不接入云安全中心、不安装主机客户端、不主动扫描。已核对文档和人工传输fixture不等于画像业务输入链完成；权限、分页、地域／资源关联仍须真实验收。产品路径见[PRD](../requirements/product.md)。

### 2.3 资源检索不是管理员静态资产清单

ECS `DescribeInstances`可在指定地域按名称通配、ID、标签检索，已知ID最多100个同地域批量核对，token分页`MaxResults`最大100。名称不是唯一标识，标签无标准业务角色语义；单标签／标签交集过滤存在1000结果限制，达到边界应缩小条件或明确评审`ListTagResources`适配，不声称无限检索。CFW `DescribeAssetList.SearchItem`仅承诺IP／实例ID，不能把ECS名称／标签直接塞入该字段；其`ResourceType`是公网资源类型枚举，也不等于ECS实例规格。

后端先用本地目录定位，目录不足时准备有限地域／类型／名称或ID的发现计划；用户接受后执行，候选歧义先消歧，再固定对象审计。目录保存账号／地域／类型／ID、名称／标签、来源、时点和覆盖；连接配置只给认证与读取上界，可选资产allowlist进一步收紧，本次审计对象另行固定。发现先取元数据，不给所有候选逐台读完整策略和安全组。详见[选择器映射](collection-workload.md#3-从自然语言到可执行选择器)。

### 2.4 分页／共享读取决定成本

20台资产不是20套ACL：互联网按方向共用策略分区，NAT按选定网关分区。2026-10-29整改前ACL与引用已每轮共享，ECS仍逐资产读取、SG未跨资产去重；截至2026-10-30正式代码已按地域批量ECS、按地域／组ID跨资产去重SG，20资产基本路线有61次签名loopback限定证据，详见[当前代码结果](../validation/evidence/conversation-implementation-local.md)。CFW资产接口没有批量ID数组，只有获准读取的切片才能枚举一次后本地关联，不能为省请求静默扫描整个账号。

CFW资产／互联网ACL／NAT ACL的公开页没有明文PageSize最大值；项目50是适配暂值。地址簿每页1～50、NAT防火墙元数据最大50；ECS实例MaxResults最大100，SG为10～1000。CFW资产和NAT元数据的TotalCount是integer，其余上述CFW列表计数为string；RegionNo在资产接口与NAT元数据接口的说明不同，均不能不加区分地代入ECS地域。逐项契约、请求算式与**仅模拟**的时间敏感性表见[工作负载第2／5节](collection-workload.md)。

## 3. 官方用户文档对规则设计的约束

### 3.1 默认行为与顺序

官方策略原理说明：按优先级匹配；未命中全部已配置策略时默认放行。接口文档中 `Order` 数字越小优先级越高（A-03、A-08）。

因此：

- 缩小某条允许规则的来源，不足以证明其他来源已被拒绝。
- 不能只看一条低优先级允许规则就断定实际访问路径。
- 推荐需要说明单条修改还是配套修改，并检查其他规则、兜底与业务影响。
- 不把观察动作无条件当作拒绝；精确行为在支持矩阵与真实验证中明确。

### 3.2 匹配条件不只有地址与端口

官方文档还讨论应用、域名与严格/宽松 ACL 模式（A-05、A-08、A-09）。

建议初始开发用已明确的直接 CIDR、协议、端口、方向、动作、顺序和启用状态场景。对域名、应用识别、地理区域、动态组、生效时间、IPv6 等未支持语义，保留原字段并标记，不把未知条件丢弃后给确定结论。

### 3.3 保护状态、命中与运行时可达性

- `ProtectStatus` 文档区分保护中、开启中、未保护、关闭中；接口失败或资产未返回不能直接变成“未保护”。
- `HitTimes` 文档存在不代表长期流量日志完整，也未在本轮核实计数窗口和重置规则；不按零命中自动推荐删除。
- 云防火墙配置允许，不代表安全组、主机防火墙、监听服务、路由等全部放行。
- 引入 ECS/安全组后仍只能在已支持条件下作配置层判断；实际可达需要额外证据与明确授权的测试。

## 4. 数据、权限与采集完整性

推荐实现原则：

1. **后端受控采集**：明确允许的读接口、账号、地域、资源范围和参数；不向 Agent 开放任意 API 名、任意 URL 或任意 SDK 方法。
2. **最小权限**：根据 API 授权信息逐项配置实际需要的 RAM 权限并验证。不为方便直接授予全权限；“名称以 Describe 开头”不能替代授权核对。
3. **凭据隔离**：云凭据与模型凭据留在后端/本地私有配置；公开事件、报告和前端不携带密钥。
4. **分页与失败记录**：记录请求参数、页数、总数、去重、限流、错误和缺失字段。总数或分页信息不一致时标为部分采集。
5. **来源与版本**：每个对象保留原始位置、采集时间、归一化版本和证据引用；不同产品采集有时间差，不声称天然原子快照。
6. **身份与关联**：以账号/地域/资源 ID 为主要关联依据，公网 IP 作为证据之一；关联失败显示原因，不凭名称相似强连。
7. **统一输入**：真实采集与离线样例通过同一归一化服务供规则和工具使用。人工构造数据必须标明来源。
8. **外部文本不可信**：标签、资源名、策略描述都是数据，不得改变提示词、工具范围或模型预算。

本节是设计要求，不代表本项目已实现这些控制。

## 5. 不建议由 Agent 随意实时查询所有产品

推荐基本采集先由受控流程建立快照，再由 Agent 根据疑点选择 `get_asset`、`get_business_intent`、`get_policy`、`resolve_address_reference` 等领域工具。

当前固定资料工具只读本次封存输入，缺资料返回缺项；必要云刷新由同一已接受意图的有界计划链执行并生成新证据／时间标记，不能让模型任意实时调用产品API。规则先计算确定事实，模型读取投影后的对象／发现／引用，避免反复发送每台资产的整套ACL。基线与Agent实验使用相同事实集合、快照、工具条件和预算，避免实时数据漂移影响比较。

这既能体现 Agent 的补查决策，也能限制云 API 次数、账号权限和运行成本。只读不等于无数据泄露风险，工具输出与日志仍需脱敏。

Eino已支持同进程函数工具，当前Query层与Runner已有实际适配；首版无需为此自建MCP服务。MCP是host／client／server上下文互操作协议，未来明确需要跨客户端复用时，可在同一领域Query层外加现成适配；它仍需额外处理版本／传输／认证／取消／错误计数，不能替代云RAM、业务范围或模型工具schema。备选及来源见[工作负载第7节](collection-workload.md#7-eino函数工具与mcp)。

## 7. 下载、联网与 token 的关系

下载文件到磁盘本身，不等于把文件全文输入模型；但将文件内容、检索片段或工具结果送进模型上下文仍会占用相应用量。在线阅读也同样需要处理返回内容；不能承诺本地或联网方式一定免费、一定更省。

建议使用：

```text
官方索引与来源清单
        ↓
只下载当前范围相关的页面
        ↓
去导航、去脚本，保留正文和原始来源
        ↓
本地关键词检索，只读取需要的字段/段落
        ↓
在需要时重新打开官方页面核对更新
```

不要每轮把全部 HTML、PDF 或近十万字符正文送入模型；也暂不因此引入向量数据库。具体上下文、缓存和检索计费以所用模型服务/平台为准，不能用文件字节数直接换算 token 或账单。

## 8. 资料缺口与后续验证安排

- G2已经通过；2026-10-29在现行设计和实施计划中整改资源解析、自动证据、配置来源与缓存，不重开整体审批，也不把全部资料接口变成首版功能。
- 系统设计已形成必需字段、最小只读范围和关联规则提案；影响已选能力的资料缺口在设计审核前补齐或明确降级。
- 真实账号版本、权限、分页和资产关联在批准的后续只读集成阶段验收，不要求在需求审核前真实调用；尚未验收的能力不写成已验证。
- 新的模型／云端验证不是当前自动执行任务；涉及预算、真实数据和权限时保持既有授权边界。
- 真实资源开通、日志开启、策略应用与费用支出不由本份资料调研授权；该资料记录未进行这些操作。

| 数据族 | 当前可核实依据 | 尚需核实与权限边界 |
| --- | --- | --- |
| 互联网出向 ACL | `DescribeControlPolicy` 的 `Direction` 支持 `in/out`；请求与响应的方向必须保留 | 按方向独立分页／计数、动作／状态／顺序／引用、默认行为；已有E4人工fixture适配证据，账号实际响应与完整性未验收 |
| NAT 边界 ACL | 官方产品文档按 NAT 网关选择规则，说明源／目标／端口／动作／优先级／状态和引擎模式 | 现已核实当前 DescribeNatFirewallControlPolicy／DescribeNatFirewallList 的公开契约及官方 SDK 类型；真实响应／账号能力／默认 profile 与权限仍需验收，详见[云采集设计](../design/aliyun-collector.md) |
| NAT 保护与资产关联 | 需要可定位的网关、防火墙、资产和观察点上下文 | CFW 信息不足时，再评审最小网络查询权限；不得自动读取其他账号 profile 或补开产品 |
| SNAT／DNAT 资料 | 与防火墙 ACL 分开；当前仅建议保留显式来源的关联资料 | G2已明确仅保留有来源的关联上下文，默认不新增转换表查询；真实字段／观察时点需核实，不声明全转换审计或实际可达性 |

每族数据独立记录时间、来源、完整性、失败／未纳入状态；资料不足降级为未知，不以网络调研替代真实接口验收。外部查询仍须既定授权，不因 CR-1 自动调用。

## 10. 公开契约依据与适配设计

当前NAT只读适配选择、未核实接口排除、字符串／整数分页差异、Policys集合、ProxyStatus／StrictMode与WithContext源码路线见[云采集设计](../design/aliyun-collector.md)；T-01～T-06见[清单](../references/b2-technical-design/2026-10-26/manifest.json)。公开文档／源码、E4编译与人工fixture协议证据分别保留边界，均不等于实际账号查询成功；2026-10-29的工作负载核对不重新改写旧证据日期。
