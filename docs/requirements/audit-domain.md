# 云防火墙审计领域需求

基线：需求v0.6／B2、设计v0.6，G1／G2已通过。本文为业务对象与判定边界；实际运行验收另行取证。2026-10-29将第9节整轮审计会话与[客户旅程目录](customer-journeys.json)对齐，明确正常／异常／恢复分支；正式主链已有有限人工输入下的代码与本机结果，完整客户分支及真实接入仍待验收，原型实际可观察范围另见其说明，不能用局部规则与协议测试代替产品验收。

## 1. 要解决的业务问题

审计回答的是：“在给定采集范围、时点、支持语义与明确业务要求下，哪些配置不一致或存在可解释风险，哪些信息还不足，以及建议成立需要哪些条件？”

不回答：“互联网到主机服务是否一定实际可达”“本账号是否整体合规”“某条零命中策略是否一定无用”。云防火墙只是访问控制链路的一部分，快照也不等于运行时连接验证。

## 2. 最小领域词汇与信息要求

下表是信息需求，不是数据表设计；允许实际接口使用不同字段名，但不得丢失影响结论的信息。

| 对象 | 审计需要的信息 | 缺失的影响 |
| --- | --- | --- |
| 资产 | 云平台、账号／地域／资源类型／原ID、名称／标签等有来源线索、公网地址、用途、关联证据和保护状态 | 无法可靠关联时，不将相似名称或相同标签当同一资产 |
| 策略 | 所属边界与方向、原始标识、来源与目标、协议、端口、动作、顺序、启用状态、有效期、应用等条件与引用 | 不允许解析时静默抛掉条件，继而当成简单四元组策略 |
| 引用对象 | 引用类型、原始标识、成员、采集时间及展开完整性 | 未解析不等于空集合，也不等于全部地址 |
| 业务访问要求 | 适用资产、必要访问、允许来源／协议／端口、集合是否完整、管理来源、例外及有效期、声明人／来源与版本 | 未声明不等于禁止；未声明的管理来源不能由模型填充 |
| 审计输入 | 来源、范围、采集窗口、分页／失败、对象版本及默认行为／相关模式的已知程度 | 数据不完整时，只能保留有依据的局部事实，不能给“全部通过” |
| 证据 | 对象与版本、字段／结果位置、来源及时间；公开数据另有脱敏映射 | 不可定位的信息不能支撑确定性推荐 |
| 发现／推荐 | 检查判据、对象、状态、严重程度与依据、证据、修改对象、成立条件及影响 | 缺少事实或业务约束时保留待确认，不强行凑可执行配置 |
| 资产画像 | 角色与服务、应用、环境、重要性、来源、确认状态及版本，允许多角色 | 名称、标签、关联安全组端口、日志和模型可生成候选，但不自动成为业务授权；未知不停止通用基线 |
| 防护能力 | 具体组件、所覆盖对象／链路、状态及采集／人工确认来源，适用目标与例外 | 单层关闭不等于所有防护缺失；未知状态不判未部署 |
| 日志摘要（M1） | 类型、事件窗口、过滤／采样／缺段、查询条件、标识映射及时间版本 | 零记录不能单独判日志关闭、策略无用或资产安全 |

“业务访问要求”（既有字段中也称业务意图）指具体服务的允许／必要访问、保护目标与例外。“对话任务意图”另指用户这次要审计、解释、查看状态、取消或复审什么对象、边界和时点，两者必须分开：选择某台资产不能确认其访问授权，提出一次审计也不能确认画像。策略描述、资源标签仅为上下文，不天然是经批准的业务要求，也不是系统指令。

## 3. 产品语义依据与项目判断的区分

原始资料编号均可在 [参考资料索引](../references/README.md) 定位；已有正文可在 [离线参考资料](../references/README.md) 查阅。

| 依据 | 核实到的产品事实 | 本项目的需求约束 |
| --- | --- | --- |
| A-03 策略查询 | 提供方向、动作、启用状态、顺序及有效期等信息；列表有分页 | 这些因素及采集完整性不能在归一化／审计中丢失 |
| A-08 匹配原理 | 按顺序匹配；所有策略均未命中时默认放行；存在应用等额外条件 | 不能只看单条允许规则，不能把“没有放行规则”理解为拒绝 |

| A-17／18／19／20 保护与日志 | 防护开关、IPS 模式和日志类别含义不同 | 状态、覆盖和观测完整性独立记录，不用空日志替代开关证据 |
| A-11／12／27、A-24、I-01 资产上下文 | ECS 元数据、标签与已关联安全组配置可读，分组／标签方法可借鉴 | 自动线索支持角色推断与引导确认，不依赖云安全中心；端口不证明运行服务或访问授权 |
| B-01～04 安全指南／控制 | 最小必要访问、策略维护、日志审计与高风险公开等主题 | 作为原则／主题依据，经项目映射和用户审核后使用，不直接继承跨云语义或整体认证 |

## 4. 原 B1 语义细化与通用判定约束

### 4.1 原 B1 语义支持矩阵

本表保留原 B1 入向语义细化；B2 的当前范围为入向＋有限出向＋NAT ACL，新增边界约束见第 8 节。不能用原 B1 的边界限制排除 B2 已确认目标；具体支持矩阵见已批准的审计设计。

| 维度 | 建议首版精确检查的子集 | 其他情况如何处理 |
| --- | --- | --- |
| 边界与方向 | 原 B1 为互联网边界入向 | B2 有限出向／NAT 见第 8 节；VPC 复杂路径继续排除 |
| IP 与端口 | IPv4 字面地址／CIDR，TCP／UDP 的单端口与端口区间；保留全地址／全协议含义 | IPv6、ICMP 等标记不支持；协议 ANY 不得被错误缩成 TCP，超出检查可证明范围时降级 |
| 引用 | 完整展开的有限静态 IP／端口地址簿；具体类型与字段见审计设计 | 动态成员、域名、区域、未知类型保留原信息；不得按空集合参与计算 |
| 动作与生效 | accept／drop、明确启用、总是有效的规则 | 观察 log 不得等同拒绝；复杂有效期、未知状态或其他动作先标记超出精确推导范围 |
| 应用及高级条件 | 不附加应用识别限制的简单配置 | 有应用／域名／其他高级条件时不丢字段后硬算；相关模式未知时说明影响 |
| 地址观察位置 | 业务要求与云防火墙观察到的报文地址语义一致 | 有前置代理／地址转换且映射未明确时，不把最终用户地址直接当防火墙可见来源来比较（A-05） |
| 顺序与默认行为 | 在所审流量范围内，相关规则顺序和默认行为明确且采集完整 | 相关更高优先级规则缺失／不支持时，不声称有效放行或有效拒绝已确定 |
| 业务要求 | 明确提供并注明适用范围和完整性的允许集合／必要访问 | 只有用途描述、非完整允许列表或过期例外时，不作全量集合差异断言 |

上述是项目支持边界的需求约束与设计细化输入，不是阿里云产品能力限制。某一条相关策略不支持，不必丢弃所有无关检查；必须说明具体影响了哪一项判断。

### 4.2 领域需求条目

- **DR-01 匹配语义完整**：区分“配置中存在宽泛条目”和“该范围在快照所含配置逻辑中允许”。后者不证明规则已实际下发或流量可达。后者需要相关规则、顺序、状态与默认行为均满足判定前提。
- **DR-02 不伪造确定性**：结论区分原始事实、规则推导、待确认、信息不足与不支持；未检查和通过必须分别统计。状态与严重程度是不同维度。
- **DR-03 业务要求可追溯**：必要访问与允许集合注明来源、适用范围、完整性和版本。管理端口／来源依据明确声明或已批准检查配置，不冒充普遍强制标准。
- **DR-04 引用与缺失显式化**：保留分页、错误和引用展开情况；缺失成员、未知状态、未知业务要求均不转换为空值来证明安全。
- **DR-05 规则结果不可被模型覆盖**：规则原始结果单独保留；Agent 可以补充证据或提出疑点，不可凭自然语言删除规则事实或无证据改判。
- **DR-06 推荐有成立条件**：定位资产和策略，标明单条／配套修改、前置假设、必要访问影响、复审方式与待确认项；修改建议不等于云端已修改。
- **DR-07 复审可比**：比较前核对范围、对象身份、业务要求、实际封存输入的时点、新鲜度／完整性、归一化和判据版本；输入缺失或范围变化只产生不可比说明，不能当成风险消失。
- **DR-08 补查受控**：Agent 只能读当前任务允许的证据；实际请求尝试计数、幂等和重启中断不能由模型控制；依据前次结果补查时记录关联，不要求展示内部思考；无证据或预算耗尽可返回部分结果。

- **DR-09 自动线索与确认分开**：按服务支持多角色，结合 ECS／安全组证据生成候选，再由对话／表单预览确认；权限不足或线索冲突显式处理，未知角色仍可执行独立基线。共享组、允许端口和模型不等于实际运行或授权，不接入云安全中心。
- **DR-10 防护分层与优先级**：区分适用性、已证实缺口和未知。CFW 当前关闭不推导从未防护或全层缺失；组件建议有条件、影响及人工决定，整改顺序不与实现等级混用。
- **DR-11 日志证据有界**：记录类型、窗口、覆盖／采样、标识与时间对应；ACL 和 IPS 不混用，流记录不随意计作连接或攻击；零命中只作复核候选。
- **DR-12 基线与业务判据分开**：经采用的安全基线可独立于业务白名单运行；业务违规需明确业务要求。模型仅使用固定判据，不自行更改基线或将历史流量当授权。

严重程度由具体判据和已知影响给出；端口只是一项输入。整改优先级、实现范围与判定状态分开；模型置信度不能替代证据。缺少白名单不妨碍已采用基线检查，但禁止编造具体整改来源。

## 5. 检查目标及其适用前提

原有六项保留，新增基线／角色及可选防护、日志判据。CHK-01～08 已纳入 B2 核心检查目标；CHK-09～12 为 M1 可选增强、默认关闭。精确规则契约与实现设计已通过整体G2，详细输入、判据、例外、优先级与案例以规则目录为准。本表仅作导航，数据质量与维护候选不计为确定性漏洞。

| 编号 | 问题及所需输入 | 可确认的判断 | 缺少条件时 | 典型证据 |
| --- | --- | --- | --- | --- |
| CHK-01 管理访问来源过宽 | 已声明管理服务、明确管理来源、相关完整策略 | 在支持范围内存在超出管理允许来源的有效放行 | 仅记录宽泛配置事实，待确认管理来源或匹配路径，不编造网段 | 业务要求版本、策略字段、顺序／兜底与流量范围推导 |
| CHK-02 非预期端口放行 | 适用资产、完整的允许协议／端口集合、相关策略 | 有效放行范围包含明确允许集合之外的协议／端口 | 业务允许列表非完整时不认定“其他端口均违规” | 允许集合、相关策略与差异范围 |
| CHK-03 业务来源超范围 | 针对具体服务的完整允许来源及相关策略 | 有效来源集合超出该服务的允许来源 | 未知来源／未解析引用标待确认或信息不足 | 业务要求、引用展开、有效来源差异 |
| CHK-04 精确重复配置候选 | 匹配条件、动作、状态和其他生效条件均完整 | 两条配置在已支持语义下相同，作为冗余候选 | 字段不完整／有未知条件时不宣称完全等价 | 两条原策略及归一化比较；不据此自动删除 |
| CHK-05 保护状态不符 | 明确“应受保护”的业务范围与可信资产状态 | 明确未保护的资产违反已声明保护要求 | 切换中、未知或未采集分别显示，不把未返回等同未保护 | 资产身份、保护预期、状态来源与时间 |
| CHK-06 必要访问被拒绝 | 明确必要访问范围、相关完整策略 | 在支持语义下存在必要流量被该 CFW ACL 拒绝 | 信息不足时不宣称业务一定中断；默认允许也不证明实际可达 | 必要访问、命中策略和推导范围 |
| CHK-07 高风险端口宽泛来源放行（M0） | 风险端口基线、范围与足够配置证据 | 存在由全地址来源条目或默认放行形成的高风险端口配置允许范围，未被已知前置拒绝全部覆盖 | 业务白名单未知仍可判基线，但整改来源待确认；端口不证明服务类型 | 基线版本、允许范围、策略与例外 |
| CHK-08 数据库访问方式不一致（M0） | 已确认服务角色、限定访问要求与相关策略 | 不需公网的数据库服务存在有效公网开放 | 普通标签／安全组端口可推断候选，但不能直接确认角色；同机其他服务独立判断 | 画像、访问要求、策略与范围 |
| CHK-09 IPS 目标差异（M1） | 明确检测／拦截目标与可信实际状态 | 实际状态违反该目标 | 未知先核查，观察不等于未检测 | 目标、模式／开关、适用范围 |
| CHK-10 日志要求缺口（M1） | 已选日志类型／保存要求与配置证据 | 已知不满足适用要求 | 空日志不证明关闭，无要求不编造统一保存天数 | 目标、配置、范围与窗口 |
| CHK-11 零命中复核（M1） | 日志窗口、覆盖和规则版本对应可靠 | 仅说明窗口内未观察到命中 | 不自动删规则、不判无用；不完整则信息不足 | 查询条件、覆盖和版本 |
| CHK-12 必要访问拒绝线索（M1） | 在事件时间适用的明确要求与可信 ACL 拒绝记录 | 生成调查线索而非自动业务故障结论 | 历史流量不等于合法，时间／NAT 不清则降级 | 事件、要求、规则及时间对应 |

CHK-01、CHK-03、CHK-07、CHK-08 可能指向同一业务问题，展示可关联或聚合；实验计分的重复处理须预先规定，不能将同一证据拆成多条增加成绩。高级遮蔽、复杂可达性、主动服务探测和自动日志清理仍不纳入默认交付；有限零命中复核属于明确待选的 M1，不自动扩大为全量日志平台。

## 9. 整轮审计会话的领域闭环（2026-10-29整改目标）

一轮审计会话可以包含多次用户答复和多个关联任务，不等于一次模型请求。本节将进入条件、自动动作、产物和下一步并入领域闭环；正常／异常／恢复分支由[客户旅程J01～J24](customer-journeys.json)唯一编号，使用体验见[PRD UF-13](product.md)。对应既有FR-02／03／04／06／08／12／15～20及AC-03／07／11／14～18／20，不新增FR／AC或另建审批包；正式主链已有[限定代码结果](../validation/evidence/conversation-implementation-local.md)，完整客户分支与真实接入仍待取证。

### 9.1 三类条件和两类意图

- **对话任务意图**决定动作、对象、边界与资料时点；它可从用户当前话语、同会话已确认上下文和有来源目录解析，缺项先澄清，不能默认一台资产或从后台名单截取第一条。
- **业务访问要求**决定哪些访问被业务允许／需要、角色、保护目标和例外；用户选择对象或要求审计不能顺带确认这些要求。
- **云执行条件**指正确连接身份、范围／只读操作及已接受执行效果；不足时停止相关外呼或提出准备步骤，不能靠模型推断身份。
- **审计证据条件**指资料时点、枚举完整性、关联与支持语义；不足时具体降级受影响检查，不等于用户请求非法。
- **业务判据条件**指某项检查需要的画像／允许集合／必要访问及确认版本；缺少它们时只问影响判定的缺项，已经可做的独立基线仍可继续。

一期单账号连接与1～3个会话不限制目录只能有一台或三台资产；一台ECS是案例复用安排。客户／租户词只有在当前连接内存在可信业务归属映射时才能参与筛选，未知则询问，不凭普通标签创造跨账号权限或多租户平台。

### 9.2 从进入到复审的动作条件

| 会话阶段 | 前置条件与系统业务动作 | 后台技术责任 | 用户可见产物／分支 |
| --- | --- | --- | --- |

| 解析对象 | 按名称／ID／地域／资源类型检索，读取前明确有限地域和受支持类型，名称可重复；核对规范身份；“这些机器／刚才那个”须能定位到同会话明确引用 | 查询分页ResourceCatalog，保留目录时点／完整性；重名、不完整目录、未命中和越界分别处理 | 唯一候选展示对象；歧义用最少问题消除；缺目录提出有限发现，不能猜对象 |

| 补业务要求 | 只询问会影响目标检查的角色／服务端口、访问允许／必要集合、完整性与例外；不把云上配置当业务授权 | 有来源的候选与用户答复写入共用草稿，规范化、差异预览、分项确认并生成版本 | 可接受、修订、拒绝或保留未知；只确认角色不确认访问；不强制填完所有表单才查基线 |
| 审计与补查 | 对象、固定证据与所需业务版本有效；按各检查前提运行确定性判据，Agent做受限依赖补查 | 原规则结果独立保存；工具范围／引用／执行策略受控；缺条件和超时保留适用结果 | 分开事实、规则推导、候选、待确认、信息不足、不支持；无模型仍可显示规则结果 |
| 解释与审阅 | 用户可问依据、影响、优先级、未检查项或改用只读解释；采纳待办不是云上整改 | 绑定原发现／报告／输入，历史解释不偷刷新；保存审阅版本，不让模型覆盖规则 | 每个结论定位对象和证据，说明条件与影响、无法证明什么、下一步补什么；不空泛给“安全／不安全” |
| 状态／取消／恢复 | 状态查询按当前明确任务读取；取消必须有明确用户意图及任务绑定；断线不是取消 | 状态读取不额外调云／模型；显式取消停止后续调用，已送达请求不保证撤回；持久历史与幂等防重放 | 真实阶段和已得结果、取消／中断状态；恢复观察或重新发起有区别，不伪造进度 |
| 变更与复审 | 用户声明在系统外人工修改后核查当前状态，或明确沿用原资料解释；不能将两种意图混同 | 同规范对象强制重采／fresh_after后新建输入和审计，按一致判据比较；旧报告不改写 | 改善、仍存在、新增、不可比较及原因；未采到对象、漏页、边界变化不当修复 |

### 9.4 对话分类、合理输出与限制

“不明确”“不知道业务白名单”“对象较多”都是正常用户情境，不能统称不合理请求。判断须看意图、数据来源和拟执行效果，而不是按“忽略”“修改”等单个关键词封禁；例如“忽略刚才的杭州，改查北京”是目标修订，应使旧计划失效并重新核对。

| 分类／例子 | 合理响应与后台限制 |
| --- | --- |
| 清楚且可执行：“审计杭州web-prod的入向配置” | 解析并展示目标和数据策略，在已有范围／接受效果内执行；不能无谓重复询问已确认字段 |
| 需澄清：“查这台／客户甲的机器”，或同名多对象 | 保留同一意图，给有限候选或询问关键字段；可信归属不明就不猜；未消歧不审错对象 |
| 业务信息不足：“不知道合法管理来源，先查风险” | 可运行采用的独立基线；业务一致性检查标待确认；不给虚构白名单，不把缺资料判为非法 |
| 云资料不足／权限缺失／查询未穷尽 | 说明具体缺什么、影响哪些结论；在既有范围内提出补采或离线路径；不能把空返回都解释成无资产／无风险 |
| 范围较大：“审计这个地域的ECS” | 在支持范围内做目录计数／分页与分批计划，说明规模和完整性；超出当前可完成容量时给收窄或分批选择，不截前N台冒充全量，也不默认非法 |
| 能力／保证范围不支持：“证明端到端可达／整个账号合规” | 明确仅能提供已支持的配置层审计和证据，必要时给人工核查建议；不虚构已完成，不因一项不支持丢弃其他独立事实 |
| 当前不允许的云写或越界：“直接删策略／改用别的账号／扩大权限” | 阻止对应执行；可保留只读分析、条件建议或人工操作说明；用户自由文字不能创造云写工具或切换身份 |
| 无关输入 | 简短说明产品职责并给可用审计起点，不创建云任务、不给伪审计结论 |
| 外部描述／工具内容中的指令伪装 | 当作数据，不改变系统指令、执行权限或参数；必要时标记受影响证据并继续可验证部分 |
| 用户误贴密钥等敏感值 | 不要求在对话提供凭据；已知或已识别敏感值在保存可见消息和发送模型之前处理，不得回显或进入消息／模型／日志／报告及业务库，给受控配置入口提示；不把误操作等同恶意用户，也不宣称能自动识别任意未知秘密 |

### 9.5 领域产物与异常／恢复关系

| 领域环节 | 客户旅程 | 产物与不变量 |
| --- | --- | --- |
| 目标与对象 | J01～J05 | 离线输入先校验格式与支持版本，错误可修正重导，不完整保留局部与缺口；保留同会话目标修订、字段来源、候选与选择；账号／地域／类型／ID核对身份，名称／普通标签不授予权限，已确认归属只作业务过滤；可信完整空集与未知、陈旧、权限失败和漏页分开 |
| 证据时点 | J06、J14 | 目录用于定位，审计证据另固定；合格复用零新增云查询，强刷不能用旧资料满足变更后要求；新鲜度、完整性、支持语义和来源保证分别记录 |
| 业务确认 | J07～J09、J18 | 自动事实、候选、草稿及已确认版本分开；角色与访问分项确认，必要访问与完整允许集合分开，明确空集不等于未声明；冲突不覆盖新版本，失败不假称已保存 |
| 策略分区与判定 | J10～J13 | 每任务一个边界／方向／实际策略集，NAT一个网关，目录覆盖不冒充账号全部网关，同VPC／用户选择不证明路径；采完整相关ACL与引用，不只看几条allow；规则原始结果、Agent疑点与条件建议独立 |
| 执行与恢复 | J14～J18、J21 | 接受后自动推进，规则先显示；状态查询不外呼，取消停止新增请求，受理答复未知先查原任务、同次不重复消费；观察恢复只补发，重启中断不重放，迟到成功不覆盖终态 |
| 审阅、报告、复审 | J19～J20 | 审阅与本地待办不改原判定；固定报告不随当前资料改写；人工改后新资料审计，改善／仍存在／新增／不可比较有前后证据 |
| 使用边界与隐私 | J22～J24 | 拒绝越界效果但允许合法目标修订；无关输入不建伪任务；外部文本只作数据；已识别敏感值不入公开消息、模型和持久业务产物 |

云执行的同一接受范围／效果内无需每请求重新确认；用户确认对象或执行不等于确认业务角色与访问授权。若运行后仍缺业务要求，产出待确认并保留适用基线，用户确认新版本后通过新任务生效，首版不要求长期挂起等待。预算、容量与实际时点在执行时仍须有效，3会话共用授权额度，不给每个会话复制额度。

### 9.6 界面、原型与产品验收

客户场景目录规定每一步客户输入、前置状态、自动取得资料、可见回答、正式需保存产物和下一步；分支键可供原型及正式测试引用。PRD与原型应互核：客户补地域后候选变化，修改范围使旧预览失效，不知道白名单仍做独立基线，目录未知／权限不足／不支持／越界分别反馈，历史解释与刷新当前分流；不能只靠固定按钮返回不变文本。

原型可以完全使用人工资料，并可用故障情境复现慢链路、保存失败或观察断线。原型的可见结果只证明相应模拟行为；若历史仅存页面内存，不得称正式持久恢复。当前可运行范围和检查方法见[原型README](../prototypes/audit-workflow/README.md)。正式后台、真实只读权限、模型多轮能力和人工整改复审另按[验证计划](../validation/verification-plan.md)取证；本目录、外观或协议fixture不能代替验收。

J01～J24是客户流程类别，不是正式评价数量，也不等于资产数量。它们不替代DC／RC判据案例、至少一次真实人工整改→重采集→复审或AC-21的20～30独立评价案例。定时采集、M1日志增强和未来CLI／TUI仍按已确认可选边界，不因场景整理自动扩展。
