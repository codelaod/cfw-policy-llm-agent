# 产品需求与使用流程

基线：需求v0.6／B2、设计v0.6，G1／G2已通过。本文为产品PRD与交互要求；实际运行验收另行取证。

## 1. 为什么需要单独的 PRD

系统需求规定范围、功能、判据及验收；本 PRD 规定使用者如何进入、完成和退出业务流程，以及页面展示、确认动作和异常分支。两者共同属于 G1 需求审核输入。需求确认后的系统设计再确定组件、状态存储、接口、任务机制、部署与安全实现。

原型用于核对信息层级、操作路径和确认边界；已批准的正式前端方案见前端设计。原型不等于生产功能或组件运行验收。

## 2. 产品目标与不做事项

目标用户：能够提供账号数据和业务访问要求、需要审阅风险及建议的运维／安全人员。首版建议为受控单操作者使用，不引入组织、租户、复杂审批或消息中心。

完成标准：用户能够选择数据，利用自动取得的上下文和对话引导确认资产，发起审计，理解证据与建议，记录本地处理计划，并在人工修改后重新审计。

明确排除：云安全中心及其 API、客户端和付费采集依赖；主动端口扫描／进程探测；云上写操作；仅靠聊天记录维持业务事实；自动购买或开通安全产品；零命中自动删规则。WAF 等仅为条件性建议，不是新的接入或采购前提。

## 3. 轻量信息架构

建议以五个业务视图／入口组织，可合并为标签或步骤页；无需五套独立前端模块。设置采用服务端连接选择和脱敏状态展示；设计需为本地敏感／付费端点提供最小访问口令等保护，口令不是云／模型密钥，不引入组织账号体系。

| 页面 | 核心信息 | 主要动作 | 异常／空态 | 需求关联 |
| --- | --- | --- | --- | --- |
| P-01 数据与任务 | 离线／真实来源、账号／地域范围、快照版本／完整性、最近任务 | 导入或选择来源、只读采集、查看失败／部分结果 | 无数据时给导入入口；失败不显示“0 个风险”；缺权限说明影响范围 | FR-01／02／08 |
| P-02 资产与引导确认 | 资产列表、事实证据、候选角色、待补问题、确认卡片 | 自动取线索、发起候选推断、手动／对话修订、预览确认、保留未知 | 无标签、组无法关联、模型失败、多人服务／线索冲突均可继续人工标注 | FR-03／04／12 |
| P-03 审计发起与过程 | 选定资产、固定输入与画像／基线版本、缺口、预算／状态、工具事件 | 开始、取消、查看证据或已完成规则结果 | 信息不足可只做适用基线；模型失败显示部分完成，不抹掉规则结果 | FR-05／06／08 |
| P-04 发现与建议 | 状态、严重程度／整改顺序、来源判据、资产服务、证据、建议条件／影响 | 筛选、审阅、采纳为本地待办、暂缓并说明原因、进入资料补充 | 无问题仍显示检查覆盖；未执行项不是通过；采纳不代表云上变更或修复 | FR-07／09／13 |
| P-05 报告与复审 | 固定输入、规则／画像版本、结果、限制、处理计划及前后对比 | 导出、关联新快照发起复审、查看不可比较原因 | 当前资料已更新不改写旧报告；范围／对象缺失不得记成修复 | FR-10／11 |

日志 M1 若纳入，放在来源／证据页的可选区域，不新增强制日志平台主导航。模型与云凭据管理方式在设计阶段确定；本 PRD 不承诺实现密钥管理控制台。

全局增加轻量的会话／历史入口或抽屉，显示当前空间、会话与所用资料时点；不是新增组织模块。P-01 关联历史任务，P-02 的对话可跨刷新继续，P-03 展示阶段／耗时，P-04 可追问指定发现，P-05 可看历史报告。推荐短语覆盖 Web／未来 CLI／TUI，首屏与失败处不能是空输入框。

## 4. 自动线索与确认的业务契约

### 4.1 哪些信息能自动获取

公开文档核对结果如下，不代表已调用账号。字段完整性、权限、分页、地址与组的关联在后续只读验收确认。

| 信息 | 只读来源 | 系统如何使用 | 不能推导 |
| --- | --- | --- | --- |
| 名称、标签、系统类型、地址、已关联组／网卡 | A-11 `DescribeInstances` | 形成资产事实和角色线索；已有受信标签映射可填草稿并展示来源 | 不存在通用业务角色字段保证，也没有可靠实时进程／监听信息 |
| 方向、协议、目的端口、动作、优先级和来源引用 | A-12 `DescribeSecurityGroupAttribute` | 在所关联组中提取入向允许配置，连同拒绝／未知条件和引用给模型，提出候选角色及缺口 | “配置允许”不等于正在监听、实际可达或得到业务批准；安全组也不等于 CFW |
| 网卡／安全组绑定补充 | 必要时 A-27 `DescribeNetworkInterfaces` | 只有已返回关联不足时补查，记录账号／地域／实例／网卡／组关系 | 不枚举整个网络，不把共享组的全部端口当成每台主机的真实服务 |
| 已知用途、保护要求与访问关系 | 本地已确认画像／业务要求 | 提前填入已有版本，只询问缺失／冲突信息 | 新线索或模型建议不能静默覆盖人工确认 |

对共享安全组、多安全组、多网卡、大端口段、ALL 协议、源安全组／前缀引用、关联不完整等情况显示歧义。不能只抽取端口数字，也不能忽略 direction、policy 与关联对象而给“已识别服务”结论。

### 4.2 最小状态与确认边界

角色状态：未知 → 候选 → 编辑中／待确认 → 已确认；出现冲突另标待复核。拒绝候选和保留未知都保留原线索，不强制接受模型建议。

已确认画像至少有资产／服务范围、角色、来源、确认时间与版本；允许访问的完整性、必要端口和来源是独立字段，可以仍然未声明。确认“这是数据库”不等于确认“允许公网访问数据库”。

本地确认不回写云标签／分组／安全组。若既有事实来自用户先前批准的标签映射，可以按已批准范围导入，并保留映射版本；未批准的普通标签只生成候选。

## 5. 端到端使用流程

### UF-01 首次进入与准备数据

1. 展示系统是只读审计工具，以及当前是否为人工／离线数据。
2. 用户选择公开人工样例、导入离线数据或选择已在服务端配置的云连接；不在对话收集 AK、模型密钥。
3. 采集／校验完成后显示对象数、范围、快照版本和完整性。错误、未知与真实空集分别表达。
4. 完整数据进入 P-02；部分数据可进入但带缺口提示；无可用数据停留在来源页，不生成“安全”报告。

### UF-02 自动候选 → 对话引导 → 用户确认

1. 展示自动取得的实例元数据与安全组配置证据，默认不重复询问已确认且未冲突的内容。
2. 用户启动有预算限制的“引导确认／生成候选”任务；同一任务内不逐个模型请求反复弹授权，失败也不后台无限重试。它可复用审计 Agent 能力，不承诺多 Agent。
3. 模型提出候选角色、证据位置和限制。例如“标签 component=db、关联组允许入向 TCP 3306，可能为数据库；尚不能证明正在运行数据库”。
4. 提问优先选择会改变规则或推荐的缺口：实际用途、服务端口、是否需要公网、允许调用方／管理入口。只问未知项，可跳过或明确不知道。
5. 用户通过对话或表单修改，形成结构化确认卡，展示资产、角色／服务、访问要求、来源和与旧版本的差异。
6. 用户以当前基版本确认后保存本地新版本；版本已变化返回冲突供重新预览，不覆盖新值；拒绝、取消或保留未知不形成授权。模型不可用时可直接人工编辑，仍可运行不依赖角色的基线。

### UF-03 不同角色的离线引导例子

独立人工案例：A 的标签／安全组包含 Web 线索，B 有数据库端口线索，C 缺标签且组引用未解析。可复用同一资产模型分别构造快照，不要求同时创建三台真实 VM 或部署三类实际服务。

- A：建议 Web 候选；问是否确实对外提供服务及实际端口，不直接把安全组来源当作批准来源。
- B：建议数据库候选；问实际数据库服务与调用方，不直接将默认端口证明为已运行数据库。
- C：说明信息不足，允许人工补充或保留未知，不默认 Web、不暂停全部审计。
- 同一 ECS 兼有 Web／数据库时，对服务分别确认；共享安全组不能让所有资产自动获得同一业务角色。

### UF-04 发起审计与执行反馈

1. 用户选择范围和数据策略，查看拟复用／刷新资料、基版本及缺口；可选准备完成、进入规则前封存实际输入。
2. 启动前说明：哪些检查能运行、哪些会待确认／不支持；重复提交使用同一幂等意图，服务端不得重复建任务／消费；角色未知不阻止独立基线。
3. 请求先固定、实际输入准备后只封存一次；按 L0 计划／L1 事实／L2 规则／L3 Agent／L4 汇总分层展示，并显示排队、阶段、累计外部耗时和实际可得用量；不显示完整内部思考。
4. 取消／超时／预算耗尽后停止新增请求并保留已得结果；已到达上游的请求不能保证撤回，重启不自动重放；模型失败可标部分完成。
5. 审计中仍缺业务信息时产出待确认项，而不是无限等待或自动编造。首版不要求实现长时间挂起／恢复工作流。

### UF-05 结果补充信息与重新审计

1. 用户从某发现进入同资产的引导区，查看为何缺少该信息。
2. 补充、预览并确认画像／访问要求的新版本。
3. 原任务及报告保持原版本不变，界面提示“资料已更新，可使用最新资料新建审计／复审”。
4. 新任务继承可用范围与前次关联，但不把旧模型结果直接标为修复；存在范围变化时说明可比性。

### UF-06 审阅和本地处理计划

1. 打开发现，查看结论类型、依据、证据、适用范围、建议条件及业务影响。
2. 可记录审阅意见、采纳为本地待办或暂缓并记录理由；与原发现／任务关联持久保存，刷新或服务重启后仍可查看，保存失败明确提示。待办／暂缓不是云端执行，也不改变原始风险判定。
3. 风险例外若需要生效，应进入业务要求的适用范围、理由和到期编辑，再明确确认；随意一条聊天回复或“忽略”按钮不是全局例外。
4. 由用户在云平台完成实际变更，产品不提供“自动修复”按钮。

### UF-07 导出与复审

导出至少一种可读格式与 JSON，包含范围、版本、证据、限制和人工处理状态；真实标识按公开导出约定脱敏。选择人工变更后的新快照／资料版本发起复审；风险消失、仍存在、新增与不可比较分开，缺页／对象缺失不算修复。

### UF-08 失败、取消、重试和缺信息

| 触发情况 | 用户可见反馈 | 可做动作 | 禁止行为 |
| --- | --- | --- | --- |
| 凭据未配置／只读权限不足 | 脱敏类别和受影响范围，不输出密钥或原始错误正文 | 返回连接选择／导入离线样例 | 把权限错误当无资产 |
| 标签缺失／安全组无法关联 | 事实缺口和影响范围，候选不确定 | 手工确认、必要补查或保持未知 | 自动默认 Web／数据库 |
| 模型不可用、能力不足或输出无效 | 候选生成／Agent 补查未完成，说明失败；已有事实与规则结果仍可看 | 手工标注，或用户发起新的有界尝试 | 无限重试、错误结果冒充确认 |
| 线索与已确认画像冲突 | 新旧证据并列，标明需要复核 | 保留旧版、明确改版或保留冲突 | 静默覆盖已确认用途／访问授权 |
| 任务失败／用户取消 | 已得规则结果与状态、未执行检查 | 查看部分报告，修正后新建任务 | 显示全部通过或继续后台请求 |
| 资料在结果后变化 | 当前报告仍显示绑定版本 | 使用新资料发起复审 | 原地改写旧任务输入或结论 |

### UF-09 连续会话与重开历史

当前会话包含多轮消息、确认资料、关联任务／报告，以及与原发现／任务关联的审阅意见、本地处理计划和理由，用户不用重填前轮已确认事实。刷新／服务重启后解锁应用可重开会话并查看上述记录；旧运行中显示中断而不自动重放。解释旧报告沿用原证据与时点，问当前风险才进入新的数据策略。助手公开历史和受控摘要持续使用，不回放完整原始思考或孤立 tool 协议消息。

### UF-10 数据复用、累计时间与渐进结果

日常优先用符合策略的快照；手工改策略后明确强制刷新。界面区分缓存预览和本次最终输入，显示各数据族原时点与完整性。排队、凭据、云请求、模型链共享根限时；模型慢／失败前先显示已取得规则结果。不提供虚假的百分比，刷新失败不默默把旧数据当当前。定时采集若以后启用仅刷新数据，默认关闭，不自动调用模型。

### UF-11 连接配置、身份与过期

选择服务端已配置连接，页面分别显示配置有效、身份验证、可续期性与产品状态；GET 状态不外呼，用户明确检查／采集才执行。云平台与 CFW 可共用一个受限 RAM Provider，模型凭据独立。静态 STS 过期不会自己续期，错误不自动切系统其他身份，仍可查看历史／离线／人工路径。MCP 不是必须配置项。

### UF-12 推荐短语与不同入口

首次无数据有样例和 3～5 个可用短语；已有上下文给续聊、补资料、解释、复审或失败下一步。普通短语填输入框，外部动作打开范围／数据策略预览，不点击就偷偷收费／收集。Web 卡片、CLI 帮助／结果后建议、TUI 键盘选择可不同，均消费同 GuidanceCatalog。未交付 CLI／TUI 不冒称已实现，但将来交付必须具备这些入口。具体目录和副作用契约见[用户引导](../design/guidance-and-entrypoints.md)。

## 6. 页面信息层级与原型参考

当前离线原型提供五个业务视图的交互参考，不新增正式模块；页面信息层级、视觉约束与布局见 [DESIGN.md](../prototypes/audit-workflow/DESIGN.md)。

| 工作区 | 布局与主动作 | 需要审查的重点 |
| --- | --- | --- |
| 审计工作台（P-01） | 左侧业务导航；空态载入人工样例；载入后显示资料、资产确认状态和下一步；主操作打开审计预览 | 不虚构风险分／已完成任务；演示情境设置不占主流程 |
| 资产与业务（P-02） | 资产选择＋事实证据＋候选与表单；预览对话框后确认 | 事实／候选／确认分层；空来源保持未知；修改或切资产使旧预览失效 |
| 审计任务（P-03） | 单边界预览、输入版本、缺口、显式启动；执行阶段与本页任务记录分开 | 出向／NAT 标已确认需求但尚未实现；不隐式外呼；取消保留结果；不覆盖进行中任务 |
| 发现与建议（P-04） | 左侧发现列表、右侧结论／证据／条件／影响；处理计划放在末尾 | 固定原始状态，采纳不变成已修复；固定解释标清不是新模型问答 |
| 报告与复审（P-05） | 可读报告版面、固定版本、局限及复审步骤；完整文本折叠 | 旧任务不随资料改变；“准备复审”只开预览，不冒充重新采集 |

统一轻背景、蓝色主操作、语义状态与排版间距。保留可见键盘焦点、语义表单、状态提示和窄屏布局。普通流程不默认展示原始 JSON、大块调试日志或无意义装饰。

正式前端不得直接复制此 HTML 作为组件工程。页面／组件方向已随整体G2通过，正式实现仍须核验主要空态／错误态及行为；原型美化不代替架构或业务验收。

| 编号 | 产品使用需求 | 系统需求／验收 | 可核对场景 |

## 8. 产品与实现的分工

本文的主流程、五视图、引导确认、未知／失败分支和默认关闭项已获确认；数据、持久化、版本／幂等、权限／预算、取消与错误映射见已批准的专项设计。正式组件与业务测试仍须实际完成，不能按原型外观验收生产能力。

空允许集合只有在用户明确声明禁止所审访问时才表示拒绝全部；未填来源或未确认空列表继续表示未知。原型不具备访问口令、持久连续会话、真实采集、累计外部计时或完整业务表单，具体局限统一在原型README维护。

## 9. CR-1 新边界的产品需求（B2 已确认）

- 创建任务明确选择互联网入向／出向／NAT 边界，并展示所选防火墙、网关、方向和数据族完整性，不把选择边界隐藏在 Agent 自行判断中。
- 出向业务表单需要发起资产、允许外部目标／协议／端口、用途、完整性和例外；不得复用“管理来源”字段充当出向白名单。**当前原型尚未实现该完整表单**，出向固定样例因此保持待确认。
- NAT 资料区区分 ACL、网关／资产关联、SNAT／DNAT 转换上下文和未知状态；只读未接入时显示未验证，不显示“0 条规则＝无风险”。
- 发现、报告和复审携带边界身份，跨边界不能直接比较修复；空态／不支持／缺权限均给下一步，但点击建议不自动调用外部服务。
- 原型只提供三个单边界人工情境；持续会话、真正历史、批量画像、完整新边界表单及实际采集并未实现。具体已确认范围与排除项见 [CR-1／B2](system.md)。
