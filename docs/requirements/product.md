# 产品需求与使用流程

基线：需求v0.6／B2、设计v0.6，G1／G2已通过。2026-10-29将已明确的对话主入口整理为完整客户旅程；本文规定应有体验，不将原型或限定协议测试写成正式功能已交付。客户使用场景唯一目录为[customer-journeys.json](customer-journeys.json)，原型入口与实际可观察范围见[原型说明](../prototypes/audit-workflow/README.md)。

## 1. 用户要完成什么

运维／安全人员可以从空白对话说出“审计杭州 web-prod 的互联网入向”，在系统帮助下找到正确对象、准备有来源的资料、确认必要业务要求、查看有证据的发现和条件建议、记录本地处理计划，并在系统外人工修改后重新采集复审。用户不必先选快照、逐台在后台配置资产，或把云上能读取的事实重新填一遍。

一轮审计会话包含目标澄清、执行及后续追问，可以有多次用户答复和多个关联任务，不等于一次模型请求。用户每一步都应知道：当前审谁、使用何时的资料、已经得到什么、哪些尚不能判断、下一步可以做什么。可运行原型用于核对这些行为，正式实现与真实账号验收分别取证。

首版面向受控单操作者，交付Web；业务审计者与人工变更执行者可以是同一人，不增加组织审批系统。首版使用一个显式账号；“客户甲的机器”只在该账号内存在有来源、已确认的业务归属时作为过滤条件，不建立多租户平台，也不凭普通标签猜归属或切换账号。

资产总数与执行并发分开。20台业务组是正常有限对象集合，目录可以大于单次批次；3个会话指同时执行能力；真实评价串行复用一台ECS是成本安排，均不构成资产总数假设。超出当前可完成批次时提供分批或收窄选择，不截前N条冒充全部，不宣称已验证百万规模。

继续排除云写、自动修复、主动扫描、云安全中心及其API／客户端／指纹采集、自动采购或开通。完整SNAT／DNAT转换审计、跨云／跨VPC复杂路径和端到端可达性证明不在首版。

## 2. 客户主线与系统分工

对话是主入口。五个辅助视图帮助核对对象、业务资料、进度、证据和报告，不能把用户赶回“先配置资产／先选快照”才能发问的路径。欢迎语、例句和失败后的下一步本地可用，点击建议先填入问题或打开预览，不隐式读取云或调用付费模型。

| 阶段 | 用户要做的事 | 系统应自动完成的事 | 需要询问或确认时 |
| --- | --- | --- | --- |
| 表达目标 | 说出审计、解释、状态、取消或复审，以及知道的名称／ID、地域、类型等 | 保留当前会话目标，复用本会话已明确的上下文，检索已有目录 | 对象、边界或指代不清时只问影响执行的缺项 |
| 找到对象 | 选择同名候选，或补充地域、ID、类型 | 展示名称、地域、类型、ID、目录时点和归属来源；分清未知、陈旧、未穷尽与可信空集 | 缺目录时说明有限发现效果；归属未知时不猜 |
| 核对计划 | 看清审计对象、边界、资料时点、是否刷新、模型模式及外部效果，明确发起 | 在已接受范围内完成必要目录准备、资料复用／刷新及审计，不为分页或每次请求重复询问 | 发现仍有多个候选，或对象／范围／模式／效果扩大时重新核对 |
| 准备与检查 | 等待或取消，可先查看已得资料 | 自动推进，展示真实阶段；核对相关策略顺序、状态、引用、默认行为和完整性；先给可用规则结果 | 无法取得关键证据时指出具体影响；不要求用户替系统计算策略 |
| 补业务要求 | 接受、修改、拒绝候选或保留未知；按需要确认访问要求 | 取现成事实、保留有来源候选，与表单共用草稿，展示差异和分项确认 | 角色、允许访问、必要访问和例外分别确认；只问会改变判定的未知项 |
| 理解与审阅 | 问依据、影响、优先级、未检查项；记录待办或暂缓理由 | 分清事实、规则推导、候选、待确认、信息不足和不支持，保存与原发现关联的审阅 | 模型失败仍可看规则；保存失败保留草稿，不说已保存 |
| 人工整改与复审 | 在云平台手动修改后要求重新核查 | 取得变更后的新资料，关联原报告，展示改善、仍存在、新增和不可比较 | 对象缺失、漏页或边界变化不能直接称修复 |

同一已接受效果中的必要读取不逐次确认；外部执行尚未获准时只保留目标、澄清和本地预览。使用模型帮助理解目标或生成候选同样受本次模型选择和既有授权约束；模型未配置或本次未选择／未授权模型使用时，明确ID／辅助表单、人工业务确认和离线规则路径仍可用。模型已配置启用且本次明确选择时，即便上游兼容尚未验证，也可在已授权范围内尝试；尚未验证仅说明保证级别，失败保留规则，不要求普通用户先完成模型验收。

## 3. 自动资料与业务确认

### 3.1 系统应取得的事实

名称、标签、地域、资源类型、系统类型、地址、关联安全组／网卡、CFW保护状态与相关ACL等能在授权范围读取的事实，由系统取得并展示来源、时间、缺失和关联依据。名称与标签帮助检索和提供角色线索，稳定对象仍按账号／地域／类型／ID核对。当前读取不到的字段是未知，不伪装为空值或不存在。准备读取前先明确有限地域和资源类型；名称可能重复，筛选及分页须符合支持来源的能力，较大集合提供收窄或分批，不承诺无限全账号标签搜索。名称／标签先在资产目录解析，再按稳定身份关联防护资料，防护视图未返回不能单独证明资产不存在或未防护。

安全组上下文保留方向、动作、协议、地址／端口、顺序、引用和资产关联，不能只抽取端口数字。共享组、多组、多网卡、ALL协议、大端口段和未解析引用需说明歧义。端口、角色、名称、标签或历史流量均不能证明服务正在监听、实际可达或已获业务授权；安全组也不等于CFW。

事实来源与细节见[业务画像](business-context.md)及[领域需求](audit-domain.md)。这些是应满足的信息要求；当前正式输入与工具链的缺口继续按[实施计划](../development/implementation-plan.md)整改，不把文档核读当实际采集成功。

### 3.2 用户确认的内容

角色可以未知、候选、待确认、已确认或冲突；同一台ECS可按服务承担多个角色。用户可以接受、修改、拒绝或保留未知，候选和已确认旧版冲突时并列复核，不静默覆盖。

确认“这是数据库”只确认角色，不确认“允许公网访问数据库”。允许访问、必要访问、集合是否完整、管理来源及例外均独立显示和确认；用户没填来源保持未知，只有明确声明所审服务不允许任何该类访问并确认时，空允许集合才表示拒绝全部。出向依赖目标不能沿用入向管理来源。

对话和表单编辑同一草稿。确认前显示对象／服务、来源、差异及未确认项；修改对象或内容后旧预览失效；已保存版本发生变化时保留草稿并重新核对。例外须有适用对象与检查、理由、授权来源和到期，普通“忽略”或暂缓不是全局例外。本地确认不回写云标签、分组或策略。

用户不知道业务白名单时，仍运行已采用且前提满足的独立基线；业务一致性比较保持待确认。不能为了给建议编造管理网段或允许来源，也不能抹掉已有确定事实。

## 4. 五个辅助视图

| 视图 | 用户可看、可做的事 | 主要空态或失败路径 |
| --- | --- | --- |
| P-01 数据与任务 | 查看来源、连接状态、目录／资料范围和时点，查看历史目标及任务；导入离线资料或核对准备计划 | 无资料仍可对话；缺权限、目录未知、漏页与完整空集分别表达 |
| P-02 资产与业务 | 核对对象、自动事实、角色候选、访问要求及差异；与对话共用草稿并分项确认 | 可人工编辑、拒绝或保留未知；保存失败不丢草稿 |
| P-03 审计发起与过程 | 核对当前计划，查看排队、资料、规则、Agent补充和汇总；取消或查看部分结果 | 慢采集、慢模型、失败、取消和中断均有真实状态与下一步 |
| P-04 发现与建议 | 按对象、边界、判定状态及整改顺序查看，追问证据、条件和影响，记录本地待办或暂缓 | 未检查不是通过；模型疑点不覆盖规则；本地处理不表示修复 |
| P-05 报告与复审 | 查看固定版本报告与审阅，导出可读格式和JSON，准备人工变更后的复审 | 当前资料变更不改旧报告；不可比较给原因；部分报告保留缺口 |

首屏优先对话、当前上下文和一个明确主动作。普通流程不默认展示源码式事件、原始JSON、大块调试日志或虚构健康分；证据按需展开。页面保留语义表单、清楚状态、可见键盘焦点及窄屏阅读顺序。视觉方向与组件实现分工见[原型设计说明](../prototypes/audit-workflow/DESIGN.md)及[正式前端设计](../design/frontend-and-events.md)。

## 5. 使用流程

### UF-01 首次进入与准备数据

无快照也可建立会话并表达目标。显示云连接、模型和数据来源各自状态，不在对话收集凭据。连接未就绪时可选择公开人工样例或有来源的离线导入；模型缺失时可人工确认与规则检查。离线导入先核对格式、支持版本与大小／范围限制，成功后显示来源声明、范围、对象数、时点和完整性；格式或版本错误明确拒绝，保留原目标供修正重导；可解析但不完整的资料保留缺口、可做局部检查或补充后重新导入。没有证据不生成“0风险”报告。对应J01、J05。

### UF-02 自动候选 → 对话引导 → 用户确认

先展示可读到的事实及缺口，再在用户选择的模型模式内生成候选。只询问影响判定的用途、实际服务、必要访问、允许范围和例外；允许不知道。接受、修改、拒绝及未知均有出口，对话／表单共用草稿、差异预览和确认版本。模型失败可人工编辑，不停止独立基线。对应J07、J08、J18。

### UF-03 不同角色与多服务

人工案例可分别构造Web线索、数据库线索与未知角色，也可在同一资产模型里构造多服务。标签与安全组端口只支撑候选，用户确认服务与访问授权才参与相应业务比较；共享组不能让所有资产自动得到相同角色。真实案例可以串行复用一台ECS，无需部署三台不同角色虚拟机。对应J07～J09。

### UF-04 发起审计与执行反馈

对象消歧后核对一个边界／方向与实际策略集，展示资料策略、可做检查、缺口和外部效果，再明确发起。系统在接受范围内自动准备并推进，先展示资料和规则结果，再给Agent补充与汇总，不要求客户逐阶段点击推进。同一次重复提交只对应原任务；任务耗时保护覆盖排队与外部链路，具体保护值不作为供应商时限承诺。取消、超限或失败保留已得结果。对应J10～J16、J21。

### UF-05 从发现补资料与重新审计

从待确认发现进入同对象业务草稿，说明补充信息为何影响判断。预览并确认新版本后，旧任务／报告保留旧版本，提示使用新资料新建关联审计；不在原报告上改判。首版不要求运行中的任务长期挂起等待业务答复。对应J08、J09、J18、J19。

### UF-06 审阅和本地处理计划

发现详情提供对象、判据、证据、成立条件、必要访问影响与验证步骤。采纳只加入本地待办；暂缓需理由，均与原发现关联保存，保存失败明确提示。风险例外另走业务资料的有限范围与到期确认。云端修改由用户在系统外完成。对应J13、J18、J19。

### UF-07 导出与复审

导出至少一种可读格式及JSON，包含固定范围／时点／版本、发现与证据、条件建议、限制、执行概况及人工处理状态，公开导出遵循脱敏约定。用户声明已人工变更后，取得变更后的新资料再比较，分开改善、仍存在、新增与不可比较；对象缺失或漏页不能算修复。对应J19、J20。

### UF-08 失败、取消、重试和缺信息

| 情况 | 用户可见反馈和可继续路径 |
| --- | --- |
| 连接、身份、权限或静态凭据过期 | 说明哪类资料不可取；保留目标和历史，可用离线路径；不回退机器其他身份 |
| 目录未知／陈旧／漏页 | 说明尚不知道、旧时点或未穷尽，预览有限刷新／发现、分批或收窄；不当空结果 |
| 标签、关联、引用或策略不全 | 保留事实与具体影响，提供必要补查、人工资料或局部结果；不默认角色、不全局通过 |
| 模型慢、失败、能力不足或输出无效 | 已有规则可看；人工审阅或用户明确发起新的有界尝试；不无限重试 |
| 提交后受理答复未收到 | 先恢复原提交状态，同次重试沿用原提交标识；不自动重复发起新执行 |
| 取消、超限或中断 | 停止新增调用，保留部分结果和未执行项；已到达上游请求不保证撤回，迟到结果不改写终态 |
| 保存失败或版本冲突 | 草稿仍在，成功保存才提示完成；核对新旧差异后重新预览，不覆盖较新数据 |

这些情境是正常产品分支，不等于用户请求不合理；具体步骤见J01、J05、J14～J18。

### UF-09 连续会话与重开历史

保存可见消息、确认资料、任务／证据／报告，以及与原发现关联的审阅意见和处理计划。刷新或服务重启后可重开历史和续聊，不重填已经确认且未冲突的约束。观察断线不取消任务，重连只补回进度，不重新运行或恢复额度；服务重启使旧运行显示中断，不自动重放外部调用。历史解释沿用原证据与时点，问“现在”才进入新的资料策略。对应J16、J17、J19。

### UF-10 数据复用、慢执行与渐进结果

合格复用、按需刷新和用户声明变更后的强制刷新均属M0。每类资料保留原时点、覆盖和适用版本，目录新鲜不能代替策略／引用新鲜，资料新鲜也不等于完整。刷新失败不得默用旧资料声称当前状态。排队、等待和各阶段真实显示，不伪造百分比；模型未结束前已得规则可看。定时采集为默认关闭的可选能力，明确开启后只刷新资料，不自动调用模型。对应J06、J14、J15。

### UF-11 连接配置、身份与过期

连接提供一个明确账号及允许读取的地域、边界、操作与执行保护；额外对象限制可收紧权限，不是要求管理员列出全部资产。业务目录负责找对象，本次计划负责选审计对象，三者分开。页面区分已配置、已保存的身份核对结果、产品数据可读及本次已授权；展示状态不触发在线身份检查，执行时按受控计划核对，身份检查不表示所有产品权限通过。凭据只通过受控服务配置提供，不进对话；没有配置或失效时仍可查看历史和离线资料。对应J01、J05、J22、J24。

### UF-12 推荐短语与不同入口

首次、历史、补资料、结果、复审及失败处提供与上下文相关的短语。普通短语填入输入框，涉及外部执行时先打开范围／资料策略预览。Web是首版交付；CLI／TUI仍为后续可选入口，一旦交付须遵守同一业务意图和权限，现有独立实验命令不当作正式系统命令。对应J01、J17、J23及[引导设计](../design/guidance-and-entrypoints.md)。

### UF-13 从空白对话完成一轮审计

以下为人工场景的客户操作示例，正式工程须实现同等行为；系统答复中的对象和结论由所选资料决定，不能恒定返回固定风险文本。

| 客户输入／操作 | 期望答复与自动动作 | 仍有分支时 |
| --- | --- | --- |
| “审计杭州 web-prod 的ECS互联网入向。” | 保留目标，展示当前单账号和匹配对象；无资料可先澄清并预览有限准备 | 两个同名则列候选；没有目录说明未知；不能让客户先填后台资产清单 |
| “杭州的 i-web-hz；资料合格就复用，不够就按这个范围更新，只做规则检查。”并接受计划 | 展示并固定对象、入向策略集、资料策略及只读效果；自动准备所需资料并审计 | 准备后仍有歧义停在澄清；必要效果扩大重新核对；同范围分页不再逐次确认 |
| “业务管理来源我不知道，先查风险。” | 不依赖白名单的采用基线继续，业务范围比较待确认；先给有依据的规则结果 | 无相关完整策略则说明具体信息不足，保留可证实的其他事实 |
| “为什么认为危险，会影响HTTPS吗？” | 定位原证据、规则与条件，说明已知配置允许范围及必要访问影响；不编造白名单 | 所需业务资料缺失只问会改变结论的内容；候选不能充当授权 |
| “记录为待办，导出这份报告。” | 保存与原发现关联的本地待办，导出固定版本和限制；不改变发现判定 | 保存失败保留草稿；模型失败仍能看规则报告 |
| “我已在云平台手动改完，重新采集复审。”并接受新计划 | 取得变更后的资料并新建关联审计，给前后证据和四类比较 | 漏页、对象缺失或边界变化列不可比较，不称修复 |

按名称／ID／地域／类型、可信业务归属和20对象群、消歧与范围修订、资料与业务条件、执行恢复、审阅复审和受限输入的全部必要分支，统一见下一节J01～J24。

## 6. 唯一客户场景目录与原型互核

[customer-journeys.json](customer-journeys.json)是唯一可机器核对的客户场景目录，保存每个场景的前置状态、客户话语、系统答复、自动动作、正常／异常／恢复分支、可见产物、正式需保存的产物和下一步。J编号仅用于产品旅程，不新增FR／AC，不是新的审核包。PRD在此解释使用体验；系统需求和领域需求引用同一目录，后续测试记录实际覆盖，目录自身不宣称通过。

| 场景 | 客户要完成或遇到什么 | 必须可观察的分支 |
| --- | --- | --- |
| J01 | 空白起点、连接或模型未就绪、离线继续 | 可先表达目标；三类状态分开，规则／人工路径，离线导入成功／错误／不完整恢复 |
| J02 | 按名称、ID、地域、资源类型找对象 | 唯一、类型冲突、未预列但在范围内的ID |
| J03 | 已知客户归属与20台业务资产群 | 可信映射、完整集合、分页／分批、群范围修改 |
| J04 | 同名、指代、未知归属、改目标 | 最少澄清、不猜首条、旧预览失效、合法修订可继续 |
| J05 | 目录没有、旧了、为空、读不了或没读全 | 未知／陈旧／可信空／权限／漏页区别及下一步 |
| J06 | 复用资料、刷新当前、解释历史 | 合格复用零新增云查询、变更后强刷、失败不冒充当前 |
| J07 | 自动线索与角色候选 | 接受、修改、拒绝、未知、与旧确认冲突 |
| J08 | 分项确认角色与访问要求 | 明确空集／未知、必要访问、完整性及有限例外 |
| J09 | 不知道白名单也先查风险 | 独立基线继续、业务比较待确认、不编造来源 |
| J10 | 互联网入向 | 完整分区、顺序／状态／引用／默认行为与保护状态 |
| J11 | 有限互联网出向 | 独立依赖集合、必要性、完整性、未知和不支持 |
| J12 | 一个NAT网关的策略集 | 规则身份分区、ACL与转换上下文分开、关联不足 |
| J13 | 理解结论、依据及影响 | 事实／推导／候选／待确认／信息不足／不支持；条件建议 |
| J14 | 采集慢或局部失败 | 自动推进、真实等待、局部结果、超限保留证据 |
| J15 | 模型慢、失败或输出无效 | 先规则、保留规则、依赖补查证据、明确重试 |
| J16 | 看状态、取消、重试、提交答复未知 | 查原任务、同次不重复执行、终态不被迟到结果覆盖 |
| J17 | 断线、刷新、服务重启与历史续聊 | 只恢复观察、去重、重开关系、中断不重放 |
| J18 | 保存失败或版本冲突 | 保草稿、成功才确认保存、差异重核、切对象预览失效 |
| J19 | 审阅、待办、暂缓与报告导出 | 本地状态与判定分开、固定报告、部分结果、脱敏 |
| J20 | 人工整改后重采复审 | 改善、仍存在、新增、不可比较及前后证据 |
| J21 | 三会话并行、第四个排队、同会话已有任务 | 会话隔离、共用授权额度、排队取消、20对象不受3会话误限 |
| J22 | 请求云写、切账号或越界 | 阻止对应效果，合法只读解释和目标修改可继续 |
| J23 | 无关问题或外部内容伪装指令 | 不建伪任务、不改变权限、外部内容只作数据 |
| J24 | 误贴可识别凭据 | 不回显或保存原值、不传模型、提示受控配置并恢复目标 |

原型按这些人工情境接受客户输入，让候选、资料、计划、确认、结果和下一步随话语变化；故障情境选择器用于复现分支，不代替客户主流程。原型应在客户接受计划后自动推进模拟阶段，不将“点击下一步直到完成”当主链。原型可见证据只证明其实际模拟行为；如果历史只在当前页面会话内保存，应明确说明，不能称正式持久恢复。实际可运行范围、未覆盖项及复跑方法统一维护于[原型README](../prototypes/audit-workflow/README.md)。

## 8. 必需、可选与完成证据

M0必需：空白对话主入口、目录定位与消歧、有限只读准备、自动事实与人工确认、合格复用／必要刷新／强制刷新、独立基线和有界Agent、分层结果、连续历史、审阅报告与复审，以及本目录正常／异常／恢复分支。缺真实账号不能阻止先完成可离线验证的产品链。

默认关闭的定时采集为可选能力，开启后也只刷新资料，不自动调模型。M1精确产品状态和日志增强仍可选，日志零命中不能自动删规则；CLI／TUI仍为后续可选交付。不能把缓存、目录或对话主链降为可选来解释实现缺口。

当前正式工程已接无快照对话、目录／消歧、同一audit资料准备、业务确认、规则／受限Agent、固定报告和关联复审，并有[限定本机代码结果](../validation/evidence/conversation-implementation-local.md)；24旅程／88分支的完整正式验收仍未完成，逐项状态见[实现台账](../development/implementation-gap.md)与[实施计划](../development/implementation-plan.md)。原型和正式工程分别记录已实现／已观察／未覆盖，历史E0～E4限定证据不升级为整项产品通过。正式持久化、真实权限、上游模型连续兼容、至少一次真实人工整改复审和评价均须按[验证计划](../validation/verification-plan.md)实际取证，不因本轮PRD或原型完成而宣称通过。

## 9. CR-1 新边界的产品需求（B2已确认）

每个任务明确互联网入向、有限互联网出向或单NAT网关ACL的边界／方向／实际策略集。同一分区的完整规则资料供适用资产共享，20资产不意味着20份重复全量规则读取。多个边界可在同一会话分别形成关联任务和报告，不能混成端到端路径。出向独立维护发起资产、外部目标、协议／端口、必要性、完整性与例外；NAT分开ACL、网关关联、转换上下文和未知状态；当前目标读取来源的目录仅代表已纳入CFW的NAT防火墙或有来源导入，不能宣称已列出账号所有NAT网关。同VPC或用户选中网关不证明实际路径。不同边界／网关不混排优先级，跨边界不直接比较修复。对应J10～J12、J20及[CR-1／B2](system.md)。
