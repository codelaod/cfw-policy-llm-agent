# 系统需求规格说明书

基线：需求v0.6／B2、设计v0.6，G1／G2已通过。本文为现行需求主文档；实际运行验收另行取证。

## 1. 目标、文档边界与审核顺序

论文题目：《基于大模型智能体的云防火墙策略审计与推荐系统设计与实现》。目标是让运维或安全人员理解云防火墙配置与业务访问要求之间的差异，查看可追溯的审计发现，审核有条件的推荐，并在人工修改后复审。

本需求回答“为谁解决什么问题、输入输出是什么、哪些结论允许给出、如何验收”，不在这里决定语言、框架、数据库表或 REST 路由。

### 1.1 业务背景与预期价值

云防火墙审计不仅是对规则语法的检查，还涉及资产承担的服务职责、实际暴露、防护覆盖、必要访问与证据完整性之间的关系。相同的公网允许配置，对公开 Web 服务和仅面向应用服务器的数据库可能具有不同的业务含义；但角色判断、历史访问和产品部署信息均不能替代明确授权。

主流公有云已经提供配置检查、规则使用分析和 AI 辅助安全调查等能力。本课题参考这些产品所体现的管理需求，以有限范围内的资产画像、分层防护核查、确定性规则、Agent 补查及人工复审构成可追溯流程，而不主张替代厂商完整平台或首次实现 AI 策略推荐。行业依据和方法边界见业务价值文档第 1 节。

预期业务价值包括：识别可证实的防护覆盖与访问控制缺口；使建议与资产角色和明确访问关系一致；减少配置、业务资料与证据的人工拼接；控制整改对必要访问的影响；保留可供复核的版本和证据。上述是目标，不是已证明的效率、准确率或经济收益。

## 2. 用户、业务问题与已确认约束

### 2.1 使用者与职责

- 运维／安全审计人员：提供数据与业务访问要求，发起审计，复核证据和推荐。
- 人工变更执行者：在系统外审核并应用策略；可以与审计人员是同一人，首版不据此增加审批系统。
- 项目研究者：维护公开人工案例、固定实验标签与规则版本，核对结果和局限。

这些是业务职责，不表示需要实现三套账号、角色权限或组织管理功能。

### 2.2 已确认的约束

1. 首个云平台为阿里云，演示拟使用云防火墙与 ECS；工作量按本科或一般硕士工程实践控制。
2. 首版只读云配置、开展审计和提供推荐；应用策略由人完成，不提供自动下发或云上写工具。
3. 优先交付前后端分离的 Web；CLI／TUI 不属于已承诺的首版交付。
4. 模型接入优先兼容 OpenAI 接口规范；具体语言、框架、存储和正式协议方案仍由设计阶段确定。
5. 凭据与真实敏感数据不进入前端、Git 或公开报告；技术实验的通过不能替代真实业务效果证据。
6. 用户审核需求后才进入系统设计，用户审核系统设计后才进入正式实现。
7. 不引入云安全中心的服务、API、客户端或指纹采集依赖；轻量标注结合 ECS／安全组自动线索、候选推断和用户确认。
8. 产品使用流程与轻量原型纳入需求审核；具体框架、组件、接口和正式实现留待系统设计。
9. 必须有可持久、可继续的会话／消息／任务／报告历史；选择 SQLite 时必须使用纯 Go 驱动。
10. 外部累计耗时、数据复用／刷新与分层输出、应用／云／模型／工具认证统一考虑；所有交付入口有推荐短语和下一步，Web 与 CLI／TUI 形式可不同。
11. 真实验证优先复用同一台 ECS 和同一套云防火墙，串行切换配置；每个案例保留基线与前后证据，完成后还原／清理再进行下一例。案例数量不等于云实例数量，不要求多种资产类型或多台虚拟机并行部署；必要关联资源按已确认边界另列最小清单与预算。

| 数据入口 | 离线快照＋最终的真实只读采集；二者支持同一审计业务 | 离线成功不代表云端接入成功；联调不作为需求编写前置条件 | Q2 |
| 上下文 | 云防火墙核心数据，ECS 资产上下文；安全组只作上下文，EIP 关联按需 | 不做跨安全组／路由／主机的端到端可达性证明 | Q2 |
| 规则语义 | 先支持有限的 IPv4、传输层与静态引用语义，逐项声明支持边界 | 不完整解释复杂应用、域名、动态地址或所有有效期语义 | Q3 |

| 资产角色 | 自动读取已有 ECS／标签／关联安全组配置，模型提出候选，嵌入式对话或表单引导用户确认；支持批量、多角色和未知 | 不依赖云安全中心，不主动扫描，不把端口当监听／可达性／授权证明，不静默回写云标签 | Q7（流程需求与整体设计均已确认，尚未实现） |
| 防护建议 | 核对适用的 CFW 覆盖与基础控制，按 Web／数据库等角色给条件清单 | 未读到产品状态不判未部署，不要求全部资产购买全部组件 | Q3／Q7 |
| 日志增强 | 可选导入带窗口／覆盖说明的离线或人工摘要；状态与使用线索单列 M1 | 不默认直连 SLS、开日志、引入 SIEM、采集全量日志或自动删零命中规则 | Q8 |
| 交付与运行 | 受控的单操作者演示，Web、可阅读报告和 JSON；优先离线可重复实验 | 不预设公网多用户生产部署、复杂认证和高并发 | Q5 |
| 检查依据 | 官方产品语义＋NIST 等指南原则＋厂商控制主题＋已采用的项目基线目标＋明确业务要求 | 厂商最佳实践不等于强制规范；不直接迁移其他云的规则语义，不声称整体合规认证 | Q6 |

本表已随需求整体审核纳入 B2。标明的可选能力和不承诺范围继续有效；具体技术实现、真实接口与费用仍需设计／集成验收。

## 4. 业务用例

| 用例 | 前提／输入 | 主要流程与输出 | 异常分支 |
| --- | --- | --- | --- |
| UC-01 建立审计输入 | 离线文件或已授权只读数据源、范围与时间 | 导入／采集，展示资源、策略、引用、来源及完整性，得到可复核的输入版本 | 权限不足、分页中断、未知字段分别记录；不把缺失当空数据 |
| UC-02 确认画像与访问要求 | 指定资产、人工声明或 ECS／标签／关联安全组等线索 | 确认角色及服务、必要访问、来源、管理要求和例外，预览并保存版本 | 未确认草稿不参与业务违规判定；多角色和冲突显式保留；未知角色仍可做独立基线 |
| UC-03 审计与审阅 | 固定输入版本与业务要求版本 | 确定性检查；Agent 按疑点补查；校验后展示发现、条件推荐及证据 | 缺少业务信息则待确认；模型失败仍能查看规则结果；不自动修改策略 |
| UC-04 人工变更后复审 | 原审计结果、人工修改后的新输入 | 新建审计，比较同对象／同检查的发现变化，说明新增、仍存在、已消失或不可比较 | 未采到对象、范围变化或数据不完整不能算“风险已解决” |

## 5. 首版功能需求（B2）

| 编号 | 可观察的需求 | 验收关联 |
| --- | --- | --- |
| FR-01 数据与完整性 | 离线／真实输入都能保留来源类型、采集窗口、范围、缺口和版本；人工数据显式标注；错误输入不能伪装完整快照 | AC-01、AC-02 |
| FR-02 只读采集 | 按已确认的账号／资源范围读取所需配置，记录分页与失败；缺权限和未知能力给出反馈；不提供写操作 | AC-02、AC-09 |
| FR-03 资产与策略审阅 | 可查看资产、保护状态、策略顺序／状态及引用，追溯关联依据；不能关联时展示原因而非猜测 | AC-03 |
| FR-04 业务要求维护 | 支持必要访问、允许范围、管理来源、例外及适用时间；区分未声明与明确不允许。对话若用于录入，须预览确认再保存；审计绑定有效版本 | AC-04、AC-11 |
| FR-05 确定性审计 | 执行已采用的基线和业务判据，标注依据类型／版本。白名单缺失可阻止业务比较，但不阻止独立基线；输出适用性、证据、降级与例外 | AC-05；领域 CHK／DR 条目 |
| FR-06 Agent 补查 | 在当前任务只读权限内按疑点选择领域工具；至少一个验收案例由前次查询结果决定后续补查，缺信息时允许停止给确定结论。模型接入支持多轮工具调用、工具结果关联回传和可校验的结构化输出；能力不足或调用失败时有明确反馈 | AC-06 |
| FR-07 推荐与校验 | 保留规则原始发现；模型疑点独立展示；检查对象和证据存在性；建议明确修改对象、前提、配套改动和业务影响，不编造业务来源 | AC-04、AC-06、AC-07 |
| FR-08 执行控制 | 展示运行、部分完成、失败、取消和中断等状态；新建任务幂等，重启不自动重放付费请求；超时／取消后停止新增调用并保留已有证据，不承诺撤回已送达上游的请求 | AC-07 |
| FR-09 结果审阅 | 按对象、角色、依据类型、严重程度／整改顺序和判定状态查看；未知信息列入核实队列；区分事实、推导和候选，冗余／零命中不计为确定性漏洞 | AC-03、AC-05、AC-11～AC-13 |
| FR-10 报告输出 | 至少提供一种可阅读格式及结构化 JSON，包含输入范围／版本、发现、证据、推荐、限制和执行概况，公开导出遵循脱敏约定 | AC-08 |
| FR-11 复审对比 | 将新输入与原审计关联，按一致对象和判据比较发现；保留前后证据与不可比较原因；不因用户标记“已处理”直接判定修复 | AC-10 |
| FR-12 自动线索与画像确认 | 自动展示 ECS 元数据及其关联安全组证据，模型按完整配置上下文提出候选并引导补缺项；对话／表单共用草稿，用户接受／修改／拒绝／未知后保存本地版本，支持多角色和冲突；不依赖云安全中心 | AC-11、AC-14 |
| FR-13 分层防护建议 | 根据保护适用范围、已确认角色和已知状态核查 CFW 等基础控制，给条件化组件建议；区分明确缺口、适用性评估与未知待核查；不直接开通／采购 | AC-12 |
| FR-14 日志证据增强（M1 可选） | 对有窗口／完整性说明的离线或人工摘要提供关联、零命中复核及拒绝线索；不从空日志推导安全、无用或未开启，不自动转授权／删规则 | AC-13；仅在 Q8 选用时验收 |
| FR-15 产品引导与审阅流程 | 提供 PRD 所述来源准备、画像引导、审计、建议审阅和报告复审的连贯入口及失败／取消分支；处理计划只改本地状态，不代表云变更／修复；补资料后新建版本与审计，不改写旧结果 | AC-14 |
| FR-16 连续会话与历史（M0） | 保存空间／会话、公开消息、确认资料、关联执行／证据／报告，以及与原发现／任务关联的审阅意见和本地处理计划（采纳／暂缓及理由）；刷新／重启后续聊并查看记录，引用原输入；任务是会话内部执行，不每轮孤立重建 | AC-15 |
| FR-17 数据策略与新鲜度（M0） | 提供固定快照、合格优先复用和强制刷新，展示各数据族原时点／完整性／回退；按需刷新受总预算。可选定时采集默认关，只采集不自动调模型 | AC-16 |
| FR-18 流程计划与分层反馈（M0） | 明确计划／队列、事实、规则、Agent 补充和汇总层，先显示已得结果；墙钟、阶段和外部请求累计耗时分开，不用单次超时充当总限时 | AC-17 |
| FR-19 专用连接认证（M0） | 统一管理应用访问、云 RAM／STS、模型 key 与工具授权；明确注入来源、期望账号、续期／过期及状态。CFW／ECS 可共用明确 Provider，不用任意 MCP 或全局身份补齐 | AC-18 |
| FR-20 跨入口推荐引导（M0 规范） | 首次、续聊、补资料、结果、复审、失败都有版本化建议；Web 和已交付 CLI／TUI 同意图／权限，形式可不同；目录本地可用，不隐式启动收费／云操作 | AC-20 |

需求阶段的五个轻量视图、使用流程、确认／异常分支及低保真草图见 PRD 的 P-01～05、UF-01～08；它们是 G1 审核输入。G1 后的设计再确定具体组件、接口与运行机制，不把交互需求全部推迟到编码时决定。

## 6. 质量、安全与实验要求（B2 验收条款）

| 编号 | 要求与可核对条件 |
| --- | --- |
| NFR-01 数据与权限 | 凭据仅在服务端或本地私有配置保存，配置检查仅返回脱敏状态；云工具受只读白名单与任务范围约束。真实数据进入外部模型前绑定获准字段投影，默认不发送原始整份云数据；本地 Web 的敏感／付费端点也要有最小访问保护、同源／请求校验，不默认裸露 API |
| NFR-02 结论可靠性 | 同一输入、业务要求、评估时点、归一化与规则版本产生一致的确定性结果；模型不得删除规则结果或将无证据猜测升级为事实；未知不等于安全 |
| NFR-03 有界执行 | 模型／工具／云请求均有有限次数、时间及输出大小保护，失败后保留已得证据；具体默认值和全任务预算在设计时给出，不能直接套用实验的 4 次上限 |
| NFR-04 可追溯与隐私 | 记录规则、提示词／模型配置版本引用、工具事件、证据定位和实际可得的用量，不保存模型完整内部思考；公开记录不含密钥、私有端点和真实敏感标识 |
| NFR-05 可迁移与复验 | 公开人工案例、输入约定、说明和必要依赖可随源码恢复；私有凭据和原始真实数据不随 Git 迁移；断开云账号仍可运行离线验收 |
| NFR-06 可用性与性能边界 | 演示期间可查看任务进度、错误并取消；不承诺企业级并发或未经测量的耗时指标。Q5 先确定目标规模，G2 再明确测试机器、任务规模及通过阈值 |
| NFR-07 评估可信性 | 以 20～30 个独立人工构造评价案例为主体并预先标注；调试案例、重复运行和补充真实数据分别记录。三组共用快照、业务版本和规则结果，两个模型组固定模型与对照条件；规则发现、模型推断和建议质量分别评价，保留原始计数、失败与误报漏报，不提前声称提升；具体口径见实验方案 |
| NFR-08 依据治理 | 固定所用基线、规则、风险端口、角色模板、日志窗口／阈值与例外版本；模型不能自行更改判据；规范条目、厂商建议、项目政策和业务要求分开。多个规则指向同一问题时可关联，实验预先约定去重 |
| NFR-09 时效与持久使用 | 根时限覆盖排队、凭据、采集、规则、模型链及报告，子调用共享剩余时间；历史不是无限预算或自动重放。缓存新鲜度／覆盖独立，静态 STS 不伪装可自动续期，所有新默认值均非已测性能／费用保证 |

不要求本阶段实现复杂观测平台、向量库、分布式队列、企业账号体系或生产高可用；这些不是用来替代上述质量条款的技术清单。

## 10. CR-1：已纳入 B2 的有限出向与 NAT 需求（2026-10-26）

仅做入向可以构成最小闭环，但展示面偏窄。用户已同意补充有限互联网出向和 NAT 边界访问控制，同时继续排除跨云／VPC 的复杂网络矩阵。完整取舍见 [CR-1](system.md)。

- **CR-1-F01 出向审计**：围绕资产访问外部依赖，核对明确允许目标／端口和必要访问；仅在完整、受支持的本层策略语义下给出确定性差异。无依赖声明时输出待确认，不把宽泛出向自动判违规。
- **CR-1-F02 NAT ACL 审计**：按指定 NAT 防火墙／网关独立采集或导入、归一化、判断和报告；规则身份、优先级、默认行为、保护状态及完整性不得与互联网边界混用。
- **CR-1-F03 关联与转换边界**：ACL 与 SNAT／DNAT 转换条目是不同对象。首版建议只展示显式来源的关联及缺口，不做完整地址转换／路径模拟；超出既定最小只读范围的新增查询与权限仍须另行明确授权。
- **CR-1-F04 分边界交互与报告**：任务先预览边界、输入时点、资料缺口和预算；报告明确哪些是入向／出向／NAT，跨边界结果不可直接作整改前后比较。

保持不变：单账号与有限资源的设计默认、云只读、用户确认业务要求、不接云安全中心、不自动变更或增加付费请求。离线语义、真实采集、原型交互分别验收，不能用人工样例替代真实 NAT 接口验收。

CR-1已纳入B2，接口／数据、工具权限与验证矩阵已形成并通过整体G2。设计通过不等于功能已实现，也不自动追加真实调用。
