## 1. 本轮交付与完成边界

| 交付 | 实际内容 |

| 设计取舍 | 按需首次采集＋已提交合格不可变缓存、ECS批量／SG和引用去重、共享完整ACL、本地规则预处理、固定资料Agent；定时默认关，不自建MCP或inflight合并 |
| 工作负载依据 | 官方API参数／分页／RAM、请求公式、20对象人工算例与时间敏感性见[研究](../../research/collection-workload.md)；没有真实RTT／厂商SLA或实际账号性能结论 |

## 2. 实际执行的原型回归

环境：Linux／WSL，本机Node v24.22.0；真实浏览器为缓存Chromium 155.0.8059.12，使用已有本地运行库与中文字体，无全局安装。静态服务只提供原型目录，不挂仓库、私有配置或业务数据库。浏览器交互通过Playwright CLI v0.1.22执行。

```bash
node docs/prototypes/audit-workflow/prototype-smoke.cjs
node docs/prototypes/audit-workflow/prototype-branches.cjs
```

- `prototype-smoke.cjs`：**30组通过**，含24类旅程与6组跨场景不变量，检查集合／方向、敏感值、导入、历史报告、来源隔离和服务删除。其coverage metadata检查不冒充逐分支执行。
- `prototype-branches.cjs`：从目录动态取最终分支集，逐项发送实际引擎输入／动作并断言关键产物，**88／88通过，失败0**；另有**2条不变量通过**，覆盖多服务分别保存／修订及复合目标＋规则模式。新增目录分支若无可执行案例会失败，不以编号存在充当运行通过。
- [journey-coverage.json](../../prototypes/audit-workflow/journey-coverage.json)保存入口和可见输出映射。88条中两条保留技术表达限制：J17服务重启与浏览器刷新恢复，只用人工中断／重开历史呈现预期效果，没有真实磁盘持久化恢复。其他模拟也不证明实际云、规则或模型。

真实浏览器主回归使用[可复跑脚本](../../prototypes/audit-workflow/browser-check.js)，另有独立本机补充检查23项通过：规则模式首句、新ID替换旧地域、单对象授权不扩批量、非法导入受控恢复、规则模式完成、复合输入同时更换对象／方向／模式、从选中旧报告复审保持原对象，以及1440／768／390px各辅助板无横向溢出、零pageerror。

截图及人工报告下载保存在忽略目录`output/playwright/`，独立截图名为`product-parent-group-1440.png`及`product-parent-final-{1440,768,390}.png`；它们不是正式Vue截图。主脚本另检查真实表单操作、Markdown／JSON导出、键盘、观察恢复、三任务与第四排队。主脚本终版**63项通过**，pageErrors与externalRequests均为空；另测直接file打开可用。精确状态／分支／浏览器运行结果保留在[结构化执行记录](product-workflow-checks.json)，不与映射声明混用。

## 3. Review、修复与复验

独立复核同时检查需求是否完整、原型是否实际触发、设计是否能满足以及台账是否如实反映代码。下列问题已修入当前正文／原型并复验，未单独新增逐轮审核文件：

| 发现 | 修复后核对结果 |
| --- | --- |
| batch／删成员／换方向沿用单对象授权 | 按对象集合／方向重绑，旧确认保留；20对象排除一台后指代换方向保持19，不重新展开成20 |
| 模式识别吞掉复合输入目标，或首句规则模式失效 | 对象／地域／类型／方向／模式共同解析；规则与模型模式可往返，模型disabled不被文字启用 |
| 多服务访问覆盖、删服务后旧授权仍用于新任务 | 服务分别保存allowed／required；同服务修订不改他项；删除／重命名后失配要求归档退出当前判据，旧报告保持原版 |
| 角色候选／未知整句覆盖确认，例外混在必要访问 | 接受／修改／拒绝／未知分别处理，旧确认不被拒绝候选删除；已知与未知分项提取，例外独立范围／来源／到期校验 |
| 必要访问影响虚称已确认 | 本页确认HTTPS／443后才显示相应推导；未知时为待确认，人工前提可见 |
| 旧报告复审／审阅操作落到最新任务 | 绑定选中报告／任务，历史A在B之后仍按A对象／方向复审或审阅 |
| 导入null崩溃或来源套到其他对象／会话 | 非法结构受控拒绝保留目标；导入来源和完整性逐资源绑定，不能污染无关任务 |
| 中断误显示完成、工具说明被阶段覆盖 | 中断独立终态／报告文案；阶段与公开补查目的／依赖证据均可见；迟到成功注入不改终态 |
| 目录部分结果没有保留、换对象丢草稿 | 已见子集可选且保缺口；旧范围草稿保存、可显式恢复后再预览 |
| NAT发现先要求ID、规则20秒成为第二硬封、已有规范被称不存在 | 区分名称有限发现和固定ID采集；20秒标当前guard而目标统一profile；API／Swagger状态按真实已注册子集修正 |

最终独立结论：在本轮人工交互原型、需求／设计一致性与台账范围内，已报告的实质问题均修复并复验，无剩余已知实质发现。这不等于证明任意自然语言、所有组合或正式产品均正确。

## 4. 原型冻结窗口时的正式实现缺口

客户从空白自然输入到目录定位、同意图资料准备、自动画像证据、合格缓存及正式Vue主链仍未实现完整；既有模型显式环境兼容、统一WorkloadProfile、预算追加修订与状态分层仍为目标。已有Service／人工allowed／required不重写为缺失；缺的是自动事实／对话草稿衔接。例外独立授权来源字段、未配置但可识别key形态拦截及混合合法目标恢复也在台账中。

真实账号权限／分页／字段、上游MiniMax连续兼容、至少一次真实人工整改复审、标准性能与20～30独立案例三组正式评价仍须后续实际取证。原型没有调用SDK／模型／规则算法，没有真正鉴权／SSE／轮询／SQLite／重启恢复，也不执行云写；未读取真实私有配置或产生新的云／模型请求。

本轮直接在main工作区修改；没有新提交或推送。前序配置审查的脚本参数透传、JSON重复字段歧义修复仍保留，完整配置兼容并未因此实现；本轮重跑启动脚本7项假值回归通过。历史E0～E4数字保持原证据，不加到本轮原型分支数中。
