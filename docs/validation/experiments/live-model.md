# MiniMax 真实模型初测记录

日期：2026-10-22。状态：两个**人工样例**的受限真实调用成功，不是完整模型协议或生产审计验收。精确端点、实际模型标识和凭据继续保留在本地私有配置，不公开到本记录。

## 1. 本轮完成了什么

- 新增非流式 Chat Completions 实验适配器，复用 Eino 的模型组件、Agent 与工具执行机制。
- 保留默认 `run`/`test` 的脚本模式；只有显式 `live` 加 `-allow-paid-requests` 才允许真实请求。
- 实际使用用户提供的 MiniMax 配置，未替换模型、未连接云账号、未发送真实云数据。
- 两个样例的对象、证据、明确给定的管理来源和最终状态通过本地校验。
- 本轮已结束，真实 HTTP 请求合计 **4 次**，没有因调试自动增加预算或重试。

已生成可随源码管理的 [脱敏实测数据](../evidence/live-model-2026-10-22.json)，本文不以文件存在代替 Git 提交/推送状态。公开数据还去掉了模型生成的自然语言原文，仅保留其数量与受校验字段，不能当成可直接回放的原始输出。原始脱敏运行记录在忽略的 `runtime/model-probes/2026-10-22/`；不保存完整服务响应或模型内部思考。

## 3. 实际结果

| 人工场景 | 真实请求 | 工具调用 / 结果核对 | 工具批次 | 最终状态 |
| --- | --- | --- | --- | --- |
| 有管理白名单 | 2 次，HTTP 200 | 2 次 / 2 条 | 1 批 | `conditional_recommendation`，来源保持为给定的 `198.51.100.10/32` |
| 缺少管理白名单 | 2 次，HTTP 200 | 2 次 / 2 条 | 1 批 | `needs_confirmation`，没有生成管理来源 |

每个场景的模型终止原因都是 `tool_calls` 后接 `stop`。模型在第一次响应中把两个工具放入同一批，而不是分两次连续补查；本地事件的执行先后也不能用来证明模型进行了顺序规划。

服务返回的用量：

| 场景 | prompt_tokens | completion_tokens | total_tokens |
| --- | --- | --- | --- |
| 有白名单 | 1684 | 391 | 2075 |
| 缺少白名单 | 1688 | 369 | 2057 |
| 合计 | 3372 | 760 | 4132 |

这些是服务返回的计数，不是本地估算；包括重复发送上下文的累计请求用量，不是唯一上下文长度。没有返回 usage 的响应保持未知，不擅自记成零。本轮没有重复试验，也没有准确率、召回率或显著性结论。

## 4. 已实现的保护与本地负面测试

- 只允许向配置的 Chat Completions 端点发送 POST；不跟随重定向，不向其他地址转发凭据。
- 实际 HTTP 层计数，覆盖可能的 SDK 重试，预算耗尽即拒绝继续；常见 HTTP 失败的本机模拟验证没有自动重试。
- 核对发出的模型标识、输出限额和非流式模式，限制请求/响应正文大小。
- HTTP/协议/认证等错误转换为稳定错误类别，不展示原始错误正文、地址或密钥。
- 使用 Eino 工具上下文中的实际调用 ID，支持同批多个工具结果分别回传和核对。
- 工具仅访问当前任务的人工资产，JSON 参数、任务对象、证据与最终来源受本地校验。
- `length` 截断立即失败，不自动抬高 token 上限；服务若报告超过请求输出上限也拒绝继续。
- 按协议需要在内存中保留完整 assistant 信息，思考内容不写入报告；公开实测文件中的工具 ID 已归一化。

本地模拟服务测试覆盖：多轮连续工具调用、同批多个工具、思考字段的协议回传但不落报告、HTTP 错误、拒绝跳转、预算、超时、过大响应、缺失 usage、非法调用 ID、错误工具、非法最终 JSON 与私有值反射脱敏。

上述负面测试使用**本机模拟 HTTP 服务**，不是对 MiniMax 逐一发起异常请求。普通测试、`-race` 和 `go vet` 通过，不推导生产并发或外部服务全部错误路径都已验收。

## 5. 还不能声称什么

1. **未实测连续多轮补查。** 本轮两个真实场景都是“一批工具 + 结果回传 + 最终回答”；连续工具回合只在本机模拟服务验证。提示中每轮只用一个工具的要求也没有被严格遵循，不能把它当成运行时权限控制。
2. **未验证流式或 Responses。** `responses` 配置仍只可登记；运行时明确拒绝，不静默改用另一协议。这不代表厂商不支持该接口。
3. **未验证原生 JSON Schema 输出。** 本轮只是提示约束与本地校验通过，不宣称原生结构化输出兼容。
4. **未评价审计效果。** 没有完整规则引擎、真实策略集、生产需求、重复运行或正式标注集；自然语言说明并未被证明句句正确。
5. **未接入云平台。** 没有核实阿里云版本、只读权限、分页、资产关联或实际访问路径，也没有云上写操作。
6. 精确服务配置未公开，不能仅凭公开摘要完整复现对同一服务版本的效果；这些材料是工程接入证据，不是跨模型效果排名。

## 6. 运行方式

离线检查：

```bash
bash scripts/eino-offline.sh prepare
bash scripts/eino-offline.sh test
bash scripts/eino-offline.sh test -race
bash scripts/eino-offline.sh vet
bash scripts/eino-offline.sh run
bash scripts/eino-offline.sh config-check
```

`config-check` 仍然不发送请求。真实调用须已获用户授权，单次只选择一个人工场景：

```bash
bash scripts/eino-offline.sh live -provider minimax -allow-paid-requests -scenario whitelist
bash scripts/eino-offline.sh live -provider minimax -allow-paid-requests -scenario missing-whitelist
```

**上限按每次命令独立计算，多次执行会重新获得配置中的单次上限，不是全账户预算。**上面两条命令不是要求现在再运行；本轮的 4 次预算已经使用完毕。需要做一组测试时，应明确分配整组预算，不能只看每次命令。

## 7. 后续验收缺口，不是当前自动执行任务

尚缺真正依赖上一步信息的场景，例如从业务查询结果取得引用后继续查询对象，验证连续补查、失败与停止条件；须避免用固定脚本路径充当模型决策。云端实际账号、版本、权限与字段也未验收，不能因为模型接通就写成云平台接通。

2026-10-22的[B0](../../project/decisions.md)为历史设计输入；当前[系统设计v0.6](../../design/architecture.md)已通过整体G2。上述实测缺口仍按批准方案安排，不自动追加真实模型／云请求；设计选择不能由两个样例的成功代替完整兼容或业务验收。
