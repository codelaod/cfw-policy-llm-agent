# 系统设计 v0.2 增量 Review 与本轮发布核对

日期：2026-10-22。对应需求 v0.5／B1、PRD v0.3、系统设计 v0.2。状态：**供 G2 审核的设计，不是业务实现验收**。

本记录同时覆盖本轮历史／存储／时序／认证意见及后续追加的跨入口推荐引导。用户明确授权在完成检查修订后提交推送；这不授权真实付费调用、云资源写入或 G2 前正式业务编码。早期 B0 交叉审核见 [17](17-requirements-cross-review-and-design-baseline.md)。

## 1. 本轮采用的设计结论

- Gin 负责 Web API 和中间件，底层 net/http 仍处理服务／传输；不是拿它替代 Agent 或云 SDK。
- SQLite 如采用必须纯 Go。建议 GORM＋官方列举的社区 libtnb/sqlite／modernc，须固定版本并在 G2 后验证 CGO_ENABLED=0；默认 CGO 驱动示例不照抄。适配不满足则退回直接 modernc 仓储，不放松硬约束。
- 连续业务会话／可见消息／确认／任务／报告持久化；Eino Runner 执行有界轮次，Checkpoint 不当产品历史数据库，也不把完整 reasoning 持久化。
- 数据采用指定快照、合格优先复用或强制刷新；准备后封存实际输入。可选定时采集默认关闭，只取数据，不自动调用模型。
- 根时间覆盖队列、凭据、采集、规则、模型与报告，分 L0～L4 展示；先有事实和规则，不一直等模型最终回答。
- 应用、云、模型和工具授权分层；CFW／ECS 共用明确云 Provider，禁止隐式机器全局身份回退；MCP 仅后续可信连接器。
- Web 与交付的 CLI／TUI 都有情境短语／下一步，共用目录与语义，选择建议不隐式授权云／模型动作。

## 2. Review—修订—回归安排

1. 语义检查：对照用户意见与实际使用场景，找缺失、过度承诺和成本／隐私范围漂移。
2. 契约检查：核对会话／轮次／执行状态、数据封存、时限和字段／接口，避免旧 v0.1 与新方案冲突。
3. 回归：文档链接／编号／JSON／资料哈希，既有离线原型和已修改实验；测试仅使用本地模拟，不发用户配置的模型／云请求。
4. 发布检查：只纳入相关文件，不纳入私有配置／原始数据；核对仓库级 GitHub 署名与 author／committer、目标远端，不强推／不改已推历史。
5. 修复可确定问题后重跑相关检查；不能用有限文档检查承诺实现、安全、性能或外部服务全兼容。

## 3. 增量发现与修正

| 编号 | 发现／风险 | 修正设计 |
| --- | --- | --- |
| DV-01 | net/http 的职责不清，可能被理解为不用框架或手写 Agent | ADR 明确 Gin／HTTP／用例／SDK／Eino 各层 |
| DV-02 | 使用 GORM 默认 SQLite 示例可能带入 CGO | 纯 Go 硬约束与社区适配门槛；不自动安装或声称已构建 |
| DV-03 | GORM 零值忽略／Save／AutoMigrate 可能破坏确认与历史 | 显式字段、版本 WHERE＋影响行数、不可变版本、受控迁移、SQL 参数隐私 |
| DV-04 | 历史只是一串任务，无法持续业务沟通 | 空间／会话／消息／轮次持久化，执行绑定会话，重开可续聊 |
| DV-05 | 把 Eino Checkpoint 当历史或持久原始思考 | 业务 Store／ContextBuilder 与执行恢复分离；不存完整 checkpoint |
| DV-06 | 删掉原始协议字段后直接拼旧 tool 消息会破坏回放 | 公开历史／证据摘要重建上下文；同轮完整 wire state 仅内存 |
| DV-07 | 每次实时收全量会造成高延迟和重复读取 | 数据策略、配置族时效、按需刷新／可选后台，合格缓存复用 |
| DV-08 | 刷新前就绑定不可变快照，与实际采集矛盾 | request_manifest／data_plan／resolved_input_manifest 三层，规则前只封存一次 |
| DV-09 | 各次调用没超时但累计已失控 | 根／阶段／调用共享剩余 deadline，认证／续期／退避计时 |
| DV-10 | 单工作器同步等队列子采集或 Gin 请求结束取消任务 | 本任务内采集阶段，服务根 job context，HTTP／Gin 对象不跨生命周期 |
| DV-11 | 等模型结束才显示结果、进度伪精确 | L0 计划、L1 事实、L2 规则、L3 Agent、L4 汇总；墙钟／累计区分 |
| DV-12 | CFW／ECS 各收一套密钥或默认读公司全局身份 | 连接级显式 Provider／预期账号校验，无全局／其他 profile 回退 |
| DV-13 | 静态 STS 被误认为总会自动续期 | 可续期来源明确、过期／刷新错误分层；保留历史不重新创建任务消费 |
| DV-14 | MCP 被当认证或密钥管理捷径 | 首版直连 SDK，MCP 可选受控，远程 OAuth／本地环境边界与工具权限分开 |
| DV-15 | 初始输入框空白、不同入口各写一套提示 | GuidanceCatalog 和 Web／CLI／TUI 适配、12 条样例、状态过滤与本地可用 |
| DV-16 | 点建议直接产生收费／云写／越权 | fill_input／navigate_local／open_plan_preview 分开，建议来源入历史且正常鉴权 |
| DV-17 | 当前配置／原型被误读为支持新服务 | 明确旧实验只支持模型字段，原型不持久历史／认证／调度，新增字段与依赖未实现 |
| DV-18 | 文档校验输出把未提交文件称 committed | 发布前修正文档工具标签，提交状态另查；历史输出记录不改实际当时检查事实 |

这些是已写入文档／工具的修正或实现约束，不是安全控制已上线。若后续 G2 改动路线，同步 B1／需求／PRD／设计，不用框架默认值替代业务规则。

## 4. 尚须 G2 后验证的事项

纯 Go GORM 适配与依赖版本、迁移／事务／重启、实际会话与上下文、缓存／过期／多阶段耗时、Provider 续期／取消、正式多入口交互、真实云权限与字段、模型连续依赖链和效果均未验收。没有用真实凭据补这些测试，也未安装云安全中心或外部 MCP。

当前没有发现需要扩大既有业务范围才能继续评审设计的残留阻塞；实现验证门槛明确保留，不宣称“所有东西已经没有风险”。
