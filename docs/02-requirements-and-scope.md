# 需求与首版范围

状态：范围建议稿。只读审计和前后端分离 Web 已确认；具体防护边界与检查项待确认。更新日期：2026-10-20。

## 1. 首版业务闭环

选择离线样例或真实云账号 → 获取资产、保护状态与策略 → 录入或加载业务意图 → 发起审计 → 查看执行过程、发现项和推荐 → 导出报告 → 人工应用建议后复审。

建议先支持单账号、有限地域的阿里云互联网边界入向访问控制。ECS 是主要演示资产。出向控制、VPC 边界和其他云平台作为扩展方向；统一数据结构为扩展留接口，不提前实现多云。

## 2. 必要功能

| 功能 | 首版要求 |
| --- | --- |
| 数据接入 | 离线快照与阿里云只读采集使用同一套审计输入；保留来源、采集时间和采集完整性 |
| 资产关联 | 展示公网资产、用途、所属环境、保护状态与关联策略；无法关联时显示原因 |
| 业务意图 | 记录允许的来源、协议和端口，以及用途、例外理由和适用时间 |
| 规则审计 | 运行可解释的确定性检查，保留原始发现、适用前提和证据 |
| Agent 审计 | 根据任务选择只读工具补查，结合规则结果与业务意图形成建议 |
| 结果审阅 | 区分已确认问题、待人工确认和数据不足；可查看证据与建议修改项 |
| 过程展示 | 展示任务状态、工具调用和错误摘要，支持失败任务定位 |
| 报告与复审 | 导出 Markdown 或 HTML 报告及结构化 JSON；用复审结果比较发现项变化 |

报告格式至少实现一种可阅读格式和 JSON，首版不强制生成 PDF。

## 3. 业务意图是必要输入

仅凭现有策略无法判断哪些访问是业务必需。建议内置一个小型演示场景，并允许人工编辑：

- 资产用途：如 Web 服务、管理入口、测试主机。
- 预期公网服务：如 Web 服务允许公网访问 TCP 80/443。
- 管理访问要求：如仅允许已给定的管理来源访问 TCP 22/3389。
- 业务例外：开放范围的原因、审批说明和到期时间，按场景选填。

演示白名单必须来自明确录入的业务意图，或已标注为人工构造的演示数据，不得由模型臆造。缺少白名单时只能提出“需确认管理来源”的条件建议，不能生成看似合理的真实地址。

## 4. 建议的首批检查项

优先实现 5～8 个有明确输入与判据的检查项，以下是候选清单，最终以采集验证结果为准。

| 检查项 | 主要输入与判据 | 输出边界 |
| --- | --- | --- |
| 管理端口来源过宽 | 入向允许策略覆盖管理端口，来源包含所有地址或超出已声明白名单 | 先指出策略配置问题；有效匹配条件不完整时，不能声称端口实际可达 |
| 允许端口范围过宽 | 策略端口范围超出业务声明的服务范围 | 无业务声明时作为待确认项，不能直接断定错误 |
| 来源范围超出业务预期 | 将来源地址集合与明确给出的允许范围比较 | 未解析的地址组或域名不能当作空集合 |
| 精确重复策略 | 归一化后关键匹配字段、方向、动作及其他生效条件相同 | 给出冗余候选，不自动删除；仍需考虑位置、命中关系与业务约束 |
| 公网资产保护状态异常 | 识别到公网资产，其状态不符合明确的保护预期 | 区分未保护、同步中、未知及接口未返回等情况 |
| 业务意图与策略不一致 | 给定访问需求与已采集策略存在可确认的冲突 | 需处理动作、顺序及匹配范围；无法完整推导时要求人工确认 |

端口、地址、协议、方向、动作、优先级、规则状态、地址组引用、默认行为和采集分页都会影响判断。应先实现所选场景需要的语义；超出已支持语义的规则应标记为不支持或信息不足。

特别注意，阿里云官方说明互联网边界访问控制在未配置策略时默认放行，并建议以高优先级白名单配合低优先级丢弃兜底，详见 [A-05](06-references.md)。因此，只把一条允许策略缩小到白名单，不能直接证明其他来源已经被拒绝；推荐需要核对剩余匹配路径和兜底行为，缺少信息时保持待确认。

规则遮蔽、复杂包含关系、长期零命中策略清理以及跨安全组的端到端可达性分析，暂列扩展。零命中不直接等于无用；配置允许也不直接等于服务实际可访问。

## 5. 发现项与推荐的表达

每个发现项至少包含：检查项编号、对象标识、严重程度、判定状态、证据引用、风险解释、建议修改项、业务影响及待确认条件。建议应标明单条修改还是多条配套修改，以及建议成立所需的匹配和兜底条件。

严重程度与判定状态分开表达。例如，“高严重程度，待确认”意味着潜在影响较大但证据尚不足。数据缺失不得用“未发现风险”覆盖。

模型输出中需要区分事实、规则推导和模型提出的疑点。确定性发现保留原始记录；模型不能悄悄删除或更改规则判定。人工可标记误报、接受风险或要求补充资料，并保留说明。

“合理合规”在首版中落实为有名称、判据、来源和适用范围的安全基线检查。具体采用哪些标准条目留待后续核实；不将几个检查项的通过结果表述为整体合规认证。

## 6. Web 页面与验收

前后端分离，首版页面包括数据源与业务意图、资产与策略、审计任务、发现项详情、报告与复审。优先让主流程可操作，不增加复杂组织管理、租户体系和工作流配置。

首版验收条件：

1. 离线样例可完成审计并导出报告；同一输入可用于规则基线和 Agent 实验。
2. 至少完成一次真实阿里云只读采集，记录字段覆盖、分页完整性和保护状态语义。
3. 能演示 Agent 主动补查与信息不足时停止断言的场景，工具记录与证据可查。
4. 推荐满足已给定的业务约束，能定位到具体资产和策略；不执行云上写操作。
5. Web 能展示完整流程，采集失败、模型失败、协议不兼容和未知状态均有明确反馈。
6. 至少一个可控案例在人工修改后完成复审；模拟结果与真实结果分别标注。
