# 对话式云防火墙审计原型 v0.4

直接用浏览器打开 [index.html](index.html)。这是面向客户的离线交互原型：**人工目录、人工资料与人工固定结果，原生 HTML／CSS／JavaScript，无云、模型、规则计算或服务依赖**。不需要先选择快照；输入目标后，在同一对话内消歧、确认计划、查看自动模拟执行、审阅和准备复审。所有状态仅在页面内存，刷新清空。

产品行为依据 [PRD](../../requirements/product.md)、[领域需求](../../requirements/audit-domain.md)和 [J01～J24 会话目录](../../requirements/customer-journeys.json)。[设计说明](DESIGN.md)说明客户呈现和正式组件映射。原型可检查交互契约，不代表正式 Vue／Nuxt UI 组件或产品能力已交付。

## 打开后怎么操作

1. 输入“检查 web-prod 的入向策略”，用地域或候选按钮消歧；也可直接输入“检查杭州 i-web-hz ECS”。
2. 用“补充业务资料”分别编辑角色、允许访问、必要访问、例外；预览后只确认所列项目。不知道白名单可输入“不知道管理白名单，先查基线”。
3. 确认审计计划后自动推进：准备资料、封存、规则结果、补充解释、汇总。无需点击内部阶段。也可选择“只做规则检查”。
4. 右侧查看固定对象、来源、时点、结论、证据、建议条件和影响。采纳为待办或暂缓不会改变原始发现，也不会修改云端。
5. 查看报告并导出 Markdown／JSON；人工改后“准备复审”只打开强制刷新计划，再次确认后运行新任务。历史可打开本会话旧报告。

更多人工例子：

| 输入 | 可观察变化 |
| --- | --- |
| 检查杭州 web-prod；改查北京 web-prod | 规范对象随地域改变，旧预览失效 |
| 检查北京 i-demo-057 ECS | 可定位目录第 51 个之后的对象；不要求静态配置逐台列出 |
| 审计客户甲的机器／支付业务群的 20 台 ECS | 有来源的人工归属映射形成 20 对象计划；“排除 i-demo-003”改为 19 个并重新预览 |
| 审计客户乙的机器 | 无可信归属映射，要求明确对象，不猜标签 |
| 检查杭州所有 ECS | 显示完整匹配数量，可分批或收窄，不截前 N 个冒充全量 |
| 检查杭州 web-prod 的出向策略 | 使用出向业务要求；不沿用入向来源作为外部目标 |
| 检查杭州 ngw-hz-01 NAT 网关 | 展示该网关策略集；“NAT 关联不足”情境另列资产关联缺口 |
| 解释昨天报告／现在核查这台 | 前者解释所选固定历史；后者预览合格复用／必要刷新。明确已改或重新采集才强制刷新 |
| 查看进度／取消任务／重试 | 状态不创建任务；取消保留已得结果；重试先开新计划 |
| 直接删除云端策略／无关问题／误贴已识别密钥 | 按只读范围、产品职责和敏感内容分别处理 |

左下“演示情境”是次要测试控制：目录未知／陈旧／未穷尽／完整空集、权限／身份、慢采集、慢模型、模型失败、漏页、引用不全、不支持条件、顺序／禁用、防护未知、预算耗尽、答复未知、保存失败、版本冲突、外部描述注入和改后比较等。情境只影响后续人工模拟，不是客户需要配置的 HTTP 参数。观察断开／恢复／轮询使用同一内存任务；未接收结果不能提前显示。

新建四个会话并在慢执行情境下分别确认任务，可看到三个执行、第四个排队；同会话只有一个未结束任务。20 资产是业务范围，3 是会话并发数；人工组共享一个规则分区，不演示对每台重复读取相同 ACL。

## 检查与边界

仓库根目录执行：

```bash
node docs/prototypes/audit-workflow/prototype-smoke.cjs
node docs/prototypes/audit-workflow/prototype-branches.cjs
```

`prototype-branches.cjs` 对会话目录 88 个分支逐项执行具体输入／动作和关键结果断言，并补充服务确认隔离及复合目标／模式不变量；支持范围是有限人工会话分支，不是真实云／模型／规则／持久化验收。

`engine.js` 的 24 类场景与 6 组范围／敏感内容不变量回归对应 J01～J24，检查实际候选变化、分项版本、范围隔离、终态、防重、三槽排队、补发投影、固定报告及敏感值不入记录。[逐分支映射](journey-coverage.json)为会话目录每个分支列出实际入口、可见输出、回归组和有限表达；映射的存在不代替执行。另有 2 个技术保证差异：重开人工历史／中断记录仅模拟可见效果，真实页面刷新及服务重启的磁盘持久恢复仍未实现；这两项不能按真实持久化通过。它们检查有限人工状态机，**不代表会话目录全部分支或真实规则效果验收**。

2026-10-29 本轮实跑：30 组状态／不变量检查，88 个逐分支断言及 2 个额外不变量全部通过；真实 Chromium 的 63 项界面断言通过，页面脚本错误 0、外部 HTTP 请求 0。另已验证直接文件打开。结果范围仍限这份人工原型。

[browser-check.js](browser-check.js) 是 Playwright CLI 的 `run-code` 脚本：先打开原型，再执行整段函数。它通过真实 Chromium 操作对话、业务表单、计划、自动阶段、报告下载、场景和观察恢复，并检查 1440／768／390 像素页面溢出、键盘焦点、脚本错误及外部请求。截图／下载放忽略的 `output/playwright/`。直接文件打开不需要本地服务器；本机浏览器回归也可以只把此目录作为静态根目录。

未实现的能力明确保留：

- 自由自然语言理解。此实现是可检查的有限词汇与按钮／表单状态机；复杂业务话语需要澄清，不声称能理解会话目录的每一句自然话。
- 云 API／模型／规则求值、真实预算和累计外部耗时、鉴权、真正 SSE／轮询、SQLite 持久化、重启恢复、正式 API 和组件行为。
- 任意业务归属、任意资产类型、完整 NAT 转换或端到端路径；演示目录仅有人工 ECS 与一个已纳入样例的网关。
- 例外授权来源真实性的外部核验、任意服务级语义推理、任意秘密识别、完整 WCAG 审核。例外有独立对象／检查／理由／来源／到期表单，缺项或过期拒绝确认；自由文本不自动生效或压制基线。

“保存失败”“版本冲突”“服务中断”均是可见的人工情境；服务中断没有磁盘恢复，重新打开页面会丢失本页演示历史。CSP 禁止连接；不读取本地私配、凭据、真实 API 或浏览器持久存储。
