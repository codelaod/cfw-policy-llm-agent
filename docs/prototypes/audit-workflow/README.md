# 离线低保真流程原型

状态：PRD 的需求评审附件，不是正式 Web 前端。关联 [PRD](../../16-product-requirements-and-user-flows.md) 与 [系统需求／当前 B0](../../02-requirements-and-scope.md)。

用浏览器打开 [index.html](index.html) 即可；不需要安装依赖、起服务、配置账号或模型。所有内容均是人工样例，脚本禁止外部网络连接，仅在当前页面内存中保存；刷新或重置后清空。导出文件也只是固定人工示例报告，不是规则测试结果。

## 可审核的路径

1. 载入三个 VM 的人工快照，进入资产页查看 ECS／安全组线索。
2. 模拟候选，修改角色和访问要求，预览后确认；检查未确认前不入业务事实，空来源不会从安全组复制。
3. 保留未知／拒绝候选；多选同机角色。模型不可用场景下仍能人工编辑。
4. 新建模拟审计，推进固定规则结果；取消后保留已得结果，完成后进入审阅。
5. 采纳为本地待办／暂缓，不改变发现状态、不执行云修改。
6. 补充画像后查看旧任务仍绑定原版本，再使用最新资料新建复审。
7. 在部分上下文和模型失败场景查看降级与局限提示。

## 没有实现什么

真实文件上传、云采集、LLM 对话、规则计算、服务端持久化、真实批量标注、完整任务列表、JSON 导出和所有 PRD 异常均未实现；不以原型完成代替产品验收。助手候选及发现都是固定示例，不是新一轮模型实验。

## 本地检查

```bash
node docs/prototypes/audit-workflow/prototype-smoke.cjs
```

使用 Node 标准库在最小 DOM 替身中执行原型脚本，核对结构和状态转换；不联网，不安装包。该检查不是浏览器布局／可访问性验收，也不是后端、规则或模型测试。正式系统仍须需求 G1、设计 G2 两次用户审核后实现。

本原型形成于需求 v0.3 并作为 B0 交互样例沿用；新设计中的应用访问口令、确认事务、持久幂等和重启恢复未在原型实现，不能以此跳过 G2 或正式控制测试。

本轮补充了首屏本地起点／预览建议及结果固定追问示例，并验证点击不会隐式执行。它仍不是完整 Guidance API／目录、持久会话、Gin／GORM 或真实模型；终端入口只在设计中规范，不冒称产品 CLI／TUI 已交付。
