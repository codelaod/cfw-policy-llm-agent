## 1. 授权与边界

用户要求以开题报告检查需求是否遗漏或缩水，并在审阅六项意见后授权最小补漏，按 review → 修改 → review 完成；无剩余问题后提交、普通推送，附改动记录。此次沿用 B2，不建立新的业务范围或技术基线。

- 需求只写可观察能力、使用流程与验收条件。工具调用 ID、协议字段、校验实现、错误映射等归属系统设计，本轮不写入需求或新增设计方案。
- 保持开题报告正文原样，包括题目、七章大纲、15 篇参考文献及编号；本轮不修改系统设计、正式代码、原型或实验实现。
- 保留 B2 的入向、有限出向与 NAT ACL；M1 默认关闭，完整地址转换与复杂可达矩阵继续排除，云操作仍只读。
- 20～30 指独立人工评价案例数。真实验证优先同一台 ECS／同一套防火墙串行切换配置，完成后还原／清理；不要求多类资产或多台 VM 并行部署。
- 发布授权仅限本轮相关文档；不拉取、不自动合并、不强推、不改已推送历史，不授权 G2 前业务编码或新增真实云／模型请求。

本轮不创建或清理实际云资源，不执行模型／云 API 请求；“还原／清理”是未来真实实验的人工执行约束。NAT 必要资源、权限与预算在批准执行前另行核实，串行复用不减少已确认的边界验收。
