# 项目定位与论文主线

状态：项目背景已纳入 v0.4／B0，系统设计 v0.5 待 G2；无正式业务实现。初稿日期：2026-10-20；业务价值补充：2026-10-22；论文定位澄清：2026-10-24。

## 1. 项目定位

论文题目：**《基于大模型智能体的云防火墙策略审计与推荐系统设计与实现》**。

系统面向需要检查公有云访问控制配置的运维或安全人员，将资产、防护状态、策略配置和业务需求关联起来，找出可解释的风险，并给出可供人工审核的配置建议。

论文研究对象是公有云云防火墙的策略审计与推荐流程。阿里云云防火墙及配套 ECS 用于首版适配、演示和实验验证，选择时考虑实验资源成本与使用周期；这一平台选择不将论文定位为厂商定制项目。统一数据模型与适配边界为后续扩展留出空间，其他云平台仍需单独接入和验证，首版不承诺多云兼容。

首先把云防火墙审计业务做完整，再让 Agent 在获取证据、处理业务上下文和组织建议时发挥作用。仅展示聊天窗口或一次模型问答不足以支撑本项目；只有固定规则扫描，也无法充分体现题目中的大模型智能体。

### 1.1 业务背景与预期价值

云上访问控制的有效性取决于资产职责、对外暴露、规则语义、保护覆盖和业务授权的共同约束。仅检查单条配置，难以判断同一开放范围对于公开 Web 服务或内部数据库是否适当；仅依赖流量或资源标签，也无法证明访问已经得到业务批准。

主流公有云已提供配置检查、规则使用分析、业务资产管理与生成式安全辅助等相关能力。本课题以这些现实需求为背景，拟构建有限范围内的统一审计输入、资产画像、确定性判据、受限证据补查和人工复审流程，强调结论可解释、建议有前提、结果可复核，而非复制完整安全平台或主张首次使用大模型推荐策略。

预期价值在于明确防护和访问控制缺口、增强推荐与业务上下文的一致性、减少人工证据整理、控制整改影响并支持复验。相关准确性、效率和工程收益需后续实验验证。产品比较、AI 方法及资产角色方案见 [业务价值与资产画像](13-business-value-and-asset-profiles.md)；安全指南到判据的映射见 [规则目录](14-security-baselines-and-rule-catalog.md)。

## 2. 两条主线如何结合

| 主线 | 需要回答的问题 | 实现中应能展示的内容 |
| --- | --- | --- |
| 云防火墙业务 | 当前哪些资产受保护？哪些策略存在潜在问题？建议是否符合业务需要？ | 资产与策略关联、规则语义处理、检查结果、建议及复审 |
| AI Agent 工程 | 当前信息够不够？需要补查什么？如何形成有依据的结论？ | 受限工具选择、补查流程、结构化输出、失败处理和执行记录 |

两条主线用同一批案例与系统流程串起来。例如：发现某条策略允许公网访问管理端口后，Agent 查询目标资产的用途和管理访问白名单；若白名单存在，则推荐收敛来源；若白名单缺失，则明确要求补充信息，不编造可用网段；经选用的通用安全基线仍可独立给出高风险公开的发现，不将它伪装为已确认业务违规。

## 3. 需要解决的工程问题

1. **数据关联**：将云厂商接口数据整理成统一对象，关联公网资产、保护范围、访问控制规则与业务需求。
2. **可靠审计**：明确规则检查的输入、适用条件和证据，避免将缺失数据当成安全或风险结论。
3. **有约束的推荐**：结合业务用途和允许访问范围给出可审阅的修改建议，保留不确定性。
4. **可追溯的 Agent**：记录选择了什么工具、查询了什么证据、为何需要人工补充信息，支持复核和重复实验。
5. **多模型接入**：隔离模型协议差异，优先验证 OpenAI 兼容接口中的工具调用能力。

## 4. 论文贡献的建议表述

预期贡献是一个面向云防火墙实际场景的应用系统，包括统一审计数据模型、规则与 Agent 协同的审计流程、具有证据引用的配置推荐，以及离线实验和真实环境验证。

这些是待实现与待验证的工程贡献。开题阶段可以写“设计、实现并验证”，不能提前写“显著提升准确率”“实现完全合规”或“优于所有现有系统”。是否优于基线，由实验结果决定。

阿里云官方产品已提供智能策略推荐，以及基于大模型和业务流量日志的“安全运营 Agent”策略建议能力；本轮核对了用户文档，但没有验证真实账号能力或产品效果，相关资料见 [资料记录](06-references.md) 的 A-05、A-10。本项目需要说明自行实现的审计流程、业务意图输入、模型适配和评估方法，与已有产品能力的关系；不以“首次使用 AI 推荐策略”作为创新点。

## 5. 建议论文结构

1. 绪论：背景、业务问题、研究目标、工作内容与边界。
2. 相关技术与需求分析：云防火墙访问控制、LLM 工具调用、审计需求和使用场景。
3. 系统设计：架构、数据模型、审计规则、Agent 流程、模型与云平台适配。
4. 系统实现：前后端、数据采集、审计任务、证据与推荐、报告生成。
5. 测试与实验：功能测试、对照实验、真实环境演示、错误分析与局限。
6. 总结与展望：完成情况、适用范围与可扩展方向。
